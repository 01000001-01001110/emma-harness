The agent loop

The goal, and how done is decided

The agent loop One turn Failure The memo Endings The kick Budgets Done Seams

goal.rs holds the text a run is held to, the trait that answers "is this met?", the one shipped implementation of it, and the filter that keeps the completion marker off the screen without keeping it from the loop. It is the file that separates Emma from a chat client.

crates/emma/src/goal.rs

What a goal is

// crates/emma/src/goal.rs
pub struct Goal {
    pub text: String,
    /// What a `UserPromptSubmit` hook asked to put in front of the model for
    /// this goal, in hook-name order. Empty for every goal nobody typed.
    ///
    /// **It lives on the goal rather than on the loop**, and that placement is
    /// the answer to "where does this fire?". A hook attached to a *user
    /// prompt* must fire once, when a person submits one — not once per model
    /// call, and not at all for a subagent's brief, which is a work order one
    /// machine wrote for another. Carrying it here means the only way to have
    /// any is to have been given some at the place a human's text becomes a
    /// goal; [`Goal::new`] has none, and `delegate.rs` calls `Goal::new`.
    injected: Vec<String>,
}

Two fields and four methods. Goal::new takes the text and no injection. with_injected attaches hook context and is the only way to get any. injected() reads it back. opening() and opening_turn() are the two message shapes below. The field is private, so a subagent's brief cannot acquire injected context by construction rather than by convention. tested crates/emma/src/goal.rs a_goal_with_no_injection_opens_exactly_as_it_did_before asserts Goal::new produces an empty list and an opening_turn equal to opening.

// crates/emma/src/goal.rs
/// The user message that opens a goal: **the user's words, and nothing
/// else.**
///
/// This used to prepend "Work toward this goal. You have tools; use them
/// rather than describing what you would do" and append the completion
/// contract. Both are true of every goal, which is precisely why neither
/// belongs here — see [`standing_contract`], which now carries them in the
/// system prompt.
///
/// The reason it moved is what a preamble does to a message that is not a
/// work order. Typing `Hello` produced a model that ran `pwd && ls -la`
/// and listed the task file before saying hello, at a cost of 22,083
/// tokens — correct behaviour, given it had been handed a greeting wrapped
/// in an instruction to go and do something. **A preamble applied to every
/// input is an instruction the user did not write and cannot see.**
///
/// What the user typed is now what the model reads.
pub fn opening(&self) -> String {
    self.text.trim().to_string()
}

This is the reversal to keep legible, because the reversed idea is the one that invites itself back: wrapping every goal in a work order is the obvious way to make a model use its tools, and it turned a greeting into a 22,083-token investigation. observed once, by the owner, on the run that produced the figure; the transcript is not in this tree and the number survives in this doc comment and in a test comment quoting it. tested crates/emma/src/goal.rs the_opening_carries_the_contract_of_the_check_actually_in_force asserts the opening contains neither the marker nor the phrase "work toward".

// crates/emma/src/goal.rs
pub fn opening_turn(&self) -> String {
    let opening = self.opening();
    if self.injected.is_empty() {
        return opening;
    }
    let mut s = String::from(
        "[Context added automatically by a UserPromptSubmit hook before this message. \
         The user did not write it.]\n",
    );
    for block in &self.injected {
        s.push_str(block.trim());
        s.push('\n');
    }
    s.push('\n');
    s.push_str(&opening);
    s
}

Injected context is a third thing, neither your words nor the standing contract, and each of the three other places it could have gone is wrong for its own reason. In the system prompt it would be per-turn bytes inside the cached prefix, rewriting the entry every turn and paying 1.25× for the whole prompt instead of reading it at 0.1×. Merged into your sentence it would be an instruction you did not write. As its own message before yours it would be two user turns in a row, which the API rejects. So it rides at the front of the same user turn, attributed, separated by a blank line.

crates/emma/src/goal.rs — Goal::opening_turn

It is one string rather than two content blocks because session.rs rebuilds this turn from the single opening field of the goal record, and --resume replays what was recorded. A second block would be dropped by the fold and a resumed session would replay a conversation the model never had. tested crates/emma/src/goal.rs injected_context_rides_in_front_of_the_users_words_without_becoming_them asserts the exact composed string, character for character, so a format change nobody meant to make shows up in the diff. every_hooks_context_is_carried_and_the_order_is_the_harnesss asserts two hooks appear in the harness's order.

The standing contract

// crates/emma/src/goal.rs
pub fn standing_contract(check: &dyn DoneCheck) -> String {
    format!(
        "\n\nYou work by using the tools you have rather than describing what you would do — \
         read the file, make the edit, run the command. When a request needs no tools, such as \
         a question or a greeting, simply answer it.\n\n{}",
        check.contract()
    )
}

Two sentences of framing and then whatever the check in force says about completion. It takes a &dyn DoneCheck rather than being a constant, because the harness cannot know which check a run selected, and a contract describing a rule the loop is not applying teaches a completion ritual that decides nothing. It is appended to instructions at request assembly, which is also the cheaper place: identical on every goal of every session, so it sits in the stable cache prefix rather than riding in query where nothing can cache it. tested crates/emma/src/goal.rs the same unit test above asserts standing_contract(&Never) carries that check's sentence and not the marker, and that standing_contract(&MarkerClaim) carries the marker.

The trait

// crates/emma/src/goal.rs
/// The answer to "is this goal met?", and why not when it is not.
///
/// The reason is a `String` because it is shown to three audiences — the model
/// in the kick, the user on the terminal, the session log — and one
/// representation means all three are told the same thing.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Done {
    Yes,
    No(String),
}

/// How the loop decides a goal is met.
#[async_trait::async_trait]
pub trait DoneCheck: Send + Sync {
    /// For the log, so a transcript records which authority was in force.
    fn name(&self) -> &'static str;

    /// What the model is told about how completion will be judged.
    fn contract(&self) -> String;

    /// Consulted when the model stops. `text` is its final message.
    async fn verdict(&self, goal: &Goal, text: &str) -> Done;
}

Three methods and the loop knows nothing else: it asks for a verdict and composes a kick from whatever reason comes back. Send + Sync because the check is shared across a run that may delegate. The trait is async because every alternative authority reads a file or runs a process, and retrofitting async to a trait after the fact means changing every caller.

The one shipped implementation

// crates/emma/src/goal.rs
pub const MARKER: &str = "GOAL COMPLETE";

// … elided: the two items sit some hundred and seventy lines apart in the
// file, with `Goal` and the done-detection preamble between them, and each
// carries a doc comment not repeated here.

pub struct MarkerClaim;

#[async_trait::async_trait]
impl DoneCheck for MarkerClaim {
    fn name(&self) -> &'static str {
        "marker_claim"
    }

    fn contract(&self) -> String {
        format!(
            "When — and only when — the goal is fully met, end your final message with the \
             line:\n\n{MARKER}\n\nIf you stop without it you will be told the goal is not done \
             and asked to continue."
        )
    }

    async fn verdict(&self, _goal: &Goal, text: &str) -> Done {
        if claims_done(text) {
            Done::Yes
        } else {
            Done::No("your last message did not end with the completion line".into())
        }
    }
}

MARKER is two plain words on their own line rather than a token like <done/>, so the model writes it into prose it is already writing and a human reading the transcript can see the claim being made. verdict ignores the goal entirely, which is why its parameter is _goal: the claim is about the model's own text. name() is what the goal record stores as done_check. tested crates/emma/src/goal.rs the_marker_check_answers_both_ways.

crates/emma/src/goal.rs — MarkerClaim, MARKER; crates/emma/src/agent.rs — Agent::run_goal 
// crates/emma/src/goal.rs
/// Whether the model claimed completion in the text it just wrote.
///
/// Tolerant about decoration — a model that emits `**GOAL COMPLETE**` meant the
/// same thing, and treating that as a non-claim would spend a kick on
/// formatting. Not tolerant about position: the marker must own its line, so a
/// sentence *about* the marker ("I will print GOAL COMPLETE when the tests
/// pass") is not a claim.
///
/// **And it must be the last thing said.** This used to accept the marker on
/// any line, which meant a turn reading
///
/// ```text
/// GOAL COMPLETE
///
/// Actually wait — the tests still fail.
/// ```
///
/// ended the goal `Done`, with the retraction sitting in the transcript where
/// nobody would read it because the run was over. The module doc above has
/// always said "end its final message with the line", and the refusal this
/// function produces has always said "did not end with the completion line" —
/// the code was the only one of the three disagreeing.
///
/// The cost is a model that signs off after its marker gets a kick instead of
/// finishing. That is the right side to be wrong on: a kick is one cheap turn
/// and says what to do, and a false `Done` is a wrong answer nobody sees.
pub fn claims_done(text: &str) -> bool {
    let Some(last) = text.lines().rev().find(|l| !l.trim().is_empty()) else {
        return false;
    };
    last.trim()
        .trim_matches(is_decoration)
        .eq_ignore_ascii_case(MARKER)
}

/// The characters a model decorates a line with, which a claim survives.
fn is_decoration(c: char) -> bool {
    matches!(c, '*' | '`' | '#' | '_' | ' ')
}

Only the last non-blank line counts, and this is a reversal. The function used to be any over lines, and an earlier version of this page argued for that: a model that adds a trailing blank line or a stray footer after its marker still gets its claim read. The generosity was cheap in that case and expensive in the one nobody had written down: a marker followed by its own retraction, "Actually wait. The tests still fail", ended the goal Done with the correction sitting where nobody would read it.

One detail from the old rule survives in the scan. Trailing blank lines still do not cost the claim, because the scan walks back to the last line with anything on it. A footer after the marker now does cost it, and what you get instead is a kick rather than a wrong answer. eq_ignore_ascii_case means goal complete counts, and five decoration characters are stripped from both ends: asterisk, backtick, hash, underscore, space. tested crates/emma/src/goal.rs a_marker_on_its_own_line_is_a_claim_and_a_mention_is_not covers the plain form, the bolded form, the backticked lowercase form, the sentence that mentions it, the retracted claim, and the trailing blank lines.

Keeping the marker off the screen

The marker is a ritual between the loop and the model, printed into prose a person is reading. Emma's kick needs the signal and you do not need to see it, and those are separable: verdict reads the model's real text, Outcome::text keeps it verbatim, and the filter is applied on the way to the terminal only.

crates/emma/src/goal.rs — MarkerFilter

A replace on the finished text will not do, because text streams: by the time the whole turn is in hand it is already on the screen. Buffering each line will not do either, because that holds every line of prose until its newline, turning a streamed paragraph into something that appears a line at a time. So only a line that could still turn into the marker is held. 

// crates/emma/src/goal.rs
pub struct MarkerFilter {
    /// The start of the current line, held back because it may yet be a marker.
    held: String,
    /// This line has already been ruled out; the rest of it goes straight
    /// through.
    passing: bool,
}

impl MarkerFilter {
    /// Feed a fragment; get back what should appear on the screen now.
    pub fn push(&mut self, chunk: &str) -> String {
        let mut out = String::new();
        for c in chunk.chars() {
            if c == '\n' {
                if self.passing {
                    out.push('\n');
                } else if !claims_done(&self.held) {
                    out.push_str(&self.held);
                    out.push('\n');
                }
                // …and when it *was* the marker, the line and its newline both
                // go, so nothing is left behind where it was.
                self.held.clear();
                self.passing = false;
                continue;
            }
            if self.passing {
                out.push(c);
                continue;
            }
            self.held.push(c);
            if !could_become_marker(&self.held) {
                out.push_str(&self.held);
                self.held.clear();
                self.passing = true;
            }
        }
        out
    }

    /// End of the turn: release whatever is still held, unless it is the
    /// marker. A model that ends without a trailing newline is the ordinary
    /// case, so this is where most markers are actually caught.
    pub fn finish(&mut self) -> String {
        self.passing = false;
        let held = std::mem::take(&mut self.held);
        if claims_done(&held) {
            String::new()
        } else {
            held
        }
    }

    /// Everything, filtered, for a caller that has the whole text already.
    pub fn once(text: &str) -> String {
        let mut f = Self::default();
        let mut out = f.push(text);
        out.push_str(&f.finish());
        out
    }
}

Two states and one decision per character. While passing is false the character joins held and could_become_marker is asked whether the line is still on its way to being a claim; the first "no" flushes everything held and turns passing on for the rest of the line. A newline resets both. In prose that is a one- or two-character pause on a line beginning with g. 

// crates/emma/src/goal.rs
/// Whether a partial line is still on its way to being a claim.
///
/// Deliberately generous at both ends, for the same reason [`claims_done`] is:
/// a model writing `**GOAL COMPLETE**` means the same thing, so the decoration
/// has to be tolerated *while the line is being held* or the held text is
/// released one character before the thing it was waiting for.
fn could_become_marker(line: &str) -> bool {
    let t = line.trim_start_matches(is_decoration);
    match t.get(..MARKER.len()) {
        // Long enough to have said it: it must have, and everything after must
        // be decoration.
        Some(head) => {
            head.eq_ignore_ascii_case(MARKER) && t[MARKER.len()..].chars().all(is_decoration)
        }
        // `get` also says `None` for a length that lands inside a character,
        // which only happens past the marker's own length — so that is a line
        // that is already longer than the marker and is not it.
        None if t.len() <= MARKER.len() => MARKER[..t.len()].eq_ignore_ascii_case(t),
        None => false,
    }
}

Three arms. The third is the length comparison: a line whose bytes run past the marker's length can no longer become it, and a shorter line is compared as a prefix.

The largest known weakness

The acting model grades its own homework

MarkerClaim asks the model that just did the work whether the work is done, and accepts a line of its own prose as the answer. Nothing in the loop verifies the claim. The accurate statement of the guarantee is "the loop will not stop before the model says it is finished", not "the loop stops when the work is finished". goal.rs's module doc states this in its own words rather than leaving it to be discovered.

crates/emma/src/goal.rs — module doc

Three other authorities were considered and each fails in a specific way. Stopping when the model stops costs nothing and catches nothing: a model that runs one command, reads the first error and writes "this looks like a session-API mismatch" has stopped, and the goal is untouched. A check command exiting zero touches reality and passes vacuously, on cargo test against a target with no tests, a test -f against a path that was already there, a suite whose failing case was deleted rather than fixed; it also cannot express goals with no mechanical criterion, which is most of what you type. No open tasks remain is the most legible, because you can watch the file in an editor, and legible is not the same as true: a model that learns closing tasks ends the loop will close them, and a model that never opened one has an empty list from turn zero, which reads as done before it has started.

crates/emma/src/goal.rs — module doc

The intended upgrade makes bookkeeping insufficient rather than swapping one signal for another: use the task count to decide when to stop asking, and gate the verdict behind something the model does not author. That is a second impl and a different value in Setup, not surgery on the loop, which is why DoneCheck is a trait. The stage-1 loops plan designs a third implementation along those lines: a cheap second model call as an independent judge, whose "no" costs one kick and is bounded by max_kicks like any other not-done. It is not built.

What the research says about grading by model

The owner's research note on loops, goals and cost collected the numbers behind "LLM-as-judge is brittle". Read them before anyone builds the judge check, because the failure is not that a judge is a coin flip. It is that the reassuring number is the wrong number.

  • Chance-corrected agreement with human raters, Cohen's κ, ranged 0.376 to 0.511 across 21 judge models, with the best two at 0.511 and 0.489.
  • Raw exact-match agreement overstates the judge by 33.8 to 41.2 percentage points, because much of the apparent agreement is what two graders would hit by chance on a task with few possible verdicts. The widely repeated "greater than 80% agreement, matching human-human agreement of 81%" is the uncorrected figure.
  • Position bias ranged 0.002 to 0.192 between judges, and two production models showed test-retest reliability above 0.95 while showing position bias above 0.10. A loop cannot detect that by asking the judge twice.
  • Position-flip rates rose from a median of 0.09 on easy tasks to 0.17 on hard ones, so the bias is worst where the judgment matters most.
  • Separately, METR's evaluations of o3 and Claude 3.7 Sonnet found reward hacking in 30%+ of evaluation runs: monkey-patching graders, manipulating scorers. That is the failure a verifier invites rather than prevents.

What is not verified here

unverified Whether a real model reliably ends with the marker. Every test here scripts the text. The contract asks for the line and nothing measures how often a live model produces it, which is the difference between "the loop kicks correctly" and "the loop rarely needs to". What would settle it: a set of live goals with the session JSONL read back, counting done endings against kicks_exhausted and stalled ones.
