Themes, and why a broken one costs colour and never the boot

Configuration Discovery Every file The spine Reading .claude/ Skills & commands Agents Your own files Themes It did not apply

A theme is a JSON file of colours, and every rule in the loader exists so that letting a stranger choose the colours cannot cost more than colour. Nothing here returns a Result. A bad hex loses one role, a file that is not JSON loses the theme, and either way Emma boots and says what happened.

Two directories, and the order between them

~/.emma/themes/<name>.json, then <harness root>/themes/<name>.json. Themes ride the discovery that already happened, so in a .claude/ project the project's themes live in .claude/themes/ rather than in a directory of their own.

crates/emma/src/session_command.rs · theme_dirs

/// The two directories, in the order a name is looked for in them.
///
/// **Yours beats the project's**, following the harness's own argument for
/// skipping `~/.claude/`: a project cannot select a theme, so the only way a
/// repository could change your colours is by shadowing a name you had already
/// chosen, and this order is what closes that. The reverse — your file
/// shadowing the project's — is not a risk, it is the preference working.
fn theme_dirs(home: Option<&Path>, root: &Path) -> Vec<(&'static str, PathBuf)> {
    let mut dirs = Vec::new();
    if let Some(home) = home {
        dirs.push(("yours", home.join(".emma").join("themes")));
    }
    // The harness root is already `.emma/` or `.claude/`, whichever this
    // directory has, so themes ride the discovery that has already happened
    // rather than getting a second rule to be wrong about.
    dirs.push(("this project", root.join("themes")));
    dirs
}
crates/emma/src/session_command.rs — theme_dirs, available

Selection lives only in ~/.emma/settings.json under theme, and the project's config.json has no counterpart. That is the same ruling as the model, applied a second time: theme files may live in either place, and the choice is personal.

The loader

crates/emma/src/term/theme.rs · load, the doc

/// The theme in force, and everything that went wrong getting there.
///
/// **This never fails and never blocks the boot.** A missing file, a file that
/// is not JSON, a hex that is not a hex — each costs exactly as much colour as
/// it has to and produces a sentence saying so. The caller's job is to put

crates/emma/src/term/theme.rs — load

Before any colour is parsed, the loader can exit four ways: no selection returns the built-in with no notices; a reserved name returns the built-in with a notice if a file of that name exists; a name found in neither directory returns the built-in and names both paths; and a file whose top level is not a JSON object, or which is not JSON at all, returns the built-in quoting serde's own line and column.

What a file may contain

crates/emma/src/term/theme.rs · the name tables

/// Every role name a file may use, including the one that is refused — a typo
/// of `text` should be told about `text`, not about seven names that do not
/// include it.
const ROLE_NAMES: [&str; 8] = [
    "text", "dim", "ok", "err", "warn", "info", "accent", "ground",
];

/// The settable roles, by the name a file spells them with.
const SETTABLE: [(&str, Role); 7] = [
    ("dim", Role::Dim),
    ("ok", Role::Ok),
    ("err", Role::Err),
    ("warn", Role::Warn),
    ("info", Role::Info),
    ("accent", Role::Accent),
    ("ground", Role::Ground),
];

/// How many problems are worth putting above somebody's first prompt. A wall of
/// warnings is its own defect; past this the count and the path are what the
/// user needs, because the file is where they are going to go and look.
const MAX_NOTICES: usize = 5;
crates/emma/src/term/theme.rs — ROLE_NAMES, SETTABLE, MAX_NOTICES, RESERVED

Eight role names exist and seven may be set. The eighth sits in the list so a person who misspells text is told about text, not a list of seven other names.

Four top-level keys are recognised: name, about, roles and pairs. Anything else is a notice and is ignored, with two names getting a specific sentence instead of the generic one.

crates/emma/src/term/theme.rs · apply, the key loop

    // Unknown keys are noted and ignored rather than refused, for the reason
    // `statusline.rs` gives for the same choice: this is a display preference
    // file, and a build that adds a key should not make the file unreadable to
    // the build beside it.
    for key in doc.keys() {
        match key.as_str() {
            "name" | "about" | "roles" | "pairs" => {}
            "background" | "ground_fill" => notices.push(format!(
                "{key} is not settable: the terminal's background is the terminal theme's, \
                 and Emma cannot ask what it currently is — backgrounds are declared as pairs, \
                 which set both halves"
            )),
            "glyphs" => notices.push(
                "glyphs is not settable: the ASCII set exists because a console at code page 437 \
                 renders box drawing as mojibake, which is detected rather than chosen — \
                 EMMA_ASCII_FRAME is the supported control"
                    .to_string(),
            ),
            other => notices.push(format!("{other} is not a theme key; ignored")),
        }
    }

    // The filename is the identity, so a `name` that disagrees with it is a
    // note and not an error: the file still works, and being told is what stops
    // somebody editing the wrong one for an hour.
crates/emma/src/term/theme.rs — apply

Roles are applied before pairs, because a pair may name a role as one of its halves and has to see the theme's value rather than the built-in's.

Two things a theme may not do

crates/emma/src/term/theme.rs · module doc

//! **Two things a theme may not do, and both are about a screen nobody here can
//! see.** It may not set [`Role::Text`], because a theme author has one
//! terminal and their foreground is what makes Emma unusable for the person
//! with the opposite background — and that person reads it as Emma being
//! broken. And it may not set a background on its own: backgrounds are declared
//! as [`Pair`]s, fg and bg together, because a pair is legible whatever is
//! behind it and a lone background is a colour against an unknown one.
crates/emma/src/term/theme.rs — module doc, apply_roles, pair_halves

Both refusals produce a sentence rather than a silent drop, and roles.text's is the longest string in the file, because the person it protects is not the person reading the message.

The granularity is one role

crates/emma/src/term/theme.rs · role_entry, the doc and the two ends

/// One role's three values, or `None` when the role keeps the built-in's.
///
/// The granularity is the point: a typo in one hex costs that role and leaves
/// the other seven applied, because a theme thrown away over one character is a
/// theme its author cannot debug.
    let Some(rgb) = parse_hex(&hex) else {
        notices.push(format!(
            "roles.{name}: \"{hex}\" is not a colour — write #rrggbb or #rgb; \
             the built-in colour is kept"
        ));
        return None;
    };
    Some(Entry {
        rgb,
        idx: declared_idx.unwrap_or_else(|| derive_index(rgb)),
        // Inherited, never derived. Distance at sixteen colours is exactly how
        // an accent becomes the colour that means failure.
        ansi: declared_ansi.unwrap_or(inherited.ansi),
    })
crates/emma/src/term/theme.rs — role_entry, parse_hex, named_ansi, derive_index

A role may be a bare hex string or an object with hex, ansi256 and ansi16. hex is required inside the object form, because there is nothing to derive the other fidelities from without it. An ansi256 that is not a whole number from 0 to 255 falls back to the derived cube entry, and an ansi16 that is not one of the sixteen names falls back to the built-in role's. Each of those is a notice and none of them costs the role.

The 256-colour index is derived by nearest neighbour over the xterm cube. The 16-colour name comes from the built-in role instead: the same arithmetic at sixteen colours makes Accent a light red, which turns every goal line into error styling. Intent cannot be computed from distance alone.

parse_hex accepts #rrggbb and #rgb and nothing else: a bare word is a colour name in some other file's vocabulary and would be a guess in this one. named_ansi accepts grey beside gray, because half the world writes it that way and a spelling is not an intent.

Pairs: both halves or neither

crates/emma/src/term/theme.rs · pair_halves, the doc and the collision check

/// Both halves of a pair, or `None` when the pair keeps the built-in's.
///
/// Two invariants, and neither is negotiable. **Both halves or neither**: a
/// half-declared pair applied half-way is a foreground against a background
/// nobody chose. And **`fg != bg` after resolution at every fidelity**, checked
/// on the resolved values rather than on the hexes, because the realistic
/// failure is two different hexes collapsing onto the same named colour at
/// sixteen — which a check on the hexes cannot see.
///
/// Not attempted: a contrast ratio. WCAG arithmetic against a terminal whose
/// gamma and palette are unknown is a number that looks authoritative and is
/// not, and this repository has a lesson about that exact shape of claim.
    if halves[0].rgb == halves[1].rgb
        || halves[0].idx == halves[1].idx
        || halves[0].ansi == halves[1].ansi
    {
        notices.push(format!(
            "pairs.{name} resolves to the same colour on both halves at one of the three \
             fidelities, which would draw it invisible; the built-in pair is kept"
        ));
        return None;
    }
crates/emma/src/term/theme.rs — pair_halves, half_entry, apply_pairs

Two pairs exist, chip and selection, and a half may be a hex or the name of a role. A bare hex has no role to inherit a 16-colour name from, so it takes the built-in half's, which is the same rule the roles follow applied to the only other thing that has one. text cannot be a half either: it is not a colour Emma has, it is whatever the terminal is already drawing in.

The collision check is an || across three fidelities rather than an &&, so a pair that is legible in truecolor and invisible at sixteen colours is rejected outright rather than accepted for the terminal its author happened to have.

Selecting one

/theme lists what is available and which is selected; /theme <name> selects one. It takes effect at the next start, and there is no --save, because a theme is read once at startup, so selecting one is writing it down. A live swap would have to reach every drawn surface at once while the retained transcript still holds rows already styled under the old colours, so the realistic outcome of repainting is a half-recoloured screen.

The name is loaded before it is saved, so a selection known to be broken is never written, and the write is a load-mutate-save round trip through the same shared settings document, for the reason the credentials scar on your own files gives. Under NO_COLOR the preference is still written, with a sentence saying the screen will not change: the person may well be setting up for a terminal they will use later.
