The project

Roadmap & defects

What I know is wrong with Emma, what I mean to do about it, and what I looked at and decided against. This page is the whole backlog now. It used to live in a private backlog that left the repository on 2026-08-30.

Known defects

Every entry here can be reproduced or points at the line it lives on. I keep suspicions out of this section, because a defect list I have to second-guess is one I stop reading.

Emma says things that are not true

Three messages tell you to do something you cannot do. Of everything on this page these bother me most, because the whole argument for Emma is that it says what it is actually doing.

  • The browser interaction refusal tells you to create data/browser-allowlist.json or pass --allowlist. Emma reads ~/.emma/browser-allowlist.json and has no such flag. The text is vendored from upstream and sits over an Emma-side input.
  • emma --help's approval ladder omits both EXEMPT and the unattended rung, so the shipped help disagrees with the code that decides.
  • approval.rs's own module doc has the same two omissions, which is how an undocumented unattended mode stayed undocumented.

Bounds that are looser than they read

Two fields of the same struct read like ceilings and behave like tripwires. The token budget is checked after a call comes back, so a real run went past 500,000 and stopped at 579,565. wall_clock is checked at the top of an iteration, which bounds when the loop declines to start another one rather than how long a goal takes. Neither tool.invoke nor the model call carries a deadline.

A review pass corrected the token field's wording and left the wall-clock field alone, which is why both are on the list.

Correctness

  • Fold's compacted arm turns an unreadable record into deletion. Fixed. Both damaged shapes now refuse loudly and leave the conversation alone, rather than rebuilding a different one from defaults. The fix came before anything wrote such a record because this arm is the only defaulting that changes what was sent, and a conversation quietly missing turns is not a failure anybody can see.
  • ToolCtx has no session slot, so constructing tools individually compiles and then silently misbehaves. Three crates document the consequence separately, which is what a missing shared abstraction looks like from below.
  • with_extra's collision check is debug_assert! only, on the seam that produced this project's most expensive bug and in the build shape where that bug happened.
  • Chrome is never reaped on unix. The child is dropped without waiting.
  • transcript.rs clones the whole buffer on every paint, which at the default cap is 50,000 line clones to draw about 40 rows.

Named hazards, unprovoked

Each of these is a failure the code does not remove, and none of them has been made to happen. Some are certified against what the source says while staying unprovoked in effect, which is why they are here rather than under known defects, and why every one of them says what would settle it.

They were moved off the pages describing the mechanisms they belong to. An explanation of how something works is the wrong place to keep an open defect: a reader looking for the defect list does not find it there, and a reader learning the mechanism is handed a caveat they cannot act on.

reanchor can send the cursor answer to the wrong reader

Asking the terminal where the cursor is costs a round trip on unix. By the time a resize happens the reader thread is on stdin too, so the reply can reach the wrong reader. The exposure is not Emma's alone: ratatui's own autoresize asks the same question on the first draw after any resize.

The consequence is bounded. When it fails, anchor moves nothing and the frame stays where it was. unverified: nobody has provoked the race. A resize storm on a unix terminal while a goal streams would settle it.

crates/emma/src/term/frame.rs — reanchor

A write to Emma's own configuration is an ordinary file write

approval.rs classifies by tool name, not by destination. A Write to .claude/hooks/, settings.local.json, agents/ or skills/ is the same category of act as writing a source file, so it is the one edit that can disable the check that would have caught it. A session-wide allowance makes that reachable without a second prompt: the allowance is granted for Write and the next Write is not asked about, wherever it lands.

The allowance behaviour is pinned by a test in approval.rs, so that half is not in doubt. unverified: nobody has run the sequence end to end — allow Write, then write a hook that turns the gate off. Doing that once, and reading what the next run prompts for, would settle whether the exposure is real or whether something downstream catches it.

crates/emma/src/approval.rs — decide, allowances

ToolCtx has no slot for per-session state

Nothing in the context holds state a tool needs across calls, so read tracking and the browser pool have no shared home. Constructing tools individually compiles and then silently misbehaves: the second tool does not see what the first recorded. Three crates document the same problem separately — tools/fs, tools/lsp and tools/web each warn about it in their own words, which is what a missing shared abstraction looks like from below.

unverified: the failure is described in three comments and no test reproduces it. Construct two Write tools with two different ReadTracker handles, exercise read-then-write on the same path, and assert the second tool does not see the first tool's session state. That would settle it.

crates/tool-api — ToolCtx

main.rs holds policy the scripted-provider seam cannot reach

main.rs opens by saying it is wiring and nothing else. run() is 634 lines sitting above the point a scripted provider attaches, so everything deciding what happens before the loop starts is outside what a test with no network can drive. unverified: found by reading, and nobody has measured how much of those lines no test reaches. Extracting the goal loop into the library behind the seam would both settle it and remove it.

crates/emma/src/main.rs — run

Nothing checks that main calls starting_goal

Interrupt::starting_goal is covered. That main calls it is not: the interactive goal loop is still in main.rs, so deleting the call leaves the whole workspace green. unverified: nobody has deleted the call and run the suite. Another test on Interrupt would not settle it, because that is the half already covered; extracting the goal loop into the library behind a seam a scripted provider can drive would.

crates/emma/src/agent.rs — Interrupt::starting_goal; crates/emma/src/main.rs

A refused statusLine is invisible to emma config check

config_check prints the hooks, the agents, the commands, the permissions and the notes attached to each. It never calls status_line_note(), and main reaches the call that does roughly 280 lines after the ConfigCheck arm has already returned. So a statusLine Emma refused is invisible to the one command whose stated job is answering why something did not happen.

certified in its negative half: a scratch .claude/ whose settings.json asks for a command status line produces a full, ordinary config check report with no mention of the status line at all, and so does any command string containing a space. The note does reach an interactive run through Term::warn. unverified whether it is legible there, since nobody has drawn a frame and looked. Start Emma in that scratch directory and read the lines above the first prompt.

crates/harness/src/lib.rs — load_selecting; crates/emma/src/main.rs

Hunk headers are drawn outside the diff budget

In Change::out the ordinary path pushes Out::Hunk for each hunk before consuming rows, and room is decremented only by the body rows taken. A patch with many small scattered hunks can therefore draw up to BUDGET header rows plus BUDGET body rows. The size tests use a single-hunk fixture and a coarse one, and both assert out.lines().count() <= BUDGET + 8, which a forty-hunk patch would exceed.

certified by reading the loop: room gates entry and bounds take, and the header push happens before either. unverified in effect, because no such patch has been rendered. Render one with forty scattered hunks under the budget cap and count the lines.

crates/emma/src/term/diff.rs — Change::out

Change::creation skips three checks the other paths make

creation is the Write-to-a-missing-file path, and it checks MAX_LINES and nothing else. It does not scan for NUL bytes, which live in compute, so a Write creating a new binary file is drawn as a screen of + rows where the same content over an existing file is refused as binary. It applies no byte limit to the model's content, where the existing-file path has MAX_READ. And it reports no line-ending or final-newline note, because those are gathered in compute too.

The consequence is bounded: Change::out runs sanitise over every row, so control bytes never reach a cell and the symptom is a long meaningless diff rather than a corrupted frame. certified by reading — creation is 35 lines and contains one guard, on text.lines.len(). Routing new-file writes through compute, or duplicating its guards, would remove it.

crates/emma/src/term/diff.rs — Change::creation, compute

The fidelity loop in the gutter test cannot fail

an_addition_and_a_removal_differ_in_gutter_as_well_as_in_colour closes with a loop over three Levels and then calls a renderer that takes no Skin and cannot see the level. The variable reaches only the failure message, so the identical assertion runs three times while the comment claims coverage of three fidelities. This is the false-receipt shape the project names elsewhere, inside a test file that argues against it. certified: to_text's signature is fn to_text(&self, budget: usize) -> String. Call a renderer that takes a Skin inside the loop, or delete the loop and say the test covers colour only.

crates/emma/src/term/diff.rs — an_addition_and_a_removal_differ_in_gutter_as_well_as_in_colour, Change::to_text

The colon refusal has not been checked against a non-NTFS Windows filesystem

The alternate-data-stream refusal is #[cfg(windows)] and treats a colon in any normal component as naming an NTFS stream. On unix a colon is an ordinary character in a file name and refusing it would break real paths, which is why the check is Windows-only. unverified: whether any non-NTFS Windows filesystem Emma might run on treats : as ordinary has not been checked, and if one does, this refuses a name that would have worked. Running the same probe on a FAT32 or exFAT volume would settle it.

tools/fs/src/path.rs — resolve

display rewrites a backslash a unix filename is allowed to contain

The separator swap is unconditional. A unix filename may legally contain a backslash, and display rewrites it to a forward slash, so the model is told a spelling resolve will not find. A round trip through Glob and Read would then fail on a file that exists. unverified: recorded by a platform sweep, and no test covers it. Create a file named a\b.txt on Linux and round-trip the name through Glob and Read.

tools/fs/src/path.rs — display

Deleting still_contained leaves the whole workspace green

The recheck exists to narrow the window between resolving a path and writing to it. That it is called is asserted by reading the code and by nothing else: remove the call from write.rs and every test still passes. On the happy path the guard is a no-op by construction, because the tool resolved the path at the top of the call and nothing between there and here moves it, so no ordinary test can distinguish a wired guard from a deleted one. unverified: what would settle it is a test that wins the race on demand, which is the thing that cannot be built. A weaker check that can be: assert the call site exists, and say in the test that it is a wiring check rather than a behaviour one.

tools/fs/src/path.rs — still_contained; tools/fs/src/write.rs

Nothing catches a tool built outside its crate's builder

Each crate's builder is the only supported way to construct its set of tools, and nothing enforces that — not the compiler, not the registry's coherence check, not any test. A member built directly compiles and then silently stops sharing session state. ToolCtx's own doc names it: a Write built with the wrong tracker refuses nothing, and it compiles.

unverified, and it is a claim about the absence of a test, which is the hardest kind to be sure of: it was made by reading the four crates' test files rather than by exhaustive search. Build a member with a private tracker in a scratch branch, run cargo test --workspace, and confirm the suite stays green.

crates/tool-api/src/lib.rs — ToolCtx; tools/fs/src/session.rs; tools/lsp/src/lib.rs; tools/web/src/browser/mod.rs

No test drives a real Chrome through a real redirect

The cross-origin re-ask compares the digest's final_url against the host the gate was asked about and refuses when they differ. The mutation tests cover that comparison, and they cover it through stubs. unverified: nothing has been through a real browser and a real redirect. A loopback stub serving a 302 to a different host, run through WebFetch::run with a browser attached, would settle it.

tools/web/src/fetch.rs — WebFetch::run

Planned, with the reasoning written down

Each of these has a design document that argues it, and none is started.

WorkState
An independent done check A second model judges completion rather than the acting model grading itself. Designed in the stage-1 loops plan, named there as a fallible witness rather than a verifier, because published judge agreement is about 0.38 to 0.51.
A git receipt on every finished goal Commit, diffstat and test-count delta appended to the ending record. Costs milliseconds and is what makes "the test count went down" visible at all.
A floor under the approval gate Some things no rule, flag or remembered grant can permit. Three other projects keep one, and the third is MIT and copyable, corpus and predicates included.
A pre-call headroom check Turns the token tripwire into a bound, using the provider's reported input rather than the character estimate. Sequenced first in the loops plan.
emma stats Emma has never measured itself. The session log already records the fields needed for a rollup; what is missing is a view a person can read.
Scheduled runs A scheduler line calling emma -p, not a daemon. Most of the survival story already exists.

What has to be true first

Two plans, written independently, arrived at the same gate: no longer or unattended run ships before there is measurement to read afterwards. Thirty judged goals before the first stage extends, roughly a hundred receipts before anything runs unattended.

The reason is on the loop page. An ending that reports success looks identical whether the goal was met or the measurement was gamed, and measured reward-hacking rates on agentic benchmarks exceed 30%.

Investigated and refused

These are kept because repeating a refuted idea is the most expensive mistake available here. Each was looked at properly and turned down for a reason that still holds.

IdeaWhy not
Git checkpointing of the working tree git stash create captures no untracked files, verified directly. Another project shipped ghost commits for this and removed them again.
Worktree isolation for subagents A worktree misses uncommitted work, which is the state agents most often operate on.
Turning caching off on the compaction call There is no such call. Compaction is deterministic and never reaches a model.
Feature-building in an autonomous loop The direction the model takes is unpredictable, and the source advocating loops says so itself.
Preventing a loop from editing its own success check Prevention would be a sandbox claim, and Bash defeats any tool-level gate in one line. Detection at verdict time reports the mutation instead.
An always-on sandbox crate The obvious candidate turned out to be GPL-3.0-or-later once its actual licence file was opened.
A strict wire decoder Passed 712 tests, then decoded no real tool call. See Providers.

What is not verified on this page

Every defect above was found by reading source or by counting records, and most have not been reproduced by running the code. The ones with measured rates behind them say so on their own pages. The rest are arguments, and the unverified list says what would settle each.
