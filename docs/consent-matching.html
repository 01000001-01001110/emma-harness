Matching a host, label by label

Consent & permissions The two axes The ladder The egress question The five answers EXEMPT and the floor Permission rules Matching a host Hooks

A rule that accidentally matches everything is the worst defect available in this file, so matching is label-wise and length-checked rather than substring-based. Every host in the "does not match" column below is one somebody can register today.

crates/emma/src/permissions.rs — DomainPattern, label_matches

What a pattern is

DomainPattern holds three fields. raw is the text the operator wrote, kept so the rule renders back exactly. any_subdomain is set when the pattern began *., and is split out at parse time because it is the one form whose label count is not fixed; mixing it into the general path is how "any depth" becomes "any host". labels is the rest, split on dots.

DomainPattern::parse normalises first, refuses an empty pattern, strips a leading *., and then refuses an empty remainder or any empty label. That is what makes domain:.. and domain:a..b parse errors. DomainPattern::literal is the other constructor, used by Rule::domain when the gate builds a rule from a NetworkTarget::host that is already lowercased and stripped, so it round-trips through parse unchanged.

The matcher

pub fn matches(&self, host: &str) -> bool {
    let host = normalise(host);
    let labels: Vec<&str> = host.split('.').collect();
    if labels.iter().any(|l| l.is_empty()) {
        return false;
    }
    if self.any_subdomain {
        // Strict: `*.example.com` covers `api.example.com` and
        // `a.b.example.com` and **not** `example.com`. There has to be at
        // least one label in front of the suffix, or the pattern quietly
        // becomes a longer spelling of the bare host.
        if labels.len() <= self.labels.len() {
            return false;
        }
        let tail = &labels[labels.len() - self.labels.len()..];
        return self.label_wise(tail);
    }
    // The length check. Without it, `example.com` would have to be matched
    // by suffix or by substring, and both of those match
    // `example.com.attacker.net`.
    labels.len() == self.labels.len() && self.label_wise(&labels)
}

fn label_wise(&self, host: &[&str]) -> bool {
    self.labels
        .iter()
        .zip(host)
        .all(|(pattern, label)| label_matches(pattern, label))
}

Two guards carry the whole property. The equality on label counts is what stops example.com from matching example.com.attacker.net. The strict inequality on the *. path is what stops *.example.com from covering example.com itself. Relaxing the first from == to >= turned three tests red at commit 20ac400: a_domain_rule_does_not_match_a_lookalike_host, a_star_inside_a_label_cannot_cross_a_dot and what_is_written_is_what_is_read_back_next_boot. tested

One label at a time

fn label_matches(pattern: &str, label: &str) -> bool {
    if !pattern.contains('*') {
        return pattern == label;
    }
    // A tiny glob rather than a regex: the parts between the stars must appear
    // in order, the first anchored at the start and the last at the end.
    let parts: Vec<&str> = pattern.split('*').collect();
    let mut rest = label;
    for (i, part) in parts.iter().enumerate() {
        if part.is_empty() {
            continue;
        }
        if i == 0 {
            let Some(stripped) = rest.strip_prefix(part) else {
                return false;
            };
            rest = stripped;
            continue;
        }
        if i == parts.len() - 1 {
            return rest.len() >= part.len() && rest.ends_with(part);
        }
        let Some(at) = rest.find(part) else {
            return false;
        };
        rest = &rest[at + part.len()..];
    }
    true
}
crates/emma/src/permissions.rs — label_matches, quoted entire

The host is split on dots before any pattern label reaches this function, so no * can cross one. That is the mechanism behind example.* matching example.org and not example.evil.com. A pattern that is a bare * falls through the loop with every part empty and returns true, which is how one label of a pattern can be a wildcard on its own.

crates/emma/src/permissions.rs — normalise, quoted entire

The same three steps NetworkTarget::new applies, so a rule and a target agree on what one host is. A matcher that disagreed would re-prompt for a host approved a second earlier. It is applied inside matches as well as by the caller, because a matcher that is only correct for one caller has a hole waiting for the second one.

Two spellings that block nothing

WebFetch(domain:bücher.example) and WebFetch(domain:::1) both parse, both are kept, and neither can meet a host any fetch presents. Hosts arrive from Url::host_str, which has already applied IDNA and already bracketed an IPv6 literal, so the matcher only ever sees xn--bcher-kva.example and [::1]. In an allow list that costs a prompt. In a deny list it is a protection that protects nothing, which is the same shape as Bash(rm *), and it gets the same answer: a warning at boot.

Detection is two lines. Inert::of answers Unicode when the pattern is not ASCII, and UnbracketedColon when it contains a : and does not begin with [. Inert::because supplies the clause explaining what this build will do with the rule.

The suggestion is computed, and sometimes withheld

Inert::rewrite for an unbracketed colon is format!("[{pattern}]"). For Unicode it is built label by label: an ASCII label is already its own answer, a label containing * returns None for the whole rewrite because * is not valid IDNA input, and anything else goes through idna::domain_to_ascii, whose failure or empty or non-ASCII result also ends the attempt. Where the rewrite cannot be computed the suggestion is omitted rather than guessed at, because hand-punycoding is how xn--bcher-kva becomes xn--bucher-kva. tested a_rewrite_that_cannot_be_computed_is_omitted_rather_than_invented asserts the note for two such rules contains "blocks NOTHING" and does not contain "Write `". a_suggested_rewrite_keeps_the_wildcard_it_was_written_with asserts *.bücher.example is suggested back as *.xn--bcher-kva.example, wildcard intact.

The matcher was not changed, and a premise of the plan was false

Converting the pattern instead of warning about it was the obvious fix and was rejected on three grounds. It moves the security surface: matching goes from comparing ASCII labels to running UTS-46 over attacker-influencable strings on both sides of every match, and a conversion bug can widen a match where a warning cannot. Wildcards are not valid IDNA input, so *.example.com would need a label-skipping policy nobody has asked for. And the rule stays live for a caller that hands the matcher a Unicode host directly, which the test matrix pins. idna is used at boot, in the warning path only. The matcher itself is unchanged. tested The last clause is an assertion: a_unicode_domain_rule_is_announced_and_the_deny_wording_is_the_loud_one ends by asserting for_egress("WebFetch", "bücher.example") is still Some(Decision::Deny).

One premise of the plan that built this turned out false. idna returns Ok for a wrong answer: b*cherü.example converts to xn--b*cher-8ya.example, the wildcard swallowed into punycode with no error. "If idna refuses a label, omit the suggestion" caught nothing on its own, and the shipped code checks each label for a * itself before calling idna at all.

Three near-misses that get no warning

Each was considered and left alone, on the argument that a warning firing on working configuration is its own defect.

  • domain:*.0.0.1 matching 127.0.0.1 label-wise. The pattern is legal, does what the mechanism says, and matches real things. The test matrix rows are its documentation.
  • example.com.. and example.com being the same host. Both sides strip identically, and the matrix row's own comment says tightening one side alone is the hazard.
  • ASCII-only case folding. The only rules it can bite are non-ASCII rules, and every one of those already warns.

What is not settled here

  • unverified The claim that hosts always arrive already punycoded and already bracketed rests on Url::host_str's documented behaviour and on the web tools building their NetworkTarget from a parsed Url. It was not traced through every one of the six network-declaring tools for this page. What would settle it: reading each tool's network_target and confirming none of them constructs a host from raw argument text.
  • unverified The idna behaviour quoted above, that b*cherü.example converts without error, is recorded in notes/plans/silent-wrong-answers.md and was not re-run here. What would settle it: a three-line program calling idna::domain_to_ascii on that string and printing the result.
