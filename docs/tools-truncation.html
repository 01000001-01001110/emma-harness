The truncation rule

Tools the trait outcomes truncation ToolCtx containment files Edit Bash tasks web LSP screenshot

Name the limit, name the loss, name the remedy, or say plainly that no argument raises it. Every cap in the four tool crates is tabulated below against that rule. The defect that produced it was a tool advising the model to narrow a request when what had been dropped was an inventory it had no way to narrow.

Half an admission

truncated: true on its own is true and useless. It does not say whether the prose or an inventory was lost, does not say how much, and does not name the argument that would get the rest. A tool knows all three at the moment it cuts and nothing downstream can reconstruct them. 

    /// *Which* cap cut, how much it cut, and what would raise it — one line,
    /// written by the tool that did the cutting.
    ///
    /// `truncated` alone is only half an admission. "Output was truncated" is
    /// true and useless: it does not say whether the prose or an inventory was
    /// lost, does not say how much, and does not name the argument that would
    /// get the rest. A tool knows all three at the moment it cuts and nothing
    /// downstream can reconstruct them, so it says them here and the runtime
    /// passes them on verbatim — to the model in the result, and to the human
    /// on the terminal line.
    pub truncation: Option<String>,
crates/tool-api/src/lib.rs — ToolOutcome::truncation

The note is said once, and it used to be said twice

The rule is unchanged: name the limit, name the loss, name the remedy. What changed on 2026-09-06 is that it is said once. tools/fs writes [truncated: reason] into the content and sets truncated_because(reason), and the runtime used to append its note unconditionally, so the same sentence arrived at the model twice: every one of the 24 truncated Read results and both truncated Globs in the audited logs carried it doubled. A tool that sets the flag without writing the line, which is the other half of the API, still gets the note.

The check matches the whole rendered sentence rather than the [truncated: prefix alone, because a file whose own contents contain that string would otherwise suppress a note it never carried. Trailing whitespace is ignored on both sides, since the reader ends its line with a newline and the runtime's note begins with one. tested: a_truncated_result_says_so_once_rather_than_twice and a_tool_that_only_sets_the_flag_still_gets_the_note pin both halves, so removing the check turns the first red and inverting it turns the second red.

The same file's the_two_cuts_stay_two_sentences covers all four combinations of the result cap and the walk ceiling, including the both-fired case, and asserts a walk ceiling is not described as a result cap.

Several cuts stay several sentences

When more than one cap fires they join with ; also and stay separate clauses. Merge them and you conclude the pattern was too broad when it was the traversal that gave up, or you raise max_chars, see the prose come back, and never learn the link list is still short.

certified The connective is the same literal in three places. grep -rn '; also ' tools/ --include=*.rs at commit a3eba74 returns exactly three lines: glob.rs:235, grep.rs:373 and digest_md.rs:445, each a join. It is copied rather than shared, so a fourth crate can spell it differently and nothing would notice.

What holds it

tested no_tool_here_cuts_without_naming_the_cap drives Glob, Grep, Read and Bash past their caps in one sandbox and demands of each: the flag set, a truncation reason over 40 characters containing a digit, and [truncated: present in content as well, because the model reads the content and not the struct. a_whole_answer_claims_nothing is the other half. An uncut result must carry neither, or the file would be satisfiable by marking everything truncated.

On the web side the closing test is the_schema_offers_the_argument_the_truncation_notice_advertises, which asserts the notice may only name a knob the schema actually offers, and that the stated ceiling appears in that knob's description. That is the original defect written as a property.
