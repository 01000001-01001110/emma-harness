Surface

Configuration

Emma reads seven kinds of file across three scopes, and they do not all fail the same way. A mistake in the project's harness refuses the boot and names the file; a mistake in a personal preference costs the preference and says so; a key belonging to another program is ignored. This is the chapter to read when something you configured did not happen.

certified proven, and a reader can repeat it: a file, a command, a count
observed seen once, live, not repeatable on demand
tested a test that was shown to fail
unverified believed, not checked

The shape of it

Three crates read configuration and none of them shares a file with another. emma-harness reads the project's directory, which is .emma/ or .claude/, found by walking up from the working directory. The emma binary reads ~/.emma/settings.json for what belongs to the person rather than to the repository. emma-llm reads ~/.emma/credentials.json for the key. Nothing personal is settable from the project, and nothing about the project is settable from the home directory.

Emma does not adopt your global Claude Code configuration. It recognises a .claude/ directory in a project, so a skill or a command already written for Claude Code works unchanged, and it refuses to read ~/.claude/ as a harness at all. The one thing that crosses from there is the deny list, never allow and never ask, so another program's standing grants cannot widen what Emma may do.

The command to run first is emma config check. It loads everything in this chapter, prints what resolved, and calls no model. Most of the certified claims on these pages are its output.

crates/harness/src/lib.rs; crates/emma/src/settings.rs; crates/llm/src/auth.rs; crates/emma/src/term/theme.rs; crates/emma/src/commands.rs — config_check

  3. The spine: .emma/config.json Five keys and a sixth is a load error. Personas, the tool allowlist that is a filter rather than an assertion, and the declaration half of hooks and the status line.
  4. Reading .claude/, and what is not adopted The four things the harness doc lists as not carried over, twenty-two characters that make a command string a shell string, and the user scope that contributes sixty-four grants and nothing.
  5. Skills and commands One directory layout read two ways: strict for Emma's own files, tolerant for somebody else's. Licence headers, a catalogue that must not depend on directory order, and a tool that is not registered when it would not work.
  6. Agent files One format, two jobs, opposite selection rules, and nothing that fails the boot. The empty list that means inherit, and the byte-exact opener that once made ninety files out of ninety mean something other than what they said.
  7. Your own files ~/.emma/settings.json, where a typo is silence and an unknown provider is not; the four tool settings that are one program name and never a command line; and the credential write that merges because one that replaced deleted a key it had never heard of.
  8. Themes A file of colours that can cost colour and nothing else. Per-role failure, a reserved name, the two things a theme may not do, and nine problems in one file with five printed.
  9. Why did my setting not apply Five checks in the order that rules each other out, the three files that swallow a key they do not know, and every refusal in the chapter listed by its first line.

If you only read one thing

Run the command. It answers the first three questions on the last page before any of the rest matters. 

$ emma config check | head -3
cwd            C:\src\emma
harness        C:\src\emma\.emma
