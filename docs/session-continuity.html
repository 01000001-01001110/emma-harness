Two questions answered out of the same records, neither about the conversation. What was the interrupted run booted against, and has anybody used Emma in this directory before? Both are read from transcripts rather than from a marker file, and both are honest about what they did not look at.

Four fields, any of which may be missing

// crates/emma/src/session.rs
/// What the file says the interrupted run was booted against.
///
/// Every field is a string that may be empty, because a session written before
/// a field existed simply does not have it, and a warning derived from a
/// missing value is noise that trains people to ignore warnings.
#[derive(Debug, Default, Clone, PartialEq, Eq)]
pub struct Continuity {
    pub instructions_hash: String,
    pub tool_schema_hash: String,
    pub model: String,
    pub cwd: String,
}

Strings rather than Options, with the empty string carrying the "not recorded" meaning, and the check below skipping any field that is empty. It comes to the same thing and it makes the missing case the default for a struct that derives Default. cwd sat on the type from the beginning and, for a while, was the one field differences did not compare. An earlier version of this page explained the gap as intentional, on the argument that resuming into a different tree is a request the user made explicitly by naming the session. That argument covered --resume <id> and nothing else. The hazard locate names in its own doc ("a conversation about the wrong repository with write tools attached") was the only drift that arrived silently while three cheaper ones all warned. It is compared now, same as the rest.

crates/emma/src/session.rs — Continuity, locate 
// crates/emma/src/session.rs
/// The last `goal` record's account of the harness, because it is the one the
/// restored messages were actually produced under.
fn continuity_of(records: &[Value]) -> Continuity {
    let mut out = Continuity::default();
    for record in records {
        if record["kind"] == "goal" {
            out = Continuity {
                instructions_hash: string(record, "instructions_hash"),
                tool_schema_hash: string(record, "tool_schema_hash"),
                model: string(record, "model"),
                cwd: string(record, "cwd"),
            };
        }
    }
    out
}

Last rather than first, and assigned whole rather than merged field by field. A session whose model changed halfway through reports the model of its final goal. That is the harness the restored messages were produced under. The record is a goal record, so a /model switch inside a goal is not picked up here at all; it leaves a model_changed record that nothing reads back. sub.goal records are invisible to the comparison record["kind"] == "goal", so a delegation's model does not overwrite the parent's.

Warn, do not refuse

// crates/emma/src/session.rs
/// What changed between the run that wrote the file and the run about to
/// continue it, in sentences a user can act on.
///
/// **Warn, do not refuse.** The user asked to resume; declining would leave
/// them with a transcript and no way to use it, and the thing that is
/// actually dangerous is not the change but the change being invisible. A
/// conversation continuing under instructions it was never held to is the
/// "booted on the wrong prompt" failure this project has already paid for,
/// arriving one level along — so each line names the field, the old value
/// and the new one.
pub fn differences(
    &self,
    instructions_hash: &str,
    tool_schema_hash: &str,
    model: &str,
    cwd: &str,
) -> Vec<String> {
    let mut out = Vec::new();
    let mut check = |what: &str, was: &str, now: &str, cost: &str| {
        if !was.is_empty() && was != now {
            out.push(format!(
                "{what} changed since this session ran: {was} → {now}. {cost}"
            ));
        }
    };
    check(
        "instructions",
        &self.instructions_hash,
        instructions_hash,
        "The restored conversation was produced under a prompt this run is not using.",
    );
    check(
        "tool schema",
        &self.tool_schema_hash,
        tool_schema_hash,
        "A tool the transcript calls may not exist now, or may take different arguments.",
    );
    check(
        "model",
        &self.model,
        model,
        "The turns being handed back were written by a different model.",
    );
    // `cwd` was recorded from the beginning and never compared, so the one
    // hazard `locate` warns about in its own doc — "a conversation about the
    // wrong repository with write tools attached" — was the only drift that
    // arrived silently, while three cheaper ones all warned. Resuming a
    // session by id from another project is exactly how that happens.
    check(
        "working directory",
        &self.cwd,
        cwd,
        "This conversation is about a different directory than the one you are in, \
         and the tools that write files are pointed at this one.",
    );
    out
}

Each line names the field, the old value, the new one and what the difference costs. The cost sentences explain what each change means: a hash pair tells a user something changed and not what it means for the conversation they are about to continue. An empty recorded value produces no line, so a file from before a field existed is silent rather than noisy. tested resuming_into_a_changed_harness_names_what_changed in crates/emma/tests/resume.rs, which now also asserts that a cross-project resume names both directories.

crates/emma/src/session.rs — Continuity::differences

The four warnings are emitted late in startup rather than beside the resume line, because Delegate is registered after the resume is resolved and a schema hash taken earlier would hash a tool surface no request will carry. main.rs calls differences after harness.select_tools(registry) has consumed the registry, and prints each line through term.warn. The current directory is read at the call site, and one that cannot be read becomes the empty string. The empty-skip in check is on the recorded value, not the current one, so a file that recorded a directory still gets its warning in that case, with nothing after the arrow.

Whether anyone has used Emma here

// crates/emma/src/session.rs
/// Whether this is somebody's first run, and how that was decided.
///
/// **Decided from the session history rather than from a marker file.** A
/// marker is a second source of truth that can be deleted, copied between
/// machines, or written by a run that then crashed — and the question "has
/// anyone used Emma here?" already has an answer on disk, in the transcripts.
///
/// Two reasons, kept apart because they mean different things to the person
/// reading the welcome: there is no session directory at all, or there is one
/// and nothing in it was run from this working directory. The second is the
/// common one — a new project on a machine that has used Emma before — and it
/// is deliberately treated as a first run, because what the welcome lists is
/// *this project's* harness, commands and skills.
///
/// **The scan is bounded.** Sessions from every project share one directory and
/// this runs at startup on every interactive run, so only the newest
/// [`FIRST_RUN_SCAN`] files are read. That makes the answer "no *recent*
/// session from here", which is what [`FirstRun::reason`] says — an honest
/// narrower claim rather than a broad one that would cost a full directory read
/// before the first prompt.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FirstRun {
    /// Emma has never had anywhere to write a transcript.
    NoSessionDirectory,
    /// There are sessions, and none of the recent ones ran here.
    NoneFromHere,
}

/// How many session files back the first-run check looks. Fifty is far more
/// than a person switches between in a day and is one directory read plus fifty
/// small file reads in the worst case.
const FIRST_RUN_SCAN: usize = 50;

Fifty files, newest id first. The bound is what separates this from locate, which reads the whole directory if it has to: locate runs when a user asked for a session and can afford the scan, while this runs before the first prompt of every interactive run and cannot.

The trade is stated rather than hidden. A session that ran here long enough ago falls off the end of the window and the welcome is shown again, which is why reason says "no recent session was recorded from this directory" and not "you have never worked here". tested the_scan_is_bounded_so_startup_does_not_read_a_whole_history writes one session from here, then FIRST_RUN_SCAN + 1 sessions from elsewhere, and asserts the answer is NoneFromHere.

crates/emma/src/session.rs — FIRST_RUN_SCAN and its test

In the corpus today that window covers under half the directory: certified, 103 files at 2026-08-16 20:28 EDT against a 50-file scan, so 53 files are out of reach of the check even though locate would still find them. The counts are on The corpus. 

// crates/emma/src/session.rs
pub fn first_run(dir: Option<&Path>, cwd: &Path) -> Option<FirstRun> {
    let Some(dir) = dir.filter(|d| d.is_dir()) else {
        return Some(FirstRun::NoSessionDirectory);
    };
    let Ok(entries) = fs::read_dir(dir) else {
        return Some(FirstRun::NoSessionDirectory);
    };
    let mut candidates: Vec<PathBuf> = entries
        .filter_map(|e| e.ok())
        .map(|e| e.path())
        .filter(|p| p.extension().and_then(|e| e.to_str()) == Some("jsonl"))
        .collect();
    if candidates.is_empty() {
        return Some(FirstRun::NoSessionDirectory);
    }
    // Ids sort by time, so the newest are at the end — the same ordering
    // `locate` relies on, and for the same reason: an mtime moves when a file
    // is copied and an id does not.
    candidates.sort();
    for path in candidates.iter().rev().take(FIRST_RUN_SCAN) {
        let Ok(records) = SessionLog::read(path) else {
            continue;
        };
        if records
            .iter()
            .any(|r| r["kind"] == "goal" && same_dir(&string(r, "cwd"), cwd))
        {
            return None;
        }
    }
    Some(FirstRun::NoneFromHere)
}

None is the not-a-first-run answer, which reads oddly and keeps the caller simple: main.rs does if let Some(why) = session::first_run(…) and prints the welcome with the reason. Three separate paths return NoSessionDirectory: no directory was resolved, the directory will not open, and the directory has no .jsonl in it. The test covers the first and the third together, on the argument that they are the same answer to the person reading the welcome, and the second is the unreadable-directory case that nothing exercises.

crates/emma/src/session.rs — first_run; crates/emma/src/main.rs

The match on each file is the same one locate uses: a goal record whose cwd canonicalises to this one. same_dir is on Resume, and its empty-string rule is what stops the 48 empty files and the pre-cwd records from counting as a match.

The 48 empty files still cost a read each. SessionLog::read returns an empty vector for a zero-byte file, the any is false, and the walk continues. Emptiness is not tested for. 

// crates/emma/src/session.rs
impl FirstRun {
    /// Said out loud in the welcome, so a returning user can tell whether
    /// something is wrong rather than wondering why they are being introduced
    /// to a tool they already use.
    pub fn reason(self) -> &'static str {
        match self {
            Self::NoSessionDirectory => {
                "there is no session directory yet, so nothing has been recorded anywhere"
            }
            Self::NoneFromHere => "no recent session was recorded from this directory",
        }
    }
}

tested three ways. a_machine_that_has_never_run_emma_is_a_first_run covers a missing directory, a None directory and an empty one. a_new_project_on_a_machine_with_history_is_still_a_first_run is the case the welcome targets: a session recorded from elsewhere yields NoneFromHere, and once something has run here the answer becomes None. each_reason_says_which_one_it_was asserts the two sentences differ in the way a reader needs.
