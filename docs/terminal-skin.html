The vocabulary, and the blank row

The terminal Surface Frame Layout Colour Themes Vocabulary Transcript Markdown Diffs Status Sidebar Dock User tools

render.rs turns an event into styled lines and nothing else: no terminal, no locks, no writes. That is what makes “a refused call and a failed call must not look the same” a thing a test can assert rather than something somebody has to squint at. Beside it, spacing.rs owns the one rule about blank rows, and welcome.rs composes the block a new user sees once.

Two glyph sets, and why the distinction is made twice

Every tool line used to be ●. A call that ran, a call that failed with a ToolError, a call the human declined and a call a PreToolUse hook refused all arrived as the same bullet in the same weight, and the only way to tell them apart was to read the sentence after them. Those are four different things, one of them policy the user cannot override.

So there are sixteen glyph slots and two sets. UNICODE is ▶ ◆ ✓ ✗ ⊘ ⊗ ↻ ■ plus the punctuation; ASCII is > * + x o X ~ =. The reason for two is a Windows console whose output code page is not UTF-8, where ✓ renders as two pieces of mojibake, “and a transcript that looks broken reads as a broken program rather than as a stylistic choice.”

Colour is the second half of every distinction, never the first. “Colour alone fails on a terminal with sixteen of them, on a terminal with none, and on the substantial minority of readers who cannot distinguish the red from the green. Glyph alone is legible and drab.” tested: a_started_a_succeeded_a_failed_a_refused_and_a_blocked_call_all_look_different is written as “no two of these share a glyph” over seven events rather than as seven assertions on seven literals, “because the property is the distinctness and a test on the literals would pass a change that made two of them identical.” It then asserts separately that refused and blocked differ in colour too, because one of them is a decision the user can revisit and the other is not.

The Skin's methods, one per thing that can happen

Sixteen of them, all returning Vec<Line> rather than writing, so the whole vocabulary is available to a test as data. Eight go through one private helper:

crates/emma/src/term/render.rs · Skin::marked

    /// A marked line: the glyph in its colour, then the text.
    ///
    /// The glyph carries the weight as well as the colour, because bold is the
    /// one emphasis a sixteen-colour terminal and a colourless one both have.
    fn marked(&self, glyph: &str, role: Role, head: Span<'static>, tail: &str) -> Line<'static> {
        let mut spans = vec![
            Span::styled(glyph.to_string(), self.palette.bold(role)),
            Span::raw(" "),
            head,
        ];
        if !tail.is_empty() {
            spans.push(Span::raw(" "));
            spans.push(Span::styled(
                tail.to_string(),
                self.palette.style(Role::Text),
            ));
        }
        Line::from(spans)
    }

Two kinds of “there is more than this”

Skin::body caps a tool result at RESULT_LINES = 8 and appends … N more lines. That is the screen leaving something out. tool_ok's truncated flag is the tool having stopped early, which means the model's copy is short too, and conflating the two “would tell a user their output was merely abbreviated when it was actually cut.”

The reason argument is passed through whole rather than summarised, and the comment names the incident behind it: “‘output was truncated by the tool’ on a page whose text was nowhere near its limit sent a reader looking at the wrong number entirely; the tool's own sentence names the right one.” A tool that did not say which cap bound gets … output was truncated by the tool, which did not say by which limit rather than an implication that the reader has been told. tested: a_truncated_tool_and_a_long_result_say_different_things and a_stated_reason_reaches_the_screen_whole.

The two exits to a stream

crates/emma/src/term/render.rs · for_stream

/// What the fallback path writes for one line.
///
/// **The one decision that keeps a redirected stream clean.** A palette at
/// [`Level::None`] means either `NO_COLOR` or a destination that is not a
/// terminal, and in both cases the answer is the text and nothing else — not
/// even a bold. `emma … | tee` produces a file somebody reads, and an escape
/// byte in it is a defect however tasteful the attribute was.
///
/// The viewport does not come through here: ratatui writes styled cells, so
/// bold and reverse survive there even when colour does not.
pub fn for_stream(skin: &Skin, line: &Line<'_>) -> String {
    if skin.palette.level == Level::None {
        plain(line)
    } else {
        sgr(line)
    }
}
crates/emma/src/term/render.rs — for_stream, plain, sgr, codes, color_code

sgr writes the parameters by hand rather than delegating to crossterm, and the doc gives two reasons: the fallback path has to produce a byte-for-byte predictable line for a test, and this is the only place in Emma that needs it. codes handles bold, dim and reversed; color_code handles the sixteen names, Indexed as 38;5;n, Rgb as 38;2;r;g;b, and Color::Reset as nothing at all, because the user's own colour is asserted by silence.

Four modules carry a test named with_no_colour_not_one_escape_byte_is_emitted: render, markdown, diff and statusline. The render one walks twelve event kinds and asserts both that for_stream contains no \x1b and that it equals plain(line). tested And the same claim holds end to end against the built binary, which the surface page certifies.

Everything is measured in display columns

The region comment is the argument in full, and it names the failure it fixed: “Anywhere a budget derived from area.width was compared against chars().count(), a line of CJK overran its box by its own length and the cell after it was somebody else's.”

The measurement is ratatui's own Span::width, which is what Layout and Buffer measure with, rather than a second opinion from a crate imported beside it. Two width tables that disagree is the same class of bug as two crossterm versions that disagree about a KeyEvent, and the manifest already argues that one.

The limit is stated rather than hidden: unicode-width sums per character, so a ZWJ emoji sequence is measured as the sum of its parts while a terminal draws one glyph. Nothing here can fix that, “so at least Emma and its renderer are wrong together, which is the property that keeps a box from being overrun by its own contents.”

Six functions live in that region. cols measures a string; cols_upto is the bridge the input box crosses, because Editor counts a cursor in characters (what Left and Right move by) and the terminal wants a column; char_cols measures one character without allocating; rows_used is ceil(width / columns), handed to insert_before; wrap_line breaks a styled line at column boundaries; and owned deep-copies a borrowed line, because Line::to_owned would clone the borrow rather than the data.

wrap_line splits the styled line rather than the plain text, and the reason is concrete: “splitting the plain text and re-styling it is how a diff's + ends up green on one row and not on the next.” A single character wider than the whole width gets a row to itself rather than an infinite loop. tested: a_wrapped_line_keeps_every_character_and_its_styling checks the style of the fragments on either side of a break, and a_wrap_breaks_between_wide_characters_rather_than_through_one puts five CJK glyphs into a five-column window and gets ["一二", "三四", "五"].

Defect: fit can return a string wider than its budget

fit computes keep = budget.saturating_sub(cols(ellipsis)) and then appends the ellipsis unconditionally. With the ASCII glyph set the ellipsis is ..., three columns, so any budget of 1 or 2 produces an empty keep, an empty body, and a three-column result. The guarding test, a_cut_never_lands_inside_a_wide_character, hardcodes … at one column and therefore never reaches it. certified, and by an unusual receipt: sidebar.rs already knows. sidebar::clipped exists solely to make fit total, its doc says “fit itself can overrun a budget narrower than its own ellipsis”, and a_budget_narrower_than_the_ellipsis_still_never_overruns walks budgets 0 to 10 in both glyph sets against clipped rather than against fit. The five callers that use fit directly (app::hint, app::header, view::render_menu, view::preview_lines, and statusbar::attempt, which guards with ENV_MIN) do not have that protection.

The inline status row

Skin::status is the inline viewport's bottom row, and the full-screen successor to it is a different module. Its rule is stated as the reason the row is worth having at all: a field whose value is not known is absent, and a line that does not fit drops fields in a stated order rather than being cut mid-number. Every field of Status is an Option for the same reason: “a readout that is stale is worse than a readout that is missing.”

crates/emma/src/term/render.rs · Skin::status

    pub fn status(&self, width: u16, s: &Status) -> Line<'static> {
        let live = self.live_fields(s);
        for attempt in 0..5 {
            let left = self.identity(s, attempt);
            // Columns, not characters: a working directory with CJK in its name
            // is twice as wide as it is long, and the gap computed from its
            // length pushes the live fields off the end of the row.
            let used: usize = left.iter().chain(live.iter()).map(|sp| sp.width()).sum();
            let gap = usize::from(width).saturating_sub(used);
            if gap >= 1 || attempt == 4 {
                let mut spans = left;
                spans.push(Span::raw(" ".repeat(gap.max(1))));
                spans.extend(live);
                return Line::from(spans);
            }
        }
        unreachable!("the last attempt always returns")
    }
crates/emma/src/term/render.rs — status, identity, live_fields

The drop order is session id, then the working directory shortened to its last component, then the directory entirely, then the model. The labels themselves carry a small piece of history: the second meter was called spend until the owner read ctx 73k/120k · spend 103k/500k and asked whether the two were the wrong way round. They were not, and the doc explains why the question was still the defect: “a label that invites the question is the defect, and spend invited it — it reads as a level, like ctx, when it is an accumulation.” total is the same five columns, so the drop order is unchanged. tested: the_cumulative_meter_is_not_labelled_like_the_snapshot_one asserts against the exact numbers from that screen.

Defect: the live half is never dropped, so the row can be clipped

identity sheds four ways as drop rises, but live_fields is computed once, outside the loop, and appended whatever happens. At attempt == 4 the function returns unconditionally, with gap.max(1) of padding, even when used already exceeds width. On a narrow enough row that produces exactly the total 34k/50 the doc says must never happen: a number that is wrong rather than one that is missing, clipped by set_line where the buffer runs out. unverified: the width tests run at 120, 64 and 34, and the CJK test at 60 with only a ctx field. A test at width 20 with all three live fields populated would settle it.

Three small formatters finish the region. pressure(used, cap) is green with room to spare, yellow past three quarters, red past the cap, and returns Role::Text when the cap is not positive, because a cap of zero is “no cap” rather than a division by zero. human abbreviates counts (12k, 1.5M). clock writes elapsed time in the units a person waiting reads. last_component shortens a path.

One rule about blank rows

A blank row is a boundary between two blocks, and it is written only when there is a block on both sides of it. Nothing emits one of its own. An emitter that has finished a block, or is about to start one, calls separate(), which records that a boundary exists; the blank is materialised later by apply, and only if another block actually arrives.

crates/emma/src/term/spacing.rs · Spacing::apply

    pub fn apply(&mut self, mut lines: Vec<Line<'static>>) -> Vec<Line<'static>> {
        if lines.is_empty() {
            // Nothing arrived, so no boundary was crossed. The declaration
            // stands until something does arrive — an empty batch must not
            // spend the separator the next real block is owed.
            return lines;
        }
        let owed = std::mem::take(&mut self.pending);
        if owed && self.wrote && !self.last_blank && !blank(&lines[0]) {
            lines.insert(0, Line::default());
        }
        self.last_blank = lines.last().is_some_and(blank);
        self.wrote = true;
        lines
    }
crates/emma/src/term/spacing.rs — Spacing::apply, separate, wrote_text, blank

Three booleans, and each guards a defect that was on the screen the owner photographed. pending makes separate() idempotent, which is what stops two emitters stacking their separators; wrote stops a blank row being the first thing in the transcript, under the shell prompt the user typed emma at, where “a gap reads as output that went missing”; and last_blank, together with the !blank(&lines[0]) check, stops a separator landing beside a blank row the content wrote itself.

Content blanks are never removed, only allowed to suppress a separator, and the test says why that distinction matters: blank_rows_a_block_wrote_itself_are_left_alone is framed as the assertion that stops “collapse blank runs” from looking like a reasonable simplification, because a blank line inside a fenced code block is part of what the reader copies out. tested, seven tests in 235 lines.

It is a state machine and not a filter over finished output because the terminal is irreversible: “once a row is written it is the terminal's and cannot be taken back, so the decision about a blank row has to be made before it is emitted.” wrote_text exists for the one path that bypasses apply entirely, the fallback's raw prose write, so it can say that rows happened.

Which path it still governs

With the full-screen frame as the default, spacing.rs governs the plain path, -p, EMMA_NO_FRAME and the EMMA_UI=inline hatch. In the full-screen frame the transcript buffer separates the blocks it holds and Frame::separate is a no-op, because “separate() on the inline path had to be a declaration because the terminal owned the rows; here the buffer owns them and the rule is structural.” The module's own doc still describes the pre-2026-08-12 world throughout, which is worth knowing before reading it. certified: spacing.rs's module doc says “Both output paths hold one of these: the viewport, and the plain-lines fallback”, and Frame::separate returns without touching it under Ui::Full.

The block a new user sees once

welcome.rs is 211 lines and three functions, and its premise is one sentence: “A welcome that lists capabilities the run does not have is worse than no welcome, because the first thing it teaches is that Emma's own account of itself cannot be trusted.” So every line of it is read from the run that is actually starting: the harness that loaded, the tools that survived selection, the commands and skills that exist in this project.

Three things to type, and no more, “a list of twenty options is a list nobody reads”. A project with no commands and no skills is told so explicitly rather than left with an absence, because “a user who has read about commands and skills and sees neither should learn that this project has none, not wonder whether Emma has them.” And the last row says why they are seeing it, from Welcome::reason, so a returning user can tell whether something is wrong.

The block does not pad itself. Its first and last rows are content, and the blanks between its sections are its own layout rather than the gap around it, which is the one exception the Line::default() source test names. tested: the_welcome_leaves_the_gap_around_itself_to_whoever_is_placing_it asserts all three of those at once.
