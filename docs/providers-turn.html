The turn that comes back

Providers & models The boundary Content blocks The turn back Model limits Caching The cache floor Retry Credentials

One JSON body and a few dozen SSE fragments have to produce the same AssistantTurn, down to the signature on a thinking block, because that turn goes straight back out on the next call. The type it produces carries a counter whose name lies: with caching in play, input_tokens is not the input.

Four counters, and the one that is not what it says

crates/llm/src/lib.rs · struct Usage

/// Provider-reported token counts for one model call.
///
/// **`input_tokens` is not the input.** With prompt caching in play the
/// Messages API splits the input three ways and `input_tokens` carries only the
/// *uncached remainder* — the bytes that were neither read from nor written to
/// the cache. In tustle-agent, where this was learned the expensive way, a
/// 72,549-token turn was recorded as `input_tokens: 2`. Anything that means
/// "the context this call carried" must use [`Usage::billable_input_tokens`]
/// or [`Usage::billable_total_tokens`]; summing the bare field under-counts by
/// up to ~10× the moment caching starts hitting, which silently loosens every
/// cap folded from it.
///
/// The two cache fields default to `0`, which covers providers that do not
/// report them and requests that sent no `cache_control` at all. A `0` here
/// means "nothing cached", never "unknown".
///
/// There is deliberately no `total()`. tustle-agent had to keep one and
/// `#[deprecated]` it so the wrong call compiled wrong rather than merely
/// reading wrong; Emma has no callers predating caching, so the trap cannot
/// recur here — the only way to get a total is to ask for the honest one.
#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
pub struct Usage {
    /// Uncached input only. See the type-level note before summing this.
    pub input_tokens: i64,
    pub output_tokens: i64,
    /// Input tokens written into the cache on this call (billed at 1.25×).
    #[serde(default)]
    pub cache_creation_input_tokens: i64,
    /// Input tokens served from the cache on this call (billed at 0.1×).
    #[serde(default)]
    pub cache_read_input_tokens: i64,
}
crates/llm/src/lib.rs — Usage
Field What it counts Price vs base
input_tokens The uncached remainder only. Neither read from nor written to the cache. 1.0×
cache_creation_input_tokens Written into the cache on this call. 0 when the marker was ignored. 1.25×
cache_read_input_tokens Served from an entry a previous call wrote. 0.1×
output_tokens Everything generated, thinking included. output rate

billable_input_tokens() adds the first three; billable_total_tokens() adds output on top. Neither is weighted by price, because a cost view applies the three multipliers separately while cap semantics count tokens. There is no total(), so those two methods are the only ways to get one. billable_counts_all_three_input_fields pins the arithmetic and then states the scar as an assertion: assert!(usage.billable_input_tokens() > usage.input_tokens * 100) on a fixture where the bare field is 41 and the truth is 32,241. tested The mutation was not run here; the claim rests on reading the assertion, which cannot pass if the sum drops a field.

Both cache fields carry #[serde(default)], so a response that omits them parses rather than failing. absent_cache_fields_parse_as_zero_not_as_an_error sends a usage object with two keys and asserts both cache fields read 0 and the billable input equals the bare input. tested The cost of that default is that a provider which stopped reporting the fields would look identical to one that cached nothing, which is a real ambiguity the type accepts and its doc names.

The batch path

read_batch reads the body to a string, parses it, and hands it to turn_from_message. A parse failure becomes LlmError::Protocol carrying the serde message and the trimmed body, so an HTML error page from a proxy shows up as prose rather than as "invalid JSON".

crates/llm/src/anthropic.rs · turn_from_message

/// Batch mode: the whole message arrived at once.
fn turn_from_message(msg: &Value) -> Result<AssistantTurn, LlmError> {
    if msg.get("type").and_then(Value::as_str) == Some("error") {
        return Err(LlmError::Api {
            status: 200,
            message: api_message(&msg.to_string()),
        });
    }
    let content = msg
        .get("content")
        .cloned()
        .ok_or_else(|| LlmError::Protocol("the response carried no content array".into()))?;
    let usage: Usage = msg
        .get("usage")
        .cloned()
        .map(serde_json::from_value)
        .transpose()
        .map_err(|e| LlmError::Protocol(format!("usage: {e}")))?
        .unwrap_or_default();
    let stop_reason = msg
        .get("stop_reason")
        .and_then(Value::as_str)
        .unwrap_or_default()
        .to_string();
    // **The same refusal the streaming path makes, and it was missing here.**
    // `Assembly::finish` rejects a turn with no stop reason because "a turn
    // reading 'The tests all pa' was handed to the loop as a finished answer,
    // with no truncation signal anywhere downstream". The batch decoder took
    // `unwrap_or_default()` and passed the empty string on -- and batch is the
    // mode `-p` runs in, so the unattended path was the unguarded one.
    //
    // A reviewer drove a stub server with a batch body carrying no stop_reason
    // and got exactly this row's worked example back, accepted as finished.
    // There is a second cost: `stop_reason == "max_tokens"` is what DEF-026's
    // truncation warning keys on, so in batch mode a cut-off turn was silent as
    // well as unreported.
    if stop_reason.is_empty() {
        return Err(LlmError::Protocol(
            "the response carried no stop reason, so the turn is incomplete — there is no \
             way to tell a finished answer from one the connection cut short"
                .into(),
        ));
    }
    turn_from_content(content, stop_reason, usage)
}
crates/llm/src/anthropic.rs — turn_from_message

Five outcomes live in that function. An error-shaped body arrives with HTTP 200 and never reaches classify, so it is turned into Api { status: 200 } here. A missing content is a protocol error. A usage object that will not deserialize is a protocol error naming the field; a usage that is absent entirely defaults to four zeros. And a missing stop_reason is a protocol error, the same refusal Assembly::finish makes on the streaming path.

That last one was true of streaming and not of batch until 2026-08-23, and batch is the mode -p runs in. The streaming path had refused an empty stop_reason since DEF-020; this decoder read it with unwrap_or_default() and passed the empty string on. Streaming refused empty stop_reason; batch did not until 2026-08-23.

An independent reviewer drove a stub server with a batch body carrying no stop_reason and got back exactly the worked example below, accepted as a finished turn. No fixture had caught it because every batch fixture in the file supplies a stop reason, so the branch had never been exercised. tested a_batch_response_without_a_stop_reason_is_a_fault, with an_ordinary_batch_response_still_decodes as its control. Adding a refusal at a provider boundary is exactly the change that starts rejecting valid traffic, and a boundary that rejects good responses is worse than one that accepts a rare bad one.

There is a second cost, and it is not obvious from here: stop_reason == "max_tokens" is what the loop’s truncation warning keys on, so in batch mode a turn cut off at the output limit was silent as well as unreported.

A stream that closed without ever saying why it stopped did not finish. It was cut. A dropped connection, a proxy timeout and a truncated response all arrive as a clean close, and the code used to return Ok with whatever text had turned up.

A turn reading "The tests all pa" was handed to the loop as a finished answer, with no truncation signal anywhere downstream and no way to tell it apart from a model that genuinely said that. A failure is recoverable (Protocol is retried like any other). A confident half-sentence is not. That asymmetry is why an empty stop_reason is an error rather than a default, and it is the same one this project applies to a truncated tool result.

crates/llm/src/anthropic.rs · turn_from_content

/// The single place a typed turn is derived from content blocks, so batch and
/// streaming cannot drift apart in what they extract.
///
/// This is the whole of the Anthropic-to-Emma translation for a turn, and it is
/// three lines because [`ContentBlock::from_value`] does the deciding — text and
/// tool calls used to be pulled out here by hand into fields beside the blob,
/// and they are now views on the parsed blocks. What a block this client does
/// not model becomes is that function's business too, and the answer is that it
/// is kept whole.
fn turn_from_content(
    content: Value,
    stop_reason: String,
    usage: Usage,
) -> Result<AssistantTurn, LlmError> {
    let Value::Array(blocks) = content else {
        return Err(LlmError::Protocol(
            "content was not an array of blocks".into(),
        ));
    };
    Ok(AssistantTurn {
        content: blocks.into_iter().map(ContentBlock::from_value).collect(),
        stop_reason,
        usage,
    })
}

The stream path

read_stream accumulates bytes into a String, cuts frames on \n\n, takes the line starting data: , parses it as JSON and applies it. A frame with no data: line and a data: line that will not parse are both skipped with continue, so the event: x lines and any keep-alive comment pass through harmlessly. Bytes are decoded with from_utf8_lossy per chunk, which would corrupt a multi-byte character split across a TCP read boundary. unverified Nothing in the suite splits a chunk mid-character; settling it means a stub that writes a two-byte UTF-8 sequence one byte at a time and asserting the assembled text.

crates/llm/src/anthropic.rs — Assembly, read_stream, read_batch

Why the blocks are a map and not a vector

Assembly.blocks is a BTreeMap<usize, Partial> keyed by the index the API assigns each block, so the reconstructed turn is in the order it was sent regardless of frame arrival. finish iterates the map, which yields keys in order, and renders each Partial back to the wire object the batch path would have received.

The one guarded assignment

crates/llm/src/anthropic.rs · Assembly::apply, the message_delta arm

"message_delta" => {
    if let Some(sr) = ev.pointer("/delta/stop_reason").and_then(Value::as_str) {
        self.stop_reason = sr.to_string();
    }
    let u = ev.get("usage");
    let out = pick(u, "output_tokens");
    // Guarded rather than assigned: `pick` cannot tell "absent"
    // from "zero", so an unguarded write would let a
    // `message_delta` carrying only a stop reason erase the count
    // that `message_start` established.
    if out != 0 {
        self.usage.output_tokens = out;
    }
}
crates/llm/src/anthropic.rs — Assembly::apply, pick

pick returns 0 for a missing key, a null, and a genuine zero alike. That ambiguity is what the guard exists for. It costs one case: a turn that really did generate zero output tokens keeps whatever message_start reported, which is also zero, so nothing is lost in practice. str_at is its string twin and returns an empty string for anything missing. A tool_use with no id assembles as a call with an empty id rather than failing.

An error frame ends the turn

A frame of type error returns LlmError::Api with status 200 and the provider's message, prefixed the stream ended in an error. It is not retried: the response was already a success and bytes may have reached the terminal. a_mid_stream_error_frame_ends_the_turn asserts both the message and that the stub saw exactly one request. tested The same path is where a gateway could echo an API key into an error, which credentials covers.

Truncated tool arguments

crates/llm/src/anthropic.rs · parse_tool_input

/// A tool call whose arguments did not parse is a fault, not an empty call:
/// invoking a tool with `{}` because the JSON was truncated would run the wrong
/// action with default arguments.
///
/// The empty-string case is not that case and is deliberately `{}`: a
/// `tool_use` block that carried no `input_json_delta` at all is a call to a
/// tool that takes no arguments, not a truncated one. Truncation leaves a
/// partial fragment behind, and a fragment does not parse.
fn parse_tool_input(json: &str) -> Result<Value, LlmError> {
    if json.trim().is_empty() {
        return Ok(json!({}));
    }
    serde_json::from_str(json)
        .map_err(|e| LlmError::Protocol(format!("tool arguments were not valid JSON: {e}")))
}

The parity test

streaming_assembles_the_same_turn_as_batch sends the same assistant turn twice, once as a batch body and once as 19 SSE frames, and asserts the two parsed turns are equal in text, tool calls, stop reason, usage, content blocks, and finally as whole values. It then asserts the first block is a ThinkingBlock with signature: Some("sig-abc"), with the comment that a thinking block which lost its signature in reassembly is rejected on the next call. Last, it asserts the streaming run produced exactly the two text deltas ["Reading ", "them now."] and that the batch run produced none. tested

That is the test that would catch a divergence between the two paths, and What it cannot catch: both sides are fixtures written by the same author, so a key the real API sends and neither fixture carries is invisible to it. That is exactly the shape of the failure on the previous page.
