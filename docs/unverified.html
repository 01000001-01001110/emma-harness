What is not verified

Everything I believe about Emma and have not checked, gathered from the amber marks on the other pages, with the experiment that would settle each one.

I put this here so the amber does not stay scattered across ninety pages where I will never go looking for it. Each row says what is claimed, why nobody has confirmed it, and what it would take. A row leaves when somebody runs the experiment. Becoming more confident does not count, and that is the only rule this page has.

certified proven, and a reader can repeat it: a file, a command, a count
observed seen once, live, not repeatable on demand
tested covered by a test shown to fail when the guarantee is removed
unverified believed, not checked

Cheap to settle, worth doing first

Each of these costs minutes or a fraction of a cent, and each one currently props up something larger.

ClaimWhat would settle it
Emma's system prompt is smaller than the alternative. The tools half is measured now: 29,505 bytes over 16 tools on 2026-09-05, by crates/emma/tests/prompt_size.rs. What is still unmeasured is the conversion to tokens, the system field (which varies with persona and done-check), and the comparison figure for Claude Code (~30,000 tokens), which is widely reported and never counted here. Submit Emma's exact first-request body to /v1/messages/count_tokens and record the returned input_tokens; the endpoint was already used against this project on 2026-08-11. Claude Code's half needs its request captured off the wire, and is the reason this sat unmeasured while the byte count needed neither a key nor a network. See the goals.
Eight of the ten per-model cache floors. Only claude-opus-5 and claude-haiku-4-5 were measured against the live API. The rest are transcription from a document dated 2026-08-11, and four rows present in that document are missing from the table entirely. The same two-request canary per model, a fraction of a cent each. See Providers.
The chars / 4 token estimate. Called an under-count in both agent.rs and anthropic.rs; nobody has measured the real ratio. Its effect is larger now because a per-model floor of 4,096 means an under-count withholds a marker from a 16 KB prefix rather than a 2 KB one. Count a real prefix with count_tokens and compare against the estimate.
The Ollama window estimator against a real tokeniser. estimate_prompt_tokens counts at four characters per token and a quarter is added as headroom. On the one certified run it over-estimated, which is the safe direction, but that was one prompt of repeated ASCII filler and English prose, CJK or dense JSON would each land differently. See the boundary page. Run a corpus of real session prompts through estimate_prompt_tokens and compare each against the server's prompt_eval_count; the ratio must never exceed 1.25 in the unsafe direction.
Anything at all about OpenAI. Nothing in openai_compat.rs has reached api.openai.com. Both values that distinguish the OpenAI wire from OpenRouter's — max_completion_tokens and a refused temperature — are the fork's claims restated, and a loopback stub can only prove Emma sends what the constant says. One call with an OpenAI key to a cheap model sending max_tokens, expecting a 400 that names max_completion_tokens, then temperature: 0.9 on a reasoning model. Ten minutes with a key.
Six of the seven language servers. Bash, terraform, ansible and python are installed on neither machine; bicep resolves here and has never been started; the PowerShell command line has never been executed because there is no pwsh. Their caveat and install strings are the fork's claims with the platform wording rewritten. See Code intelligence. Install the server named in that page's table and run Diagnostics on a file of that kind with a deliberate error in it. One language at a time.
Whether the two model measurements behind Edit's label tolerance are reproducible. “nemotron-3.5-lightning:30b-mlx sent eight labelled anchors in one run” and “ornith:35b lost a run emitting 1088#f011 as replacement text” are the fork's comments, dated 2026-08-24, and neither was reproduced here. The same goes for the 14 firings that justified accepting both addressing forms at once. A keyless local run against Ollama with a model of that class, driving Read then Edit; and the owner's session store, if those runs survive.
Whether the two SVG figures on each page render correctly. Every diagram in this site was validated by parsing the XML and checking coordinates against the viewBox. None was looked at. Open the pages in a browser. A stranded label or an overlapping box is invisible to arithmetic.
That a temperature ever reaches Anthropic or an OpenAI-compatible host. Both renderers are proven against a loopback stub, and a stub agrees with whoever wrote it. Ollama is the one host this box can reach, and there the two request bodies are certified off a recording proxy. See the boundary. One Messages API call with temperature: 0.2 and one without, comparing the bodies off the socket; and one OpenAI call with a temperature to a reasoning model, expecting the 400 that temperature_field: None exists to avoid.
That a sampling block reaches a goal record. The resolver and the wire are each proven and the join is not: nobody has set sampling.ollama.temperature and then read the record back off disk. Set it, run one goal, and read "temperature_source": "manual" out of the session file.
That plan mode has ever stopped a real write. Six mutations pin the rung's position and its refusal; nothing runs a scripted goal in plan mode and reads the record back. A test in crates/emma/tests/loop.rs asserting the goal completes rather than aborts and the session log carries a denied record with "by": "mode".
How many training records survive --min-ending finished. The 250-record sweep ran with the default filter. emma export-training --min-ending finished, and count.
The whole-crate test count for emma-tools-tasks. The certified 51 predates the five tests behind the task move and sweep. cargo test -p emma-tools-tasks.
What voice, lsp, memory_policy and ui hold. Four settings blocks from the same port, described nowhere on this site beyond one table row. The same is true of the web_search record kind and the three kinds only engine/claude.rs writes. Read the four types in settings.rs and the four call sites, and write the rows.

ClaimWhat would settle it
Anything about macOS behaviour. Eight tests failed there and have been fixed by reading, not by running. Cross-compilation covers five of eight packages; three pull a dependency needing a C toolchain this machine lacks. One #[cfg(unix)] test could not be compiled anywhere. Pull and run the suite on the Mac. Three minutes.
The unix arm of the hook fix. Windows has no SIGPIPE, which is what makes abandoning the pipe safe there. On unix, closing the read end can kill a daemon that later writes. WSL was attempted here; wsl.exe --status returned Wsl/EnumerateDistros/Service/E_ACCESSDENIED. On Linux, add sh versions of the inherited-pipe, last-write and daemon fixtures, run the suite, set the drain grace to zero and require the last-write case to fail, restore it, and verify the daemon's post-abandonment SIGPIPE result.
Whether Chrome is reaped on unix now. It was not, and every killed browser left a zombie; reap_when_it_exits fixed that on 2026-09-06 by moving the handle onto a thread that waits. The fix is #[cfg(unix)] and this is a Windows box, so the arm is not even compiled here. Note that kill -0 succeeds against a zombie, so the obvious check reports the opposite of the truth. On Linux or macOS, kill a session's Chrome and check ps -o stat= -p <pid>; and run reaping_collects_a_child_exit_status there.
Whether /copy reaches the clipboard. It writes OSC 52, and the protocol has no acknowledgement: the terminal honours the sequence or ignores it, with no reply. The PTY harness can prove the bytes leave Emma and can never prove they arrived. See Copying out. Press /copy in a real Windows Terminal and then Ctrl+V somewhere. Ten seconds, and only a person can do it.
What a Shift+drag selection actually contains. Mouse capture takes plain drag-selection, and Shift gives back the terminal's own, which takes whole rows with sidebar columns, borders and gutter interleaved into every line. How bad that is with the sidebar open has never been recorded. Drag with Shift on a real console and paste into an editor. The selection never passes through Emma, so no harness can see it.
Symlinks in the completion gate's tree fingerprint. The fingerprint hashes path and bytes, so a symlink's target is not represented. Two reviewers tried to build a fixture: git normalises a hand-written 120000 entry on refresh, and os.symlink needs a privilege this account does not hold (WinError 1314). A Linux checkout, or Developer Mode enabled here. The exec bit and submodule cases were settled this way and both turned out to be demonstrated collisions rather than theoretical ones.
Whether a non-NTFS Windows volume treats : as an ordinary character. The alternate-data-stream refusal is #[cfg(windows)] and unconditional. If some filesystem Emma might run on allows a colon in a name, that name is refused when it would have worked. See Containment. Run the same probe on a FAT32 or exFAT volume; a USB stick will do.
Whether the leaked-profile warning fires on a real leak. The test produces a removal failure by putting a file where the directory should be. The failure it was written for is a killed Chrome still holding its files open, which was 8 of 66 closes when somebody last instrumented it. Open six live browser sessions, end a goal, and check whether the warning fires and whether the directories it names are on disk.
Every unix path in runctl. libc::kill, setsid, /proc/<pid>/comm and the ps -o comm= fallback are the fork's code, unchanged, and this box has no unix to run them on. On Windows all three signals refuse outright, so the only platform where pause, resume and cancel do anything is the one that has never run them. See Acting on a run. The macOS leg of the port's certification order.
The symlink containment guarantee under include_ignored. a_symlink_out_of_the_tree_is_never_followed is #[cfg(unix)] and did not run here, and include_ignored is a new argument that widens what the walk reaches. Run the suite on macOS, or enable Developer Mode here and add a #[cfg(windows)] twin.
That archiving a live run on Windows really would split a transcript. The guard is tested against a fake process table; what it defends against is read out of the standard library's documented open flags rather than watched. Two processes and a std::fs::rename under a live appender. Twenty lines, on this box.
Whether a daemonized hook outlives Emma's own process. The environment it was tested in confounds the result: a plain unrelated parent behaved the same way, so nothing there is attributable to Emma's code. A run from a normal desktop session rather than a sandboxed one.
Everything the font script does once it reaches Terminal.app. command is certified as produced and nothing has ever run it. The module's central claim is that a font name Terminal does not have is accepted and ignored, which is why the receipt may only say "asked". On the Mac, in Terminal.app: ask for Monaco, then ask for a name that does not exist and read the exit status. Non-zero means the claim is wrong and apply should report the error instead.
That Windows Terminal really offers no in-band font control. What is certified is what Emma does here, not what the terminal would do if sent an OSC 50. Nothing was written at the console, because this session's output is captured and a negative result would be indistinguishable from the capture. In a real Windows Terminal window, emit OSC 50 with a family and a size and watch whether the cell size changes.
Which of the Code page's function keys a terminal actually delivers. The page binds F2 through F10, six of them to language-server questions, and handle_key matches KeyCode::F(n) with no fallback spelling for any of them: a key the terminal keeps never reaches the page and nothing on screen says why. Two cases are reported and neither has been measured here. On macOS the top row is media keys unless Use F1, F2, etc. keys as standard function keys is on, which would cost Terminal.app and iTerm2 users every one of the six. On GTK, F10 is the menu-bar accelerator by default, which would cost GNOME Terminal the document-symbols key specifically. Both are read off vendor documentation rather than observed, and this box runs Windows. A keystroke dump on Terminal.app, iTerm2 and GNOME Terminal, recording for each of F2–F10 whether the event arrives, with the macOS preference in both positions. If any is swallowed, the answer is a second spelling on the help row rather than a note in the docs.
A resume across a real directory change, on a console. Agent::resume_in_place is driven directly against temporary directories by every test it has. Start a session in one tree, /resume a session recorded in another, and read the four receipt lines on screen.

Nobody has looked at it

A cell buffer is not a console. A fully tested scrollback defect has shipped out of crates/emma/src/term/ twice, so I have stopped believing the suite about anything drawn on a screen. These close when I open a terminal and look, and not before.

Claims resting on records rather than observation

These carry tested or certified elsewhere on the site, and the marks rest on evidence in the repository rather than on somebody re-running the thing while writing the page. Worth separating out, because a test's own claim about what it catches is itself a claim, and this project has been wrong about that before.

  • Most tested chips mean the test exists and passes, and that its recorded mutation argument was read and found sound. Four pages ran fresh mutations of their own; the others did not, because six agents shared one working tree and could not safely break the code. What would settle it: run the named mutations one at a time on a disposable branch: paste the named test's red result, restore the production source, and paste its green result before starting the next. The HTML-only settlement did not authorize those Rust edits.
  • The live cache-floor certification is quoted from a status entry and a commit message. No raw request or response body survives in the owner's records. The numbers are specific and consistent, and there is no transcript behind them.
  • Judge-reliability figures, reward-hacking rates and licence findings on other projects were read through the owner's research notes rather than from the papers and repositories directly.
  • The architecture map's citations were sampled and found consistent on 2026-08-16, roughly sixty of them. The rest were not opened. Two figures taken from it turned out to be wrong when counted, which is why this row exists.

Structural, and unlikely to be settled soon

The done check grades its own homework

Ending::Done looks the same whether the goal was met or the measurement was gamed. Published chance-corrected agreement for model judges runs about 0.38 to 0.51, and measured reward-hacking rates on agentic benchmarks exceed 30%. An independent judge and a git receipt are designed in the stage-1 loops plan and its v2 revision, and neither is built.

The gate has no floor

Nothing anywhere is an unconditional deny. Three other projects keep one, and the third is MIT and copyable. The counter-argument is recorded too: a floor that fires on a legitimate command is an outage rather than a safety property. See Consent.

Compaction has never run outside its tests

Zero compacted records exist across 100 session files. The largest input any call has carried is 95,524 tokens against a 120,000 cap, so the path has never been reached in real use. What would settle it: a session long enough to cross the threshold, with the resulting record inspected.
