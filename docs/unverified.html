What is not verified

Everything believed but unchecked, gathered from the amber marks on the other pages, with the experiment that would settle each one.

This page exists so the amber does not stay scattered. Each row names what is claimed, why nobody has confirmed it, and what it would take. Rows leave when someone runs the experiment, not when someone becomes confident.

certified observed against the real API, terminal, or file on disk

Cheap to settle, worth doing first

Each of these costs minutes or a fraction of a cent, and each one currently props up something larger.

ClaimWhat would settle it
Emma's system prompt is smaller than the alternative. No measurement of the system field or tool schemas exists, and there is no emma stats. The comparison figure for Claude Code (~30,000 tokens) is widely reported and equally unmeasured here. Render one real request and count the system field and tool schemas with /v1/messages/count_tokens. Same method that bracketed the cache floors. See the goals.
Eight of the ten per-model cache floors. Only claude-opus-5 and claude-haiku-4-5 were measured against the live API. The rest are transcription from a document dated 2026-08-11, and four rows present in that document are missing from the table entirely. The same two-request canary per model, a fraction of a cent each. See Providers.
The chars / 4 token estimate. Called an under-count in both agent.rs and anthropic.rs; nobody has measured the real ratio. It now matters more, because a per-model floor of 4,096 means an under-count withholds a marker from a 16 KB prefix rather than a 2 KB one. Count a real prefix with count_tokens and compare against the estimate.
Whether the two SVG figures on each page render correctly. Every diagram in this site was validated by parsing the XML and checking coordinates against the viewBox. None was looked at. Open the pages in a browser. A stranded label or an overlapping box is invisible to arithmetic.

Needs a machine we do not have here

ClaimWhat would settle it
Anything about macOS behaviour. Eight tests failed there and have been fixed by reading, not by running. Cross-compilation covers five of eight packages; three pull a dependency needing a C toolchain this machine lacks. One #[cfg(unix)] test could not be compiled anywhere. Pull and run the suite on the Mac. Three minutes.
The unix arm of the hook fix. Windows has no SIGPIPE, which is what makes abandoning the pipe safe there. On unix, closing the read end can kill a daemon that later writes. Run the leak.cmd equivalent on Linux and check whether the daemon survives.
Chrome is never reaped on unix. The child is dropped without waiting, so every killed browser should leave a zombie. Found by reading; never observed. Note that kill -0 succeeds against a zombie, so the obvious check reports the opposite of the truth. Open and close a session on Linux or macOS, then check ps -o state= for the pid.
Whether a daemonized hook outlives Emma's own process. The environment it was tested in confounds the result: a plain unrelated parent behaved the same way, so nothing there is attributable to Emma's code. A run from a normal desktop session rather than a sandboxed one.

Nobody has looked at it

A cell buffer is not a console, and a fully tested scrollback defect has shipped from crates/emma/src/term/ twice. These are the claims that only a human with a terminal can close.

ClaimWhat would settle it
Whether the full-screen interface looks right at all. Run it and look.
Whether the approval prompts, boot warnings and "ignoring N line(s)" notices read correctly on a real terminal. Configure a rule that triggers each, then start Emma.
Ctrl-C specifically restoring the alternate screen. The mechanism is global and idempotent and reached from the panic hook and process::exit, but no Ctrl-C-specific certification is recorded. Press Ctrl-C in a real session and confirm the terminal is intact.
Whether a #[cfg(unix)] arm added for the platform sweep even compiles. Build on the Mac. It could not be compiled on this machine.

Claims resting on records rather than observation

These are marked tested or certified elsewhere on the site, and the marks are honest, but the person who wrote the page did not personally re-run the thing. The distinction matters because a test's own claim about what it catches is itself a claim.

  • Most tested chips mean the test exists and passes, and that its recorded mutation argument was read and found sound. Four pages ran fresh mutations of their own; the others did not, because six agents shared one working tree and could not safely break the code. What would settle it: run the named mutations one at a time on a clean tree.
  • The live cache-floor certification is quoted from a status entry and a commit message. No raw request or response body survives in notes/. The numbers are specific and consistent, and there is no transcript behind them.
  • Judge-reliability figures, reward-hacking rates and licence findings on other projects were read through notes/research-*.md rather than from the papers and repositories directly.
  • notes/map-architecture.md's citations were sampled and found consistent on 2026-08-16, roughly sixty of them. The rest were not opened. Two figures taken from it turned out to be wrong when counted, which is why this row exists.

Structural, and unlikely to be settled soon

The done check grades its own homework

Ending::Done looks the same whether the goal was met or the measurement was gamed. Published chance-corrected agreement for model judges runs about 0.38 to 0.51, and measured reward-hacking rates on agentic benchmarks exceed 30%. An independent judge and a git receipt are designed in notes/plan-loops-stage-1.md and notes/plan-loops-v2.md, and neither is built.

The gate has no floor

Nothing anywhere is an unconditional deny. Three other projects keep one, and the third is MIT and copyable. The counter-argument is recorded too: a floor that fires on a legitimate command is an outage rather than a safety property. See Consent.

Compaction has never run outside its tests

Zero compacted records exist across 100 session files. The largest input any call has carried is 95,524 tokens against a 120,000 cap, so the path has never been reached in real use. What would settle it: a session long enough to cross the threshold, with the resulting record inspected.
