The sidebar

The terminal Surface Frame Layout Colour Themes Vocabulary Transcript Markdown Diffs Status Sidebar Dock User tools Pages Run control Copying out

Sessions, tools, quick help, in a bordered box on the left. Pure rendering: the shell owns the state and hands it in as a State, and nothing here reads a file, takes a lock or asks the terminal a question. Every number in it was measured off the approved TUI mockup directly, and where the image and the design note disagree the file records that the image won.

How wide

crates/emma/src/term/sidebar.rs · width

/// The narrowest useful sidebar: a session name beside `Yesterday`, untouched.
pub const MIN_WIDTH: u16 = 28;

/// The widest: past this an ultrawide window is spending columns on padding.
pub const MAX_WIDTH: u16 = 40;

/// Below this many total columns the shell should collapse the sidebar
/// automatically. The *decision* is the shell's — a user who re-expanded below
/// the threshold is honoured (design §3.2) — but the number lives beside the
/// rest of the width arithmetic so the two cannot drift apart.
pub const AUTO_COLLAPSE_COLS: u16 = 100;

/// The mockup's measured proportion, in thousandths: 22.4% of the width.
const PROPORTION_MILLIS: u32 = 224;

/// How many columns the sidebar takes out of `total`. Zero when collapsed.
pub fn width(total: u16, collapsed: bool) -> u16 {
    if collapsed {
        return 0;
    }
    let measured = ((u32::from(total) * PROPORTION_MILLIS + 500) / 1000) as u16;
    // The half-of-total cap is applied after the floor on purpose: on a
    // terminal too narrow for the floor, "half of it" is the honest maximum,
    // not a licence to take 28 of 40 columns.
    measured.clamp(MIN_WIDTH, MAX_WIDTH).min(total / 2)
}
crates/emma/src/term/sidebar.rs — width and the four constants above it

The ordering of the clamp and the cap is the decision. Applying min(total / 2) after the floor means a terminal too narrow for 28 columns gets a shrinking sidebar rather than one that eats the transcript. A sidebar wider than the pane it sits beside has the two the wrong way round. The shell will usually have collapsed it by then, but a user who re-expanded is honoured, and honouring them must not mean a 28-column sidebar beside a 12-column transcript.

tested: an_expanded_sidebar_never_takes_more_than_half_the_terminal walks every width from 0 to 200 and asserts the property rather than checking a threshold. the_width_is_the_mockups_proportion_between_a_floor_and_a_ceiling pins four literals. The formula clamp(round(0.224·cols), 28, 40) is an argument in a comment until a number is written down. a_collapsed_sidebar_takes_no_columns_at_any_size holds the contract the layout depends on, including at u16::MAX.

The measured grid

Three constants carry the whole geometry, and each was read off the image at its 10px character pitch: headers two columns in from the border, list rows led by  >  or three spaces, and every right-aligned column ending two columns before the border, so the pane shares one right edge down its whole height.

The module doc records two places where the image overruled the design note. The selected row is accent text on a barely-raised near-black band (rgb 25,27,30 over a 13,15,19 ground), nothing like the approval chip's dark-on-pink. And the [+] affordance is accent pink rather than a dim note. On the second, the design's §3.2 had argued for [-] on “show the action” grounds and flagged it as an open question; the owner then ran the build against the image and reported the sidebar “not formatted like the image”, which answered it in the other direction.

What gives when a row does not fit

crates/emma/src/term/sidebar.rs · list_row

fn list_row(row: &Row, w: usize, skin: &Skin) -> Line<'static> {
    let lead_w = LEAD.min(w);
    let pad_w = RIGHT_PAD.min(w.saturating_sub(lead_w));
    let avail = w.saturating_sub(lead_w + pad_w);
    let trailing = clipped(&row.trailing, avail / 2, skin);
    let t_w = cols(&trailing);
    let name = clipped(
        &row.name,
        avail.saturating_sub(t_w + usize::from(t_w > 0)),
        skin,
    );
    let gap = avail.saturating_sub(cols(&name) + t_w);
    // The lead is ASCII by construction, so slicing it to the pane is a
    // byte-safe way to keep a one-column pane at one column.
    let lead = &(if row.selected { " > " } else { "   " })[..lead_w];
crates/emma/src/term/sidebar.rs — list_row

The name truncates and the trailing column survives. The trailing column is short and uniform; the eye scans it as a column. One row whose date is missing reads as a row with no date, while a name cut short still reads as that name. The trailing text is itself capped at half the row so a pathological value cannot invert the priority.

The gap is computed after both cuts, from measured columns, so the trailing text ends flush on the shared right edge whatever clipped undershot by. A wide glyph that would not split leaves the gap one wider, never the row one over. tested: a_cjk_trailing_column_ends_flush_with_the_shared_right_edge asserts line.width() == 26 exactly and that the line ends with the three CJK glyphs plus two spaces.

The one function that makes fit total

crates/emma/src/term/sidebar.rs · clipped

/// [`fit`], made total. `fit` itself can overrun a budget narrower than its
/// own ellipsis — the ASCII set's `...` is three columns — and a row that
/// overruns writes into the border. Below that, a run of dots is all the cut
/// mark there is room for; zero is zero.
fn clipped(text: &str, budget: usize, skin: &Skin) -> String {
    if cols(text) <= budget {
        return text.to_string();
    }
    let ellipsis = skin.glyphs.ellipsis;
    if budget < cols(ellipsis) {
        return ".".repeat(budget);
    }
    fit(text, budget, ellipsis)
}
crates/emma/src/term/sidebar.rs — clipped; crates/emma/src/term/render.rs — fit

This is the receipt for the fit defect the vocabulary page reports: the file that hit it wrote a wrapper rather than fixing the shared function, and said so. tested: a_budget_narrower_than_the_ellipsis_still_never_overruns walks budgets 0 to 10 in both glyph sets.

The property for the pane as a whole is asserted on the assembled lines rather than on the buffer. set_line clips, and a clipped overrun is exactly the invisible defect this test exists to catch. no_row_is_ever_wider_than_the_pane walks widths 0 to 44 against four hostile rows and five chrome lines. tested

Defect: the overflow row is the one line that skips clipped

fitted cuts the assembled lines to the pane's height and appends … N more rows, built with format! and no width budget. It is the only assembled line in the file that does not pass through clipped, and fitted is absent from the vector no_row_is_ever_wider_than_the_pane walks. render's set_line clips it, so the symptom is a silently cut loss-count in the one row whose job is to count the loss out loud. At the 28-column floor the text is about seventeen columns and fits; it needs a pane narrower than that, which width can produce on a terminal under 56 columns. certified: read fitted, and read the chrome vector in the guarding test, which contains header, two help_rows and two note_rows calls and no fitted.

The selected row, marked twice

A > in the lead and a full-width band from Palette::band. The band runs border to border, one style across every span including the lead and the padding, so the highlight is the full row and not a patchwork. The image shows it running border to border. With no colour it degrades to reversed video, so the selection is never carried by colour alone and the > survives everything.

tested three ways. the_selected_row_is_distinguishable_with_no_colour_at_all asserts on the cells rather than on the marker, because the marker alone could pass with the band gone. the_band_is_accent_on_a_subtle_ground_and_covers_the_full_row asserts every span carries the same style and that the band is not the chip. And the_selected_row_is_painted_exactly_as_it_was_before_the_band_moved walks the painted cells from column 1 to 28 at three fidelities against the exact colours the private table used to produce, then asserts the border kept its own background. The band is the row, not the pane.

That last test is the receipt for the move into the palette. Its doc names the risk precisely: not that the pair stops existing, which the test above would catch, but that one of its four fidelities quietly changes value on the way across. “The Ansi256 and Ansi16 rows are the important ones: those are the two the palette now computes differently.”

A header over nothing

A header over an empty section reads as a broken pane, so each one says in words what would be there. Four constants carry the sentences, and all four are ASCII so they render on the exact consoles the ASCII glyph set exists for.

crates/emma/src/term/sidebar.rs — the empty states region

note_rows wraps these rather than truncating them, and the reason is arithmetic: at the design's own 28-column floor the sessions hint is wider than the pane. A truncated explanation is half an explanation, which is the defect the sentence exists to prevent. A single word wider than the pane is still clipped with a mark, because wrapping it would invent a break. tested: an_empty_section_explains_itself_rather_than_showing_a_bare_header draws an empty State at 30 columns, flattens the rows, and asserts all four sentences arrived whole and that no ellipsis appears anywhere.

TOOL_MISSING is a sentinel with a narrow contract, and the doc says why it cannot collide: when can never mint this string and no single-key binding can be three characters, so neither a session's date nor a live key collides. list_row treats it as a whole-row signal and dims the label with it, so the row reads as switched off rather than broken, and the words carry what the dimming cannot on a colourless console. tested: an_unavailable_tool_reads_as_switched_off_not_broken checks the dimmed label's colour against Role::Dim and an available label's against Color::Reset, then re-draws the whole pane in ASCII with no colour and asserts the words are still there.

Defect: the affordance's doc denies a click that is routed

COLLAPSE_HINT's doc says “What it does not do is accept a click. The shell owns input, and until it routes a mouse press here this is a label for Ctrl-B, drawn where the mockup drew it.” The shell routes exactly that press. App::click hit-tests the SESSIONS header row and toggles the sidebar, and a_click_on_the_sessions_header_toggles_the_sidebar_and_latches asserts it end to end. A reader of this file alone would conclude the [+] is decorative. Still true on 2026-09-06, and now with a second half: hits exists and reports a rectangle for every clickable row, and nothing consults it, so the file now denies a click it routes and advertises clicks it does not. certified: the two are in the tree together at 62ab9c3 and the click test passes in the 477-test suite.

The session clock

Three public functions turn a session into a row. session_label is the first goal with whitespace collapsed, so a pasted multi-line goal stays one row, and UNTITLED_SESSION when there is none. There is no length cap: the pane already truncates to fit, and two caps drift. The doc names what it replaced: sessions have ids (sess-<ms>-<pid>), not names, and an id dressed up as a name is the filename defect this constant replaces.

session_time_ms digs the creation time out of an id, and refuses anything that does not parse. A made-up time is worse than no column. It requires the pid half to be all digits and the millisecond half to be positive. tested against four malformed ids.

pub fn when(then_ms: i64, now_ms: i64, offset_min: i32) -> String {
    let off = i64::from(offset_min) * 60_000;
    let t = then_ms.saturating_add(off);
    let n = now_ms.saturating_add(off);
    let t_day = t.div_euclid(DAY_MS);
    let n_day = n.div_euclid(DAY_MS);
    if t_day == n_day {
        let rem = t.rem_euclid(DAY_MS);
        return format!("{:02}:{:02}", rem / 3_600_000, rem % 3_600_000 / 60_000);
    }
    if n_day - t_day == 1 {
        return "Yesterday".to_string();
    }

}
crates/emma/src/term/sidebar.rs — when, civil, MONTHS

Four buckets: 12:42 for the same civil day, Yesterday, May 18 for this year, and May 2025 before that. A date from last May shown bare would be a fresher claim than the file can back. A timestamp from the future renders as the date it says, because a skewed clock is the caller's fact to keep.

offset_min is an argument and not a lookup, because std cannot ask the OS for a timezone and this module draws. The doc names the failure of passing zero: an offset of 0 renders UTC under a local-looking format, which is a quiet lie on any box west or east of Greenwich; the shell must pass the real offset, not guess. tested: the_offset_moves_the_midnight_boundary_not_just_the_clock shows two instants that are “Yesterday” in UTC and 01:30 two hours east, and a case where the offset crosses a civil year.

civil is Hinnant's civil_from_days, the standard closed form, with div_euclid/rem_euclid standing in for the paper's floored division. It is exercised against known calendar anchors in the tests rather than trusted on reputation, and the test's own doc records that the first draft of the anchor forgot 2020's leap day and the algorithm caught the fixture. That is the right direction for that to fail. tested

The calendar, which degrades whole

A month grid sits under QUICK HELP, added on 2026-09-06. It has no navigation and no state: it shows the month State::today names, with that day marked in the accent colour, and nothing else. today is an Option and None draws no calendar at all, because the shell owns the clock and the widget should not reach for one. app.rs fills it at paint time rather than storing it, so a session that runs past midnight moves its mark without a timer, and it adds the machine's local offset before converting, because a calendar that flips a day early in the evening is worse than no calendar.

The date arithmetic is Howard Hinnant's civil-from-days algorithm, written out rather than approximated, with the proleptic Gregorian leap rule spelled in full: 2024 is a leap year, 2100 is not, 2000 was. weekday carries the file's only magic number, the + 4 for 1970-01-01 having been a Thursday. A month outside 1–12 answers zero days and renders as an empty month rather than panicking on a caller's arithmetic slip. month_grid returns as many week rows as the month needs, which is four for a 28-day February beginning on a Sunday and six for a 31-day month beginning on a Friday. tested against known anchors and a full decade round-trip; deleting the % 100 and % 400 clauses fails with 2100 is divisible by 4 and is not a leap year.

The weekday row is Su Mo Tu We Th Fr Sa in ASCII, like the empty states, because this row has to survive a legacy code page. GRID_WIDTH is exactly that string's width and every week row under it is the same, so the three centred sections share one visual centre.

The section is drawn entire or not at all, and that is the difference between a calendar and a list. fitted truncates a list from the top and counts what it dropped out loud, which is right for a list: three of seven tools is still a tool list. Three of five week rows is a wrong calendar. So a pane too short, or too narrow to hold the grid, gets no calendar rather than part of one, and the append leaves one row of headroom for fitted's own overflow line so that adding the calendar can never be the thing that pushes the pane into truncation. tested — the_calendar_draws_its_month_under_quick_help and a_short_or_narrow_pane_drops_the_calendar_rather_than_half_of_it; replacing the append with if false loses AUGUST 2026 from the pane.

Where a clickable row landed

hits answers where every clickable row of the sidebar landed, for the same area render was handed, as a Hit::Session(i) or a Hit::Tool per rectangle. It is the paint's own arithmetic rather than a copy of it: both hits and render go through painted, so a row cannot be drawn in one place and hit-tested in another. A row the truncation removed, and the overflow line itself, report nothing, because a row nobody can see is a row nobody can click. A collapsed or too-small pane reports nothing at all, which is the truth about it. tested — no_reported_row_lands_outside_the_pane_or_on_the_overflow_line and a_click_on_a_drawn_tools_row_returns_that_tool; commenting out the Hit::Tool slot fails with no rect recorded for Shell.

unverified as a behaviour anybody can see, because nothing calls it. App::click does not consult hits yet, so a pointer on a TOOLS row still does nothing and the intended guarantee — that clicking a TOOLS row fires exactly the chord its Alt key fires — has no test that could fail. That dispatch is a later package. What would settle it: the call site in App::click, plus a test that drives a click and an Alt chord through the same path and asserts they land on the same action.

Assembly, and the ASCII fallback

render refuses outright when collapsed or under three cells either way. The pane is absent, not clipped. Otherwise it draws one bordered block, calls content to build every line at the inner width, hands them to fitted for the height, and writes them row by row.

content is four sections now with section_break between them, the calendar being the fourth: a blank row, a thin rule inset one column, a blank row. Those blanks are the sidebar's internal layout, which is the exception the spacing rule already holds for welcome.rs. A pane too narrow for an inset rule gets a blank row instead, because one stranded glyph does not read as a rule and the inset would overrun.

header right-aligns the affordance and drops it whole when it will not fit. Half of [+] is not a control; it is debris. Its right pad goes first, since one column off the border still reads as the control. help_row gives every key a shared column so the descriptions align, capped at half the pane so a long key cannot push them all off the edge, and both halves are dim. The two columns are told apart by alignment, which no colour level takes away.

tested: the_ascii_fallback_is_pure_ascii_and_still_reads_as_structure draws the whole pane at Level::None with the ASCII glyph set and asserts every cell is ASCII, the headers survived, a rule survived and the selection marker survived. a_zero_or_tiny_area_is_survived renders at five degenerate sizes.
