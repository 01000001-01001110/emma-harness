What a model will take

Providers & models The boundary Content blocks The turn back Model limits Caching The cache floor Retry Credentials The claude engine

Two of the values in a request are properties of the model rather than of the request, and getting either wrong is an HTTP 400 before a token is generated. Both were single constants until a user could choose a model, at which point the first call on the wrong choice failed for a reason nobody had asked about. A hundred lines of table and eleven lines of clamping is the whole answer.

One struct, one lookup, two clamps

crates/llm/src/models.rs · struct Limits

/// What one model accepts.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Limits {
    /// The largest `max_tokens` this model accepts. Above it, HTTP 400.
    pub max_tokens: u32,
    /// Effort levels this model implements, ascending. **Not a ceiling** — a
    /// slice, because the set has holes: Opus 4.6 supports `max` but not
    /// `xhigh`, which arrived one model later. A ceiling would send `xhigh`
    /// there and earn the 400 this module exists to prevent.
    pub efforts: &'static [Effort],
}
crates/llm/src/models.rs — Limits

The shape is not arbitrary. GET /v1/models reports both of these per model, max_tokens as a field and the levels under capabilities.effort.<level>.supported, so Limits is what that response parses into and a later discovery stage can replace the lookup without touching the clamping. That stage is not built.

The set is a slice because the ladder has holes

There are two effort sets in the file and each is used by several rows:

crates/llm/src/models.rs · ALL_FIVE, NO_XHIGH

const ALL_FIVE: &[Effort] = &[
    Effort::Low,
    Effort::Medium,
    Effort::High,
    Effort::XHigh,
    Effort::Max,
];

/// `xhigh` arrived with Opus 4.7; the 4.6 generation has `max` without it.
const NO_XHIGH: &[Effort] = &[Effort::Low, Effort::Medium, Effort::High, Effort::Max];
crates/llm/src/models.rs — ALL_FIVE, NO_XHIGH

A third set appears inline on two rows and is written &[]: Sonnet 4.5 and Haiku 4.5 predate the effort parameter and reject it outright, so the empty slice is what stops Emma sending the field at all. A ceiling comparison would look at "Opus 4.6 supports max" and conclude xhigh is fine, which is a 400.

Longest prefix wins

crates/llm/src/models.rs · limits

/// What `model` accepts, or [`UNKNOWN`] if this table has never heard of it.
pub fn limits(model: &str) -> Limits {
    TABLE
        .iter()
        .filter(|(id, _)| model.starts_with(id))
        // Longest match wins, so `claude-opus-4-8` never resolves through a
        // shorter row that happens to prefix it.
        .max_by_key(|(id, _)| id.len())
        .map(|(_, l)| *l)
        .unwrap_or(UNKNOWN)
}
crates/llm/src/models.rs — limits, TABLE

Prefix rather than equality, because the API accepts both the alias and the dated spelling and a user pasting from the console gets the dated one. claude-haiku-4-5-20251001 resolves to the same row as claude-haiku-4-5, which a_dated_snapshot_resolves_to_its_alias asserts, alongside the other half: claude-opus-4-5-20251101 resolves to UNKNOWN, because no row for 4.5 exists. tested

max_by_key is the tie-break, and no_row_shadows_another asserts the property that makes it unnecessary today: no id in the table prefixes another. Its comment says why the property is asserted rather than the tie-break: a row like claude-opus added later would silently swallow every Opus, and no other test in the file would notice. tested

An unknown model guesses low

crates/llm/src/models.rs · UNKNOWN

/// What we send to a model this table has never heard of.
///
/// **A user can name any model string, including one released after this file
/// was written, and that case is the whole design.** Three answers were
/// available and the asymmetry between their failures picks the winner:
///
/// - *Assume the model is as capable as the newest one we know.* Wrong in the
///   one direction that cannot degrade gracefully: too high a `max_tokens`, or
///   an effort level the model does not implement, is an HTTP 400 on the first
///   call — no answer, and an error naming a value the user never set.
/// - *Refuse to run against an unknown model.* Turns every new model release
///   into a bug in Emma, and makes the table a gate rather than a hint. The
///   user who typed the id is likelier to be right about it than we are.
/// - **A conservative floor.** Too *low* a `max_tokens` truncates a long
///   answer, and omitting `effort` gets the provider's own default. Both are
///   degraded, both still produce a turn, and both are fixed by adding one row
///   below. That asymmetry — a low value works everywhere, a high value fails
///   everywhere it is wrong — is the whole argument.
pub const UNKNOWN: Limits = Limits {
    max_tokens: 8_192,
    efforts: &[],
};
crates/llm/src/models.rs — UNKNOWN

8,192 is the smallest output ceiling any Anthropic model has shipped with, so no known model rejects it, and the empty effort set means no output_config is sent, which every model accepts including the two that reject the field. The cost is stated where the constant lives: a user on a brand-new Opus gets 8,192 tokens and default effort until somebody edits the file.

This fallback guesses low. The cache floor table guesses high, from the same reasoning about which failure is recoverable, and the two directions are why those tables are not one table.

The two clamps

crates/llm/src/models.rs · Limits::clamp_max_tokens

/// The caller's ceiling, lowered to the model's if the model's is lower.
///
/// Only ever downward. A request asking for 32,000 on a model that caps at
/// 128,000 still sends 32,000 — the ask is a budget as well as a limit, and
/// raising it would spend the user's money on their behalf.
pub fn clamp_max_tokens(&self, requested: u32) -> u32 {
    requested.min(self.max_tokens)
}
crates/llm/src/models.rs — clamp_max_tokens

Two tests hold it from both sides. a_lower_ceiling_is_never_handed_the_full_ask loops every row and asserts nothing comes back above what that model accepts, then pins three cases by hand: 32,000 stays on Haiku, 200,000 becomes 64,000 on Haiku, and an invented id gets 8,192. the_ask_is_never_raised_to_the_ceiling pins the other direction on Opus 5. tested

crates/llm/src/models.rs · Limits::clamp_effort

/// The best level this model supports that is no higher than `requested`,
/// or `None` when there is none.
///
/// `None` means *send no `output_config` at all* rather than "send low",
/// and it covers two different situations on purpose: a model with no
/// effort parameter, and a request whose asked-for level sits below
/// everything the model implements. Both want the same thing — the
/// provider's own default — and neither wants a level the caller did not
/// ask for. Clamping upward to "the nearest supported" would send a model
/// harder than the caller requested, which on a `Low` request for a cheap
/// subagent is exactly the bill they were avoiding.
pub fn clamp_effort(&self, requested: Effort) -> Option<Effort> {
    self.efforts
        .iter()
        .copied()
        .filter(|e| e.rank() <= requested.rank())
        .max_by_key(|e| e.rank())
}
crates/llm/src/models.rs — clamp_effort

Four tests cover the clamp. a_model_without_xhigh_is_never_sent_xhigh loops the table asserting the chosen level is both supported and no higher than the ask, then pins 4.6 landing on high and Opus 5 on xhigh. a_model_with_no_effort_parameter_gets_none_of_it pins None on Haiku for two different asks and on Sonnet 4.5 for Max. a_request_below_every_supported_level_sends_no_effort builds a contrived Limits whose lowest level is High and asserts a Low ask gets None, which no shipped model exercises. an_unknown_model_gets_the_conservative_floor_not_the_newest_row pins both halves of UNKNOWN. tested

Three more live in anthropic.rs and assert the same table reaches the socket: a_model_with_a_lower_ceiling_is_never_sent_the_full_ask, a_model_without_xhigh_is_never_sent_xhigh and a_model_with_no_effort_parameter_is_sent_no_output_config, each reading the recorded request body from a loopback stub. The unit tests pin the table; those pin that the table is what the socket sees, which a wrong wiring would break while table tests still passed. tested

Asking a provider what it has, instead of remembering

The table above was transcribed by hand on a date, and its own doc names what should replace it: an endpoint that reports the same facts. crates/llm/src/roster.rs is that seam, built against OpenRouter's GET {base}/models. It answers three questions the table guesses at, which ids exist, which cost nothing, and what each will accept, and it is library-only. Nothing in the binary calls it today, so no part of Emma's behaviour changes because it is there. certified as uncalled: grep -rn "roster::" crates tools outside the module and the docs generator returns one line, the pub use in crates/llm/src/lib.rs that re-exports its three types. Nothing calls fetch.

crates/llm/src/roster.rs — module doc, fetch, OPENROUTER_BASE_URL

The trap it records is worth more than the endpoint. Measured against the live roster on 2026-08-30, 396 models: filtering on the id suffix :free returns 18, and filtering on pricing.prompt and pricing.completion both being zero returns 21, of which three cannot run a turn of Emma's loop because they do not list tools in supported_parameters. Two are music models and one is a content-safety classifier, and handing any of them a tool-calling request is a 400 on the first call. Price-zero and tool support and text output together returns 18 usable models, and it is a different 18 from the suffix's. The two filters agree on the count and disagree on the set, so a test asserting 18 would pass over either. The tests in the file assert on membership and never on a length. observed: one live capture on 2026-08-30, recorded in the module doc. The transcript is not in the tree, so the numbers cannot be re-derived without another fetch.

crates/llm/src/roster.rs — module doc, ModelInfo::usable, Roster::free

Two admissions travel with it. Zero prompt and completion price is not the same as a free call: one of those music models bills whole songs on a dimension that is neither field, so a future text model billed per request would read as free here. And a free model is rate-limited hard. Two of four live calls that day came back 429 within a minute, per model. A roster entry says a model exists and costs nothing, never that it will answer. Roster::fetched_at_ms is not optional for the same reason a compiled-in sample value is a defect: the price reported is the price at fetch time, so Roster::age_ms exists to make "when" arithmetic rather than a guess. A fetch failure is a RosterError the caller renders as a notice, never a boot failure and never a panic. certified: fetch returns Result<Roster, RosterError> and the file contains no panic! or unwrap on the response path.

crates/llm/src/roster.rs — Roster::fetched_at_ms, Roster::age_ms, RosterError

Every field is read out of a Value by hand rather than through a derived Deserialize. That is the strict-decoder scar from typed content blocks applied one file over: an entry carrying a key this parser has never seen survives whole, and an entry that cannot be read costs that entry rather than the roster. unverified Whether a genuinely malformed OpenRouter entry appears in practice is not known here. Capturing a live response and feeding it to Roster::parse with one entry corrupted would show whether the rest survives, and that test is not in the file today.

Coverage

models.rs has three functions and all three are quoted above: limits, clamp_max_tokens and clamp_effort. Its four constants are UNKNOWN, ALL_FIVE, NO_XHIGH and TABLE, and every row of TABLE is in the table above. TABLE is pub(crate) for one reason, stated in a comment beside it: so anthropic.rs can check its floor table names the same models. certified as complete by count: grep -c 'fn ' crates/llm/src/models.rs against the test module's own boundary, or read the 349-line file.

Effort::rank and Effort::as_str live in lib.rs and are covered on the boundary. Eight tests guard this module and all eight ran green on 2026-08-16 in the 72 cargo test -p emma-llm reports. certified
