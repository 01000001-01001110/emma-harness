The agent loop

One turn, end to end

The agent loop One turn Failure The memo Endings The kick Budgets Done Seams

Three guards, a request built from four parts, one model call, and then a fork: either the turn asked for tools, or it did not. What follows is one iteration of Agent::run_goal, from the guard at the top to the message list at the bottom.

crates/emma/src/agent.rs — Agent::run_goal, Agent::call_model

The three guards, in this order

Every iteration opens with the same three tests. They come before anything that costs money, and the order among them decides which ending a run gets when two are true at once. 

// crates/emma/src/agent.rs — Agent::run_goal, top of the loop
let ending = loop {
    if self.s.interrupt.tripped() {
        break Ending::Interrupted;
    }
    if started.elapsed() > self.s.budgets.wall_clock {
        break Ending::Deadline;
    }
    if iterations >= self.s.budgets.max_iterations {
        break Ending::Iterations;
    }
    // Between the budget tests and the request, so the request that
    // goes out is the compacted one. `last_input` is what the provider
    // said the previous request weighed; on the first call of a goal it
    // is whatever the previous goal ended at, which is the right number
    // — the conversation has not shrunk since.
    self.compact_if_needed(self.last_input, "the request passed the context limit");

Ctrl-C is read first, so if you interrupt a run that was also out of time you are told interrupted, not deadline. iterations >= max_iterations is tested before the call, which makes the iteration count a ceiling and not a tripwire. The token budget below is tested after, and the two are worded differently to you for that reason. See Budgets. certified by reading the function: these four lines are the whole of what runs before Request is built.

What a request carries

// crates/emma/src/agent.rs — Agent::run_goal
let request = Request {
    // The harness prompt, then the framing that is true of every
    // goal. It goes here rather than into the opening message
    // because a preamble on the user's words is an instruction
    // they did not write — and because identical bytes on every
    // call belong in the cached prefix, not in `query`.
    instructions: format!(
        "{}{}",
        self.s.instructions,
        goal::standing_contract(self.s.done)
    ),
    tools: tool_defs.clone(),
    history: self.conversation(),
    query: query.clone(),
    max_tokens: 32_000,
    effort: emma_llm::Effort::XHigh,
    caching: self.s.caching,
};

Request::new assembles four pieces. instructions is the harness prompt with goal::standing_contract(done) appended, so the completion rule the model is told about comes from the DoneCheck actually in force rather than from a fixed string. tools is Registry::wire_definitions(), hoisted out of the loop and cloned per iteration. history is self.conversation(), every finished goal flattened in order. query is the goal in flight: its opening, the assistant turns so far, and the tool results that answered them.

crates/emma/src/agent.rs — Agent::run_goal, Agent::conversation; crates/emma/src/goal.rs — standing_contract

The split between history and query is not recorded in the session file. The fold returns one flat list, and the loop reconstructs the boundary from what it knows: chapters are goals that have finished, query is the goal that has not. A resumed conversation therefore arrives whole inside query, which costs a cache breakpoint that would otherwise have been byte-stable for the rest of the session.

The model call, and the two things racing it

// crates/emma/src/agent.rs
/// One model call, with streaming and Ctrl-C. `Ok(None)` is an interrupt.
async fn call_model(&self, request: Request) -> Result<Option<AssistantTurn>, LlmError> {
    let (tx, mut rx) = mpsc::channel::<Event>(64);
    let mut send = Box::pin(self.s.provider.send(request, self.s.mode, Some(tx)));
    let mut streamed = false;
    let mut closed = false;

    let turn = loop {
        tokio::select! {
            biased;
            _ = self.s.interrupt.wait() => return Ok(None),
            // Disabled once the channel closes, which happens when `send`
            // drops its sender. Without the guard this branch is
            // permanently ready and starves the one below it.
            ev = rx.recv(), if !closed => match ev {
                Some(ev) => { streamed |= self.on_event(ev); }
                None => closed = true,
            },
            turn = &mut send => break turn?,
        }
    };
    while let Ok(ev) = rx.try_recv() {
        streamed |= self.on_event(ev);
    }
    if streamed {
        self.s.term.end_of_text();
    } else {
        self.s.term.text(&turn.text());
    }
    Ok(Some(turn))
}

biased; makes the interrupt branch win a tie rather than tokio picking at random, so a Ctrl-C that lands in the same wakeup as a text delta ends the call. The if !closed guard on the receive branch is the fix for a starvation bug: a closed channel returns None immediately and forever, so an unguarded branch is always ready and the future that actually finishes the call never gets polled. After the loop breaks, try_recv drains whatever the sender queued before it dropped, because those deltas are already paid for.

crates/emma/src/agent.rs — Agent::call_model

The streamed flag decides who draws the text. If any TextDelta reached the terminal the loop only closes the line; if none did, the whole turn is printed at once. That covers a provider or a mode that returns a complete turn with no stream, and it is why the same text is never drawn twice. certified for the non-streaming path: tests/support/mod.rs's Fake provider ignores the event channel (_events: Option<mpsc::Sender<Event>>), so every cargo test -p emma --test loop run exercises streamed == false and draws the turn once via term.text. On 2026-09-02 cargo test -p emma --test loop a_conversational_turn_is_answered_not_stalled printed test result: ok. 1 passed; 0 failed.

// crates/emma/src/agent.rs
/// Returns whether anything was written to the assistant's line.
fn on_event(&self, ev: Event) -> bool {
    match ev {
        Event::TextDelta(text) => {
            self.s.term.delta(&text);
            true
        }
        Event::ToolUseStarted { .. } => false,
        Event::Retrying { attempt, max_attempts, delay, reason } => {
            // A retry the user cannot see is indistinguishable from a hang.
            self.s.term.warn(&format!(
                "retrying ({attempt}/{max_attempts}) in {}ms: {reason}",
                delay.as_millis()
            ));
            false
        }
    }
}

Only TextDelta returns true, because only it writes to the assistant's line. A retry warning goes to its own line and a ToolUseStarted event draws nothing here at all; the tool banner is drawn later, by run_tool_call, once the arguments are known.

What happens to a turn that arrives

Three matches on the call's result, and only one of them continues. An Ok(None) is the interrupt and ends the goal. An error goes to Ending::Provider unless recover_from_a_model_change claims it. That is the loop's one retry and is covered under Seams. 

// crates/emma/src/agent.rs — Agent::run_goal
let turn = match self.call_model(request).await {
    Ok(Some(turn)) => turn,
    Ok(None) => break Ending::Interrupted,
    // The one retry in this loop, and it is not a retry of a
    // transport failure — `emma-llm` owns those. It is the
    // conversation being made acceptable to a model the user
    // changed to mid-session. Nothing was spent: the request was
    // rejected before generation, so `iterations` does not move.
    Err(e) if self.recover_from_a_model_change(&e) => continue,
    Err(e) => break Ending::Provider(e.to_string()),
};
// The new model has accepted the conversation, so there is nothing
// left to recover from.
self.changed_from = None;
iterations += 1;

Then the accounting, in a fixed order: charge the meter, write the model_call record, store last_input, update the status line, write the assistant record, hold the turn, and only then test the token budget. Recording before testing is what makes an aborted run cost what it spent rather than nothing. 

// crates/emma/src/agent.rs — Agent::run_goal
let tokens = self.s.spend.add(cost_tokens(&turn.usage));
self.s.log.append("model_call", json!({ /* four provider fields,

self.last_input = Some(turn.usage.billable_input_tokens());

let text = turn.text();

last_text only moves when the turn had non-blank text, so a turn that was nothing but tool calls does not wipe the last thing the model actually said. That string is what Outcome::text carries and what a compacted chapter keeps as its answer.

The assistant turn is echoed back exactly as it arrived. pending_turn holds turn.content, the provider's own blocks, thinking blocks and signatures included. Nothing rebuilds a turn from its text plus its tool calls, because a re-derived signature is rejected on the next call, which puts the symptom one step away from the change that caused it. tested crates/emma/tests/loop.rs the_assistant_turn_is_echoed_back_exactly_as_it_arrived asserts the intact tool_use block is in the message that was sent back, not merely somewhere in the transcript. The test file's header records that every test in it was mutation-checked by its author; that is not a mutation watched during this write-up.

Placing the turn

A turn is held rather than pushed because where it goes depends on what happens after it: beside its tool results, beside a kick, or on the end of the conversation once the loop breaks. A turn whose tools were never run goes nowhere at all. 

// crates/emma/src/agent.rs
/// [`session::place_turn`] against a held turn, taking it only if it was placed.
///
/// A turn that could not be placed is dropped, and dropping it here rather than
/// leaving it held is what stops it being offered again at the end of the loop.
fn place(
    query: &mut Vec<Message>,
    pending: &mut Option<Vec<ContentBlock>>,
    results: Vec<ToolResult>,
) -> bool {
    match pending.take() {
        Some(content) => crate::session::place_turn(query, content, results),
        None => false,
    }
}

pending.take() is the whole of the drop. The rule about whether a turn may be placed lives one level down, in session::place_turn, which refuses a pair the API would reject: an assistant turn carrying a tool_use that no tool_result answers, or results answering nothing. It is one function rather than one per caller because the session fold needs the same ruling, and two copies of it would be a resumed conversation that differs from the one that was sent in the cases neither is tested on.

crates/emma/src/agent.rs — place; crates/emma/src/session.rs — place_turn

place is called from three sites: after a kick with no results, after a round of tool calls with their results, and once more after the loop breaks. That last call is what puts a final answer into the conversation, so a follow-up question can be asked about it. It is also the Ending::Tokens case, where the budget fired between receiving a turn and dispatching its tools, and the held turn is discarded rather than left unanswered.

Opening the query, and closing the goal before it

Two functions exist to stop two user turns from adjoining, which the API rejects. open_query handles the resume case and close_previous_goal handles the goal-after-an-abandoned-goal case. 

// crates/emma/src/agent.rs
fn open_query(mut restored: Vec<Message>, opening: String) -> Vec<Message> {
    match restored.last_mut() {
        Some(last) if last.role == Role::User => match &mut last.content {
            Content::Text(text) => {
                text.push_str("\n\n");
                text.push_str(&opening);
            }
            Content::Blocks(blocks) => blocks.push(ContentBlock::text(opening)),
        },
        _ => restored.push(Message::user(opening)),
    }
    restored
}

A fold ends wherever the interrupted run stopped, and that is usually a user turn: the tool results of the last complete round, or a kick that answered a turn calling nothing. So the new goal's opening joins the last message instead of following it, as a text block after the result blocks when the content is an array and as concatenated text when it is not. Nothing is dropped to make room. Dropping the trailing results would leave the tool_use above them unanswered. That is the other rejection the API makes. With nothing restored (every ordinary run), the match falls to the last arm and this is vec![Message::user(opening)].

// crates/emma/src/agent.rs
fn close_previous_goal(&mut self) {
    let Some(ending) = self.last_ending.take() else {
        return;
    };
    let Some(chapter) = self.chapters.last_mut() else {
        return;
    };
    if chapter.messages.last().map(|m| m.role) == Some(Role::User) {
        chapter
            .messages
            .push(Message::assistant_text(ended_note(ending)));
    }
}

pub(crate) fn ended_note(ending: &str) -> String {
    format!("[The previous goal stopped before it was finished: {ending}.]")
}

Three conditions, all of which must hold: there was a previous goal, it left a chapter, and that chapter ends on a user turn. take() on last_ending means the note is inserted at most once. The sentence is composed by ended_note rather than written inline because session::Fold::close_goal composes the same sentence from the recorded ending, and two spellings would make a resumed conversation differ from the one that was sent by one message.

crates/emma/src/agent.rs — Agent::close_previous_goal, ended_note; crates/emma/src/session.rs

A model reading an abandoned goal as a completed one is the more expensive of the two failures this prevents, and it is the reason the note states the ending rather than being an empty spacer.

The goal joins the conversation whatever the ending. A run that hit its token budget still happened, and the next goal in the session must not be told a story in which it did not. What joins is the goal's own message list rather than a summary of it; the summary is what compaction makes later, out of the goal and answer fields, and only if it has to.

crates/emma/src/agent.rs — Agent::run_goal, Chapter

A Chapter is a whole goal rather than a slice of messages because compaction works in whole goals: cutting anywhere else risks separating a tool_use from the result that answers it. Agent::conversation is the flattening, and Agent::estimated_context is that flattening measured by estimate.

Construction, and the thing the constructor refuses to touch

Agent::new takes a Setup and initialises six fields to empty. It used to call term.set_budgets(...) as well, on the argument that this is where the budgets already were. That broke as soon as a second Agent existed: the status meters belong to the process, and constructing a nested agent re-pointed the parent's context and token meters at a sub-run's caps for the rest of the run. main sets them once now, and Term::subordinate is what keeps a nested run from moving them.

crates/emma/src/agent.rs — Agent::new

Agent::resuming is a builder method rather than a Setup field, because every other caller would have written resumed: None, and because a Resumed is produced by a fallible read the caller has to have done before it can construct Setup at all. What a resume carries is on The memo and Budgets; it is consumed by the first run_goal and never again, because it describes one interrupted goal and a second goal typed at the prompt is a new goal with its own budget.
