The agent loop

How a goal ends

The agent loop One turn Failure The memo Endings The kick Budgets Done Seams

Nine endings, and four of them are decided by a ladder that runs when a turn contains no tool calls. The rungs are order-dependent, and each is written to be true only given that the ones above it already answered no.

crates/emma/src/agent.rs — Ending, Agent::run_goal

The ladder

// crates/emma/src/agent.rs — Agent::run_goal
if turn.tool_calls().is_empty() {
    // The model stopped. Everything from here to `continue` is the
    // goal being held rather than a conversation ending.
    let why = match self.s.done.verdict(goal, &text).await {
        Done::Yes => break Ending::Done,
        Done::No(why) => why,
    };
    // The model has answered the kick without doing anything. A
    // third attempt is the loop arguing with itself.
    if tool_calls_since_kick == 0 && kicked {
        break Ending::Stalled;
    }
    // Nothing was ever attempted. There is no work in flight to
    // nudge back into motion, so this is a reply, and the run ends
    // reporting it rather than spending a model call to discover
    // that nobody was working.
    //
    // The order of these three is the whole rule and none of it is
    // spare. After the verdict, so a first turn that claims
    // completion is still `Done`. After the stall rule, so a model
    // that was already nudged is judged by the rule written about
    // being nudged. Which leaves this one meaning exactly what it
    // says: no tool has been called in this goal, and nothing has
    // been asked of the model that it has not already answered.
    if !worked {
        break Ending::Answered;
    }
    if kicks >= self.s.budgets.max_kicks {
        break Ending::KicksExhausted;
    }
    kicks += 1;
    kicked = true;
    tool_calls_since_kick = 0;
    // `text` is the composed message, not a second copy of `why`:
    // `why` is the reason for a human reading the file, and the
    // message is what the model was sent — the two differ by the
    // restated goal and the list of what has already failed, and it
    // is the message the fold has to put back.
    let kick_text = goal::kick(goal, &why, &tail(&failed_ever, 5));
    self.s.log.append(
        "kick",
        json!({ "turn_id": turn_id, "n": kicks, "why": why, "text": kick_text }),
    );
    self.s.term.kick(kicks, self.s.budgets.max_kicks);
    // The provider's own blocks, verbatim. Never rebuilt from
    // `text` plus the tool calls.
    place(&mut query, &mut pending_turn, Vec::new());
    query.push(Message::user(kick_text));
    continue;
}

What each rung is protecting

Verdict first, so a model that claims completion on its first breath is Done and not something else. Put the answered rule above it and every one-shot goal, the ones where nothing needed changing, collapses into an ending nothing downstream treats as success. tested a_first_turn_that_claims_completion_is_still_done.

Stall second, so a model that has already been nudged is judged by the rule written about being nudged. The condition is no tool call since the last kick, and a kick has been sent in this run. Note kicked rather than kicks > 0: the kick count comes back across a resume, but a resumed run's last nudge was answered by a human typing a new goal, so reading the budget here would end every resumed run on its first stop and report it as a stall. tested a_model_that_abandons_started_work_twice_is_believed asserts kicks == 1, which proves the stall rule fired rather than the count running out.

Answered third, which leaves it meaning what it says: no tool has been attempted in this goal, and nothing has been asked of the model that it has not already answered. The ending exists because the owner typed hello and was told his exchange had stalled. The distinguishing signal is tool use rather than wording, and worked is per goal rather than per turn, so one tool call anywhere earlier makes every later stop a stall however conversational the sentence it stopped on. tested by a_conversational_turn_is_answered_not_stalled, and the narrowness has its own test, one_tool_call_earlier_in_the_goal_is_enough_to_make_a_stop_a_stall, because the obvious simplification, asking whether this turn used a tool, passes every other test in the file while deleting the stall rule.

Kick budget last. Reaching it means the goal was genuinely being worked and the nudges ran out. Ending::KicksExhausted's message adds the sentence that matters after an unfinished run: what was changed is on disk, and nothing was rolled back. certified that these four are the whole ladder and are in this order: the block quoted above is the entire if turn.tool_calls().is_empty() branch, from the verdict call to the continue.

crates/emma/src/agent.rs — Agent::run_goal 
// crates/emma/src/agent.rs — Agent::run_goal, the declarations
// Whether this goal has ever attempted work. It is what separates a
// conversational turn from a stall — see [`Ending::Answered`] — and it
// is deliberately per *goal* rather than per turn: a model that ran a
// command and then stopped talking has abandoned something, however
// chatty the sentence it stopped on.
//
// A resumed run starts as though it had, because a resume only ever
// continues a goal that was already in flight. The error this refuses
// to make is the asymmetric one: mistaking a stall for an answer ends a
// real goal early and silently, while mistaking an answer for a stall
// costs one model call and is what the loop did before today.
let mut worked = resuming_a_goal_in_flight;

worked is set on the attempt rather than on success, so a model whose only call was denied at the approval prompt is still mid-task and the stop that follows is a stall to be nudged rather than a greeting. The asymmetry named in the comment is the reason the seeding goes this way: calling a stall an answer ends a real goal silently, while calling an answer a stall costs one model call.

crates/emma/src/agent.rs — Ending, Ending::as_str

as_str returns a &'static str and drops the payload of Provider, which is why the goal_finished record carries a separate detail field holding the message for that one variant. The short string is what the session fold matches on and what ended_note interpolates, so changing one of these nine strings changes what a resumed conversation says about a previous goal.

Every ending names the limit that fired

// crates/emma/src/agent.rs
/// What the user is told. Named the limit that fired, because "I stopped"
/// without a reason is indistinguishable from a crash.
pub fn message(&self, b: &Budgets) -> String {
    match self {
        Self::Done => "goal complete".into(),
        Self::KicksExhausted => format!(
            "stopped: the goal was not confirmed done after {} nudges. What was changed is \
             on disk; nothing was rolled back.",
            b.max_kicks
        ),
        Self::Stalled => "stopped: the model stopped twice without using a tool, so it has \
             nothing further to do here."
            .into(),
        // Deliberately not phrased as a stop. Nothing went wrong, nothing
        // was abandoned, and the answer itself is already on the screen
        // above this line — so this says what kind of turn it was and
        // claims nothing else.
        Self::Answered => {
            "answered — no tools were needed, so there was no goal to hold.".into()
        }
        Self::Iterations => format!("stopped: hit the {} model-call limit.", b.max_iterations),
        // Deliberately not "hit the N token budget", which is what it used
        // to say and which reads as "stopped at N". It does not stop at N.
        // See `Budgets::max_tokens`: the check runs after the call, so the
        // spend reported beside this sentence is larger — by 79,565 on the
        // run that prompted the rewording — and a sentence that implies
        // otherwise contradicts the number printed next to it.
        Self::Tokens => format!(
            "stopped: went past the {} token budget, which counts cached input at what it \
             costs rather than at its size, and is checked after each call — so the call \
             that crossed it is included in the total below.",
            b.max_tokens
        ),
        Self::Deadline => format!("stopped: hit the {}s time limit.", b.wall_clock.as_secs()),
        Self::Interrupted => "interrupted. The partial turn is in the session log.".into(),
        Self::Provider(e) => format!("stopped: {e}"),
    }
}

Four of the nine interpolate a number from Budgets, which is what the test asserts. tested every_ending_says_which_limit_fired checks that KicksExhausted, Iterations, Tokens and Deadline each contain an ASCII digit. That is a weak assertion and it catches the real regression, which is a tidy-up replacing a number with prose.

crates/emma/src/agent.rs — Ending::message and its unit test

Iterations and Tokens are worded differently on purpose and a second test guards the difference. tested the_token_budget_is_described_as_the_tripwire_it_is asserts the tokens message contains the word "after", and separately that the iterations message still contains "limit", so a tidy-up that unified the two would make one of them false. Why the token budget is a tripwire at all is on Budgets.

What the caller gets, and what the file records

place(&mut query, &mut pending_turn, Vec::new());
self.s.term.goal_ended();

let outcome = Outcome {
    ending,
    text: last_text,
    tokens: self.s.spend.get(),
    iterations,
    kicks,
};
self.s.log.append(
    "goal_finished",
    json!({
        "ending": outcome.ending.as_str(),
        "detail": match &outcome.ending { Ending::Provider(e) => Some(e.clone()), _ => None },
        "tokens": outcome.tokens,
        "iterations": outcome.iterations,
        "kicks": outcome.kicks,
        "elapsed_ms": started.elapsed().as_millis() as u64,
    }),
);

The final place runs for every ending. For Done, Answered, Stalled and KicksExhausted that puts the model's last message into the conversation, which is what makes a follow-up question possible at all: the answer has to be in the conversation and not merely in the Outcome. For Tokens the held turn is one whose tools were never run, and place_turn drops it. Outcome::text is verbatim, completion marker included, because the screen is where the marker is removed and this is the record. See Done.

crates/emma/src/agent.rs — Agent::run_goal, Outcome

A goal joins the conversation whatever the ending, so the next goal in the session is not told a story in which it did not happen. If the abandoned goal's last message was a user turn, trailing tool results or an unanswered kick, the next goal's opening would make two user turns adjoin, which the API rejects, so close_previous_goal inserts [The previous goal stopped before it was finished: <ending>.].
