crates/emma/src/term/theme.rs

Themes as data on disk

The terminal Surface Frame Layout Colour Themes Vocabulary Transcript Markdown Diffs Status Sidebar Dock User tools

A theme is a JSON file of numbers, and this module is where it stops being one. It resolves at load into fixed-size Copy data, refuses two things a stranger must not be able to set, and never returns a Result: a bad hex costs one role, an unreadable file costs the theme, and Emma says so in words rather than declining to start.

Resolved once, into data that cannot fail

Everything below the loader is plain data: three fidelities per role, two pairs, no allocation anywhere in it.

/// A theme, resolved. Fixed-size and `Copy` — see the module doc for why that
/// is a constraint rather than a preference.

pub struct Theme {

    /// and nothing else may assume it.
    roles: [Entry; 8],
    /// `[foreground, background]`. Both halves are always present, which is the
    /// whole reason a background is expressible at all.
    chip: [Entry; 2],
    selection: [Entry; 2],
}
crates/emma/src/term/theme.rs — Entry, Theme, slot

slot(role) is a const fn mapping the eight roles onto array indices, and the field comment insists nothing else may assume the order. Six accessors read it: rgb, indexed, ansi16, pair, and the private halves/halves_mut. Pair is a two-variant enum rather than an open-ended map, and the doc gives the reason: “a third one has to be added here, and needing an entry in this enum is a useful speed bump on ‘just paint a background’.”

BUILTIN is pub because it is the answer to “what does Emma look like out of the box”, and it is the only place in the module where a colour is written down. Its Role::Text row carries values nothing can reach, and the comment says so rather than leaving a stranger to wonder:

        // is total, and so an edit reaching for a foreground hex has to walk
        // past the reason.

Declare one, derive one, inherit one

A role declares its hex. The 256-colour index is derived from it. The 16-colour name is inherited from the built-in role unless the author declares it. The asymmetry is measured rather than aesthetic, and the module doc states both halves: derivation reproduces five of the seven current indices exactly, and at sixteen colours the same arithmetic makes Accent LightRed, “which is how every goal line comes to read as an error. Intent cannot be computed, so it is either declared by somebody who knows or kept from the role that already had it right.”

crates/emma/src/term/theme.rs · the tail of role_entry

    Some(Entry {
        rgb,
        idx: declared_idx.unwrap_or_else(|| derive_index(rgb)),
        // Inherited, never derived. Distance at sixteen colours is exactly how
        // an accent becomes the colour that means failure.
        ansi: declared_ansi.unwrap_or(inherited.ansi),
    })
crates/emma/src/term/theme.rs — role_entry, derive_index

derive_index is a second implementation of the same arithmetic palette.rs holds as nearest_index, and the doc names the duplication and picks a survivor: “pub(super) because palette.rs needs the same arithmetic for a pair… Two copies of one measured table is one more than the design's §2.3 has receipts for, so this is the one that is meant to survive.” Both are pinned against the same seven hexes by tests in their own files, so they cannot drift silently, but there are two of them today. certified: both functions exist at 62ab9c3, and both test suites assert the same 203 and 246 divergences.

Two things a theme may not do

Both are about a screen nobody here can see.

crates/emma/src/term/theme.rs — apply_roles, ROLE_NAMES, SETTABLE

ROLE_NAMES lists all eight names including the refused one, and SETTABLE lists the seven that work. The split exists so that “a typo of text should be told about text, not about seven names that do not include it.” tested twice: a_theme_cannot_colour_ordinary_text checks the refusal is spoken and that the rest of the file still applied, and a_misspelled_role_is_told_what_the_roles_are walks every element of ROLE_NAMES and demands it appears in the message.

The second refusal is a lone background. A theme declares backgrounds only as pairs, and pair_halves enforces two invariants that the doc calls non-negotiable. Both halves or neither, because a half-declared pair applied half-way is a foreground against a background nobody chose. And fg != bg after resolution at every fidelity, checked on the resolved values rather than on the hexes: 

    if halves[0].rgb == halves[1].rgb
        || halves[0].idx == halves[1].idx
        || halves[0].ansi == halves[1].ansi
    {
        notices.push(format!(
            "pairs.{name} resolves to the same colour on both halves at one of the three \
             fidelities, which would draw it invisible; the built-in pair is kept"
        ));
        return None;
    }
crates/emma/src/term/theme.rs — pair_halves

The realistic failure is two different hexes collapsing onto one named colour at sixteen, which a check on the strings cannot see. tested: a_pair_that_resolves_to_one_colour_at_any_fidelity_falls_back builds exactly that case, a theme declaring ground with "ansi16": "light_magenta" and then a chip of ground on accent, distinct at 24 bits and at 256 and identical at sixteen.

What the function does not attempt is a contrast ratio: “WCAG arithmetic against a terminal whose gamma and palette are unknown is a number that looks authoritative and is not, and this repository has a lesson about that exact shape of claim.”

Failure costs colour and never the boot

Nothing in the loader returns a Result, and the region comment says why in one sentence: “a ? anywhere in it would throw away the seven roles that parsed because the eighth did not.” The policy follows harness/src/statusline.rs rather than the harness's refuse-to-start rule, on the ground that every distinction a theme touches is made a second time in glyphs.

An out-of-range ansi256The declared index; the hex survives and the index is derived instead.

An unknown top-level keyNoted and ignored, “so a build that adds a key should not make the file unreadable to the build beside it.”

Notices stop at MAX_NOTICES = 5, and the overflow line names the count and the path, “because the file is where they are going to go and look.” The overflow line is ASCII, and the reason is the same one the glyph tables exist for: it can be printed on a console that has not been moved to UTF-8, “and a message about a broken file that is itself mojibake is a second problem stacked on the first.” tested: a_wrecked_file_cannot_fill_the_screen_with_warnings feeds seven bad hexes, asserts exactly six notices, and asserts the last one is_ascii().

crates/emma/src/term/theme.rs — load, RESERVED

The user's directory is searched first, and the doc names the door that closes: “A project cannot select a theme, so shadowing a name somebody already chose is the only way a repository could repaint their screen, and this order is the door that closes. The reverse is not a risk; it is the preference working.” tested: a_project_theme_never_shadows_a_user_theme_of_the_same_name writes the same name into both directories and asserts the user's wins, then removes the user's and asserts the project's is used, so the order is a precedence rather than a ban.

RESERVED holds one name, emma, so shipping themes/emma.json in a cloned repository cannot change what stock Emma looks like. The notice for it exists only when such a file is actually present, “so an author who wrote a file of that name is told why it did nothing, rather than concluding their JSON is broken.” Selecting emma with no such file is not a problem to report; it is what the name means. tested in both directions.

The selection itself lives in ~/.emma/settings.json and never in a project's config.json. load's name argument is the one-run override, which beats the saved selection. tested: a_one_run_override_beats_the_saved_selection.

Selecting is not switching

A theme is read once, at startup. /theme <name> writes a key to ~/.emma/settings.json and touches no Palette, no Skin and no frame. The owner ruled the scope: “we can set theme and restart the console to see it.” The alternative is priced rather than dismissed: a live swap has to reach every drawn surface at once, and the transcript holds rows already styled under the old colours, so “the realistic outcome of repainting is a half-recoloured screen.” There is no --save flag either, because selecting is what writing it down means.

Running the binary confirms the command's own account of that: emma --help at 62ab9c3 says of /theme <name> that “a theme is read once, when Emma starts, so the name is written to ~/.emma/settings.json and the next start is what shows it”, and that “NO_COLOR outranks every theme, and /theme says so rather than letting you restart into the same screen.” certified 2026-08-16, repeatable: emma --help and read the /theme entries.

The two small parsers

parse_hex accepts #rrggbb and #rgb and nothing else, because “a bare word is a colour name in some other file's vocabulary and would be a guess in this one.” It checks every character is an ASCII hex digit before parsing, so #gggggg is refused rather than erroring per byte. tested over six rejected spellings.

named_ansi maps the sixteen names as ratatui spells them, and accepts grey beside gray and dark_grey beside dark_gray, “because half the world writes it that way and a spelling is not an intent.”

half_entry resolves one side of a pair as either a role name or a bare hex. A bare hex has no role to inherit a sixteen-colour name from, so it takes the built-in half's, which is the same rule as everywhere else applied to the only other thing that has one. text is not accepted as a half, because it is not a colour Emma has.

Roles before pairs

apply applies roles and then pairs, and the ordering is a behaviour rather than tidiness: a pair may name a role, and it must see the theme's value rather than the built-in's. tested: a_pair_may_name_roles_or_hexes_and_takes_the_themes_own_role_values sets accent to #00aaff and then declares a selection pair of {"fg": "accent", "bg": "#191b1e"}, and asserts the resulting pair is ((0, 170, 255), (25, 27, 30)).

Coverage

theme.rs is 1,211 lines and was read in full for this page, tests included. It declares 19 function items above the test boundary: entry, slot, six Theme accessors, derive_index, load, apply, apply_roles, role_entry, apply_pairs, pair_halves, half_entry, parse_hex, named_ansi and cap. All 19 are named here: 19 of 19, along with all six constants (CUBE, RESERVED, ROLE_NAMES, SETTABLE, MAX_NOTICES, BUILTIN) and all three types. Fifteen of its twenty-two tests are cited; the seven that are not are the built-in fixture tests (the_builtin_theme_is_what_emma_renders_today, the_builtin_pairs_are_the_two_backgrounds_on_screen_today, derivation_reproduces_five_of_the_seven_shipped_indices) and four straightforward loader cases.

Not settled here. Nobody has written a theme file and looked at the result. Every test in this file compares resolved values, and the resolved values are correct by the same argument the palette page makes about its own tests. unverified: write a theme into ~/.emma/themes/, select it, restart, and photograph the frame.
