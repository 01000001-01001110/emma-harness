The boundary, and the request that crosses it

Providers & models The boundary Content blocks The turn back Model limits Caching The cache floor Retry Credentials

Two methods and one struct are the whole surface between Emma's loop and any model anywhere. The struct's field order is not cosmetic: it is the order the provider's cache hashes over, and it is a type rather than a convention because a convention in a comment is one a struct literal elsewhere can ignore.

Two methods, and nothing else

Provider is small enough to quote whole. A model id, and a send.

crates/llm/src/lib.rs · trait Provider

#[async_trait]
pub trait Provider: Send + Sync {
    fn model_id(&self) -> &str;

    /// `events` is optional in both modes: pass `None` and the call is silent,
    /// pass a sender and retries become visible even in `Batch`.
    async fn send(
        &self,
        request: Request,
        mode: Mode,
        events: Option<mpsc::Sender<Event>>,
    ) -> Result<AssistantTurn, LlmError>;
}
crates/llm/src/lib.rs — Provider

Mode picks between one JSON body and a stream of SSE frames. Both produce the same AssistantTurn, so the difference a caller sees is only whether Event::TextDelta arrives on the way. A terminal wants Stream; a --print run or an internal sub-call is content with Batch.

crates/llm/src/lib.rs · enum Event

/// Anything worth showing a human while the call is in flight.
#[derive(Debug, Clone, PartialEq)]
pub enum Event {
    /// Assistant text, as it arrives. Streaming mode only.
    TextDelta(String),
    /// A tool call has started; its arguments are still streaming.
    ToolUseStarted { id: String, name: String },
    /// A request failed and is being retried. Emitted in both modes, because a
    /// retry the user cannot see is indistinguishable from a hang.
    Retrying {
        attempt: u32,
        max_attempts: u32,
        delay: Duration,
        reason: String,
    },
}
crates/llm/src/lib.rs — Event, Mode

Only TextDelta and ToolUseStarted are streaming-only; Retrying is emitted from execute, which runs identically in both modes. A batch caller that passes a sender therefore still sees its retries. tested by a_429_is_retried_after_the_delay_the_api_asked_for_and_is_visible, which runs in Mode::Batch and asserts two Retrying events with the comment a silent retry is a hang. That test's mutation was not run here: it is claimed on the assertion's own shape, not on a red run somebody watched.

A request names its four parts in prefix order

Request is four fields rather than one message list, and the order of the fields is the order the bytes go out in.

crates/llm/src/lib.rs · struct Request, Request::new

/// One model call, in prefix order.
///
/// `history` is every completed turn; `query` is this turn only — the user's
/// message first, then the `tool_use` / `tool_result` pairs the loop appends as
/// it works. Keeping them apart is what lets the renderer mark the end of the
/// history without guessing where the stable part stops.
#[derive(Debug, Clone)]
pub struct Request {
    /// Instructions. First, and byte-identical across every call of a session.
    pub instructions: String,
    /// The tool surface, exactly as `Registry::wire_definitions()` renders it.
    pub tools: Vec<serde_json::Value>,
    pub history: Vec<Message>,
    pub query: Vec<Message>,
    /// Caps thinking **and** answer together on this model family, so a value
    /// sized around the answer alone truncates mid-thought.
    ///
    /// A ceiling the caller wants, not one the model promised. Every model has
    /// its own maximum and exceeding it is a 400, so the provider lowers this
    /// to the model's when the model's is lower — see [`models`].
    pub max_tokens: u32,
    /// Likewise an ask: the provider clamps it down to the best level the
    /// chosen model actually implements, or drops it entirely for a model with
    /// no effort parameter.
    pub effort: Effort,
    pub caching: Caching,
}
crates/llm/src/lib.rs — Request

The cache is an exact prefix match, so anything that varies per turn has to sit after everything that does not. That is the whole argument for the order. Keeping history and query as separate fields is what lets the renderer find the end of the stable part without inspecting messages to guess where a turn began.

why a struct and not a convention

The module doc states the reason: the ordering is a type so that building a request with a per-turn byte at position zero is not something the type lets you express. A convention in a renderer comment is one a struct literal somewhere in the loop can ignore, and one did, for max_tokens. That is why the model clamping happens at the wire boundary rather than in Request::new.

crates/llm/src/lib.rs — module doc §"The one shape that must not drift"

Request::new takes instructions and tools and leaves the rest empty. Its two constants are asks, and its comment says so:

crates/llm/src/lib.rs · Request::new

pub fn new(instructions: impl Into<String>, tools: Vec<serde_json::Value>) -> Self {
    Self {
        instructions: instructions.into(),
        tools,
        history: Vec::new(),
        query: Vec::new(),
        // What Emma wants, not what it will necessarily get. xhigh is the
        // documented setting for coding and agentic work and Emma is
        // nothing else, and 32,000 is a budget rather than a ceiling — a
        // model that caps lower gets its own cap, a model without xhigh
        // gets the best level it has. `models` holds both, and the
        // provider applies them, because a `Request` does not know which
        // model it will be sent to.
        max_tokens: 32_000,
        effort: Effort::XHigh,
        caching: Caching::On,
    }
}
crates/llm/src/lib.rs — Request::new

with_history and with_query are the two builders, each a move-assign-return. There is no with_tools: tools are a constructor argument, because a request without them is not a shape Emma ever sends.

Messages, and the four ways one gets built

Role has two variants and no room for a third: User and Assistant are what the Messages API accepts in messages, and instructions travel in the top-level system field, which is where the prefix ordering wants them anyway.

The four constructors differ in what they promise, not just in convenience. Message::assistant takes blocks because rebuilding a turn from its text loses the thinking signature and makes the next call fail. Message::assistant_text exists beside it for turns Emma composed rather than received, such as a compaction summary or the note that says a previous goal stopped short.

Message::user is the fourth and is a one-line wrapper around Content::Text. It is uninteresting except for what it does not do: a plain user message stays a JSON string on the wire rather than becoming a one-element block array, which is a byte difference the cache would notice. certified by the golden body in the_whole_request_body_is_pinned_byte_for_byte, where the two user messages render as "content":"HISTORY …" and not as arrays. Effort is a ladder with holes in it

crates/llm/src/lib.rs · Effort::rank

/// Position on the ladder, for "the best level at or below this one".
///
/// A number rather than `#[derive(PartialOrd)]` because deriving it would
/// also make `<` work on the enum everywhere, and a comparison between two
/// efforts only means something in the one place that clamps them — a
/// model's supported set has holes, so `a < b` says nothing about whether
/// `b` can be sent where `a` can.
pub(crate) fn rank(self) -> u8 {
    match self {
        Self::Low => 0,
        Self::Medium => 1,
        Self::High => 2,
        Self::XHigh => 3,
        Self::Max => 4,
    }
}
crates/llm/src/lib.rs — Effort

rank is pub(crate) and has exactly one caller, Limits::clamp_effort. Effort::as_str is the wire spelling and has one caller too, in render below. What each is for is on the model limits page; Caching is two variants, On and Off, and belongs to caching.

Where the ask meets the model

send is two lines: render the body, execute it. Everything interesting about the outgoing request is in render, and it is short enough to read whole.

crates/llm/src/anthropic.rs · AnthropicProvider::render

fn render(&self, req: &Request, mode: Mode) -> Result<Value, LlmError> {
    let tools_chars = serde_json::to_string(&req.tools)
        .map(|s| s.len())
        .unwrap_or(0);
    // The cache floor is per-model and this is the only place the model and
    // the gating are both in scope — the same argument as the clamping
    // below, and the reason the floor is a parameter rather than a const.
    let floor = min_cacheable_tokens(&self.model);
    let system = system_field(&req.instructions, tools_chars, req.caching, floor);
    let messages = messages_field(req, tools_chars + req.instructions.len(), floor)?;

    // The request says what Emma wants; the model says what it will take.
    // Clamping happens here because this is the only place both are in
    // scope, and because it is the last point every request passes through
    // however it was built — a struct literal somewhere in the loop gets
    // the same treatment as `Request::new`.
    let limits = models::limits(&self.model);

    // serde_json orders object keys deterministically, which is what the
    // cache needs: two identical requests must render identical bytes.
    let mut body = json!({
        "model": self.model,
        "max_tokens": limits.clamp_max_tokens(req.max_tokens),
        "system": system,
        "messages": messages,
        "tools": req.tools,
    });
    // Absent rather than defaulted: on a model with no effort parameter the
    // field itself is the 400, so there is no value that would be safe to
    // send. Omitting it takes the provider's own default, which is the
    // closest thing to "as hard as this model works".
    if let Some(effort) = limits.clamp_effort(req.effort) {
        body["output_config"] = json!({ "effort": effort.as_str() });
    }
    if mode == Mode::Stream {
        body["stream"] = json!(true);
    }
    Ok(body)
}
crates/llm/src/anthropic.rs — AnthropicProvider::render

Five branches change the outgoing bytes. The floor and the two field builders decide where cache markers land; clamp_max_tokens can lower the number; clamp_effort can lower the level or drop output_config entirely; and stream appears only in Mode::Stream, which the_wire_order_is_instructions_then_tools_then_history_then_query asserts by checking sent.get("stream") == None in batch mode. tested

crates/llm/src/anthropic.rs — render, the_whole_request_body_is_pinned_byte_for_byte

Three things are absent from that body and each absence is a 400 avoided. There is no thinking block: the fixed budget_tokens budget was removed on this model family and sending it returns 400, so depth is controlled by output_config.effort alone. There are no sampling parameters, for the same reason. And output_config itself is omitted rather than defaulted when the model has no effort parameter. The first two are asserted directly: assert!(sent.get("thinking").is_none()) and the same for temperature. tested

Constructing the provider

crates/llm/src/anthropic.rs · AnthropicProvider::new

pub fn new(key: ApiKey, model: Option<String>) -> Self {
    Self {
        http: reqwest::Client::builder()
            // Generous: a long agentic turn at high effort can think for
            // minutes before the first byte in batch mode.
            .timeout(Duration::from_secs(600))
            .build()
            .expect("reqwest client"),
        key,
        model: model.unwrap_or_else(|| DEFAULT_MODEL.to_string()),
        // Deliberately not read from the environment. Emma runs inside
        // repositories with whatever env the shell carries; an env var that
        // redirects where the key is sent is a credential-exfiltration
        // switch, and no feature here is worth that.
        base_url: API_URL.to_string(),
        retry: Retry::default(),
    }
}
crates/llm/src/anthropic.rs — AnthropicProvider::new, DEFAULT_MODEL, API_URL, API_VERSION

Four constants live at the top of the file: DEFAULT_MODEL is claude-opus-5, API_URL is https://api.anthropic.com/v1/messages, API_VERSION is 2023-06-01 and goes out as the anthropic-version header, and the client timeout is 600 seconds. The timeout is the one a reader is likeliest to want to change, and it is not configurable today.

base_url is settable only through with_base_url, at construction, which the tests use to point at a loopback stub. Reading it from the environment would be a switch that redirects where the key is sent, in a program that runs inside repositories with whatever environment the shell carries. with_retry is the same shape and swaps the policy; the provider tests use it to make backoff milliseconds rather than seconds.

Debug is hand-written so no field added later can print the key by existing:

A scripted provider drives the loop with no socket and no key

Because the trait is the whole boundary, the agent loop's test suite runs against Fake: a VecDeque of scripted turns and a Vec of every Request it was handed. Each scripted turn carries text, tool calls, a token count, and an optional failure that answers with LlmError::BadRequest. Running out of script is itself a BadRequest, so a test that calls the model more times than it meant to fails rather than quietly ending the goal.

Two details of the fake are there because of live failures. It emits a signed thinking block on every turn, so the assertion that the loop hands a turn back untouched is asserting about a turn with something fragile in it. And every scripted tool_use carries extra: {"caller": {"type": "direct"}}, because the real API sends that key and a fake without it would not exercise the path a live run found broken. That path is the next page.

what is not verified here
