Sessions & context

Compaction without a model call

Sessions & context The file Records The fold Resume Continuity Compaction The corpus

Whole finished goals, replaced oldest-first with their goal text, their final answer and a fixed sentence saying the tool traffic is gone. No model is asked anything. The design note for this feature recommended the opposite, and that reversal is the main subject of this page.

What it operates on

// crates/emma/src/agent.rs
struct Chapter {
    goal: String,
    answer: String,
    messages: Vec<Message>,
    /// Already a summary. Summarising it again would produce the same two
    /// messages and a second log record saying nothing happened.
    summarised: bool,
}

A chapter is one whole goal. Compaction works in chapters because cutting anywhere else risks separating a tool_use from the result that answers it, and a boundary that is "wherever the arithmetic landed" is one somebody has to re-derive every time they read the code. goal and answer live beside the messages because they are what a summary is made of, and deriving them back out of the message list afterwards would be guesswork.

crates/emma/src/agent.rs — Chapter and its doc 
// crates/emma/src/agent.rs
/// The whole session as one message list — every goal, in order, with the
/// tool traffic that has not been compacted away.
///
/// This is what a request carries as `Request::history`, and it is what a
/// fold of the session file must equal.
pub fn conversation(&self) -> Vec<Message> {
    self.chapters
        .iter()
        .flat_map(|c| c.messages.iter().cloned())
        .collect()
}

estimated_context is that flattening measured by estimate, and it is what /model and the compaction receipt quote as "roughly N tokens". It enforces nothing.

The trigger is measured

// crates/emma/src/agent.rs
fn compact_if_needed(&mut self, measured: Option<i64>, why: &str) {
    let cap = self.s.budgets.max_context;
    if cap <= 0 {
        return;
    }
    let size = measured.unwrap_or_else(|| estimate(&self.conversation()));
    if size <= cap {
        return;
    }
    // Half the cap rather than all of it: the goal now running needs room
    // to work in, and compacting to exactly the limit would mean compacting
    // again on the next call.
    let target = (cap / 2).max(1);
    // Measured once per chapter rather than once per step. Re-summing the
    // whole conversation on every iteration of the loop below is quadratic
    // in a list whose elements are file contents.
    let sizes: Vec<i64> = self
        .chapters
        .iter()
        .map(|c| estimate(&c.messages))
        .collect();
    let mut remaining: i64 = sizes.iter().sum();
    let mut take = 0;
    while take < sizes.len() && remaining > target {
        remaining -= sizes[take];
        take += 1;
    }
    // **The returned reason used to be dropped here.** `/compact` explains
    // itself and the threshold path did not, so a conversation over its cap
    // with nothing left to summarise — one enormous goal, or a history
    // already reduced to summaries — grew on every single call in silence
    // until the token budget or a provider 400 ended it. The user's first
    // sign was the run stopping.
    if let Compacted::Nothing(reason) = self.compact(take, size, why) {
        if !self.said_compaction_stuck {
            self.said_compaction_stuck = true;
            self.s.term.warn(&format!(
                "this conversation is over the context limit and compaction cannot \
                 shrink it: {reason}. Every request from here is larger than the cap, \
                 and the run will end on a budget or a provider error rather than on \
                 the goal. `/clear` starts a fresh conversation; a smaller goal would \
                 also fit."
            ));
        }
    }
}

cap <= 0 disables compaction entirely, which is how --max-context 0 turns it off. measured is the provider's own billable_input_tokens for the previous call, which covers the whole request: the system prompt and the tool schemas as well as the conversation. The estimate stands in for one case, the first check of a goal on a process that has not called the model yet, and in practice that is a resume into a large session.

crates/emma/src/agent.rs — compact_if_needed, and its two call sites in run_goal

Two call sites. One before the first request of a goal, with None and the reason "a new goal opened over the context limit"; one inside the loop, after the budget guards and before the request is built, with self.last_input and the reason "the request passed the context limit". The second is why the request that goes out is the compacted one rather than the next one after it.

The counting loop is greedy over whole chapters and stops as soon as the remainder fits, so it never takes the newest goal unless it has to take everything. It measures each chapter once. Re-summing the conversation inside the loop would be quadratic in a list whose elements are file contents, which is the kind of cost that is invisible until a session gets large enough to need compaction in the first place.

The tail of the function used to be a bare self.compact(take, size, why);, dropping the returned Compacted on the floor. That mattered in exactly one case: a conversation over its cap with nothing left to summarise — one enormous goal, or a history already reduced to summaries — where compact answers Compacted::Nothing with a reason and the threshold path said none of it. Such a session grew on every call in silence until the token budget or a provider 400 ended it, and the user's first sign was the run stopping. The reason is now caught and said once per session, on the said_compaction_stuck flag, with /clear named as the way out; once rather than per call, because the condition holds on every subsequent request and a warning per request is a run burying itself in its own complaint. tested automatic_compaction_that_cannot_help_says_so_once in crates/emma/tests/commands.rs.

Replacing them

// crates/emma/src/agent.rs
fn compact(&mut self, take: usize, size: i64, why: &str) -> Compacted {
    let take = take.min(self.chapters.len());
    if take == 0 {
        return Compacted::Nothing("there is nothing behind the current goal".into());
    }
    let before: i64 = self.chapters[..take]
        .iter()
        .map(|c| estimate(&c.messages))
        .sum();
    let replacement: Vec<Message> = self.chapters[..take].iter().flat_map(summarise).collect();
    let after = estimate(&replacement);

One implementation with two doors. The threshold path counts until the remainder fits half the cap; /compact counts every finished goal, or every one but the last. Everything after the count is here once, because two compaction implementations would be two things a resume could disagree with, and the fold has no summarising code of its own to be the second. 

// crates/emma/src/agent.rs
/// What a compacted goal leaves behind: the goal, the answer, and a sentence
/// saying what is no longer there.
///
/// Exactly the collapse `run_goal` used to apply to every goal the moment it
/// finished — see [`Agent::chapters`]. The note is the part that is new, and it
/// is the difference between a model that reads a file again and one that
/// answers from a recollection of it.
fn summarise(c: &Chapter) -> Vec<Message> {
    if c.summarised {
        return c.messages.clone();
    }
    let goal = if c.goal.trim().is_empty() {
        "[an earlier goal]"
    } else {
        c.goal.trim()
    };
    let answer = if c.answer.trim().is_empty() {
        "[this goal ended without a final message]"
    } else {
        c.answer.trim()
    };
    vec![
        Message::user(goal),
        Message::assistant_text(format!("{answer}\n\n{COMPACTED_NOTE}")),
    ]
}

/// Said to the model, in the place the traffic used to be.
const COMPACTED_NOTE: &str = "[Summarised to save context. The tool calls from this goal and \
     their results — file contents, command output, diffs — are no longer in this conversation. \
     Read anything you need again rather than recalling it.]";

A compacted goal is exactly two messages: a user message that is the goal text, and an assistant message that is the final answer plus the note. Empty fields get stated placeholders rather than blank strings, so a goal that ended without a final message says so instead of producing an assistant message that opens with a newline. An already-summarised chapter comes back unchanged, which is what stops a second pass wrapping it in a second note.

What a folded goal loses: every tool call and every result, which means file contents, command output and diffs, and every intermediate assistant turn with its thinking blocks. What survives for the life of the session is every goal's words and every goal's final answer. The note exists because a model that does not know a file has left its context answers from a memory of it, and a confident wrong answer costs more than a second read. tested compaction_drops_the_oldest_tool_traffic_and_keeps_the_words in crates/emma/tests/conversation.rs asserts the file body absent, the goal present, the answer present and the note present, in the bytes the fake provider actually received.

The compaction that would not shrink anything

// crates/emma/src/agent.rs — Agent::compact
// A conversation summarising would not shrink has nothing to give.
// Stopping here rather than rewriting it into itself is what keeps a
// session under a cap it cannot reach from logging a record and
// reporting a saving on every single call.
//
// **Two different situations reach this line and a user needs to be
// told which.** Automatic compaction is no longer silent either way —
// DEF-009 gave the threshold path a one-shot warning naming `/clear`,
// because a session pinned against a cap it cannot compact below was
// otherwise a loop that just kept costing money. `/compact` was always
// loud, and the first live run of it said "already summarised" about two
// goals that plainly were not — because those goals were four words
// long and `COMPACTED_NOTE` is three hundred characters, so the
// replacement was *larger* than what it replaced. The sentence was true
// of the arithmetic and false about the conversation, which is the class
// of untruth this repository has already paid for twice.
if after >= before {
    let all_summaries = self.chapters[..take].iter().all(|c| c.summarised);
    return Compacted::Nothing(if all_summaries {
        "the conversation is already summarised — there is nothing left to take out".into()
    } else {
        format!(
            "summarising those {take} goal(s) would not make the conversation smaller. \
             Compaction replaces a goal with its text, its answer and a note saying the \
             tool results are gone, and here that note is longer than what it would \
             replace — roughly {before} tokens becoming {after}."
        )
    });
}

The note is roughly three hundred characters, so two four-word goals compact upward and the guard fires. That is not a corner case invented for a test; it is what the first live /compact did, and the bug it produced was a sentence rather than a crash. The arithmetic was right and the explanation was wrong, so a user was told their conversation was already summarised when it was nothing of the sort. There are now two branches, and the second quotes the before and after so the claim can be checked against the numbers. tested compaction_stops_when_there_is_nothing_left_to_win.

The record the fold replays

// crates/emma/src/agent.rs — Agent::compact
let dropped: usize = self.chapters[..take].iter().map(|c| c.messages.len()).sum();
self.chapters.drain(..take);
self.chapters.insert(
    0,
    Chapter {
        goal: String::new(),
        answer: String::new(),
        messages: replacement.clone(),
        summarised: true,
    },
);
// Both halves, because the fold replays this rather than re-deciding
// it: how many messages off the front went, and exactly what took their
// place. It is also the one record a human reads to find out what the
// model stopped being able to see.
self.s.log.append(
    "compacted",
    json!({
        "why": why,
        "goals": take,
        "drop_messages": dropped,
        "messages": replacement,
        "request_tokens": size,
        "max_context": self.s.budgets.max_context,
        "estimated_before": before,
        "estimated_after": after,
    }),
);

The replaced chapters become one chapter with empty goal and answer and summarised: true, which is why summarise's placeholders exist: a later compaction that reaches this chapter returns its messages unchanged, and a Cleared receipt counts it as not a goal. drop_messages counts the messages that left, so the fold's splice removes the same prefix from a list it rebuilt independently. See the fold's compacted arm, which is also where that arm's failure mode on a malformed record is described. tested compact_is_replayed_by_the_fold_rather_than_re_decided in crates/emma/tests/commands.rs.

The threshold path then narrates itself through term.note, naming the messages dropped, the goals taken and the before and after. A user-triggered compaction skips that line because /compact reports its own, and two notes for one action reads as two actions.

The design note recommended a model call, and was overruled

notes/design/session-and-context.md §2 surveyed six shipped tools and recommended what all of them do: summarise with one model call, same model, tools absent, effort low, against a fixed template asking for objectives, what was verified, decisions and why, what failed, files touched, what is next. It also recommended trigger-high/compact-low hysteresis, crossing around 120k and compacting down to 30–40k, and that the compacted record carry the summary plus references to the retained turns rather than copies of them.

None of the three shipped. The note is still in the tree and still reads as current advice, so the three departures belong in one place, or the recommendation comes back.

  • No model call. Three arguments, in the order agent.rs makes them: it would spend the budget of whichever goal happens to be running; it can fail in the middle of one; and it produces a claim about the conversation where the mechanical version produces a record of it. The note also warned that a model-written summary can be wrong. It offered two mitigations and described neither as a fix.
  • Half the cap, not a fixed floor. target = (cap / 2).max(1) is 60,000 at the default rather than the note's 30–40k. Same effect on how often compaction fires, and no second constant to keep in step with the first.
  • The replacement is written into the record whole. The note argued for references, citing a bug in another tool where re-serialising surviving history made the log grow without bound. The code stores drop_messages and the exact replacement messages, so a resume replays the compaction instead of re-deriving it, and session.rs contains no summarising code that could disagree with the loop's. The growth the note warned about is bounded here by the replacement being two short messages per goal rather than a retained window of turns.

The two doors a user has

// crates/emma/src/agent.rs
/// Compact at the user's request rather than at the threshold.
///
/// `everything` includes the goal that has just finished. The default keeps
/// it because "everything but the last goal" is a rule somebody can hold in
/// their head, where a target size is arithmetic they would have to be told.
///
/// It goes through the same [`Agent::compact`] the threshold does, so there
/// is one compaction implementation, one `compacted` record and one fold
/// arm replaying it.
pub fn compact_now(&mut self, everything: bool) -> Compacted {
    let n = self.chapters.len();
    let take = if everything { n } else { n.saturating_sub(1) };

/compact <words> is refused rather than ignored, and the refusal names a workflow that does work. 

// crates/emma/src/session_command.rs — compact
// Said rather than ignored. `Agent::compact`'s doc rules that
// compaction is not model-summarised — a call there spends the running
// goal's budget, can fail mid-goal, and produces a *claim* about the
// conversation where the current code produces a *record* of it. An
// instruction can only be honoured by a model, so the honest answer is
// to say so and name the workflow that does work.
say(
    s.term,
    &format!(
        "compaction replaces each finished goal with its goal text and its final \

         \"{words}\" would be silently ignored, which is worse than saying so.\n\
         Run /compact on its own, or state what to keep as an ordinary goal first \
         (\"summarise what we established about the API\") — the answer of a goal \
         always survives compaction, so it will still be there afterwards."
    ),
);

The workaround it offers is real rather than a deflection: a goal's answer is one of the two things compaction keeps, so asking for the summary as an ordinary goal puts it somewhere compaction cannot take it. tested compact_with_an_instruction_says_it_cannot_follow_one and compact_tells_all_from_an_instruction_it_cannot_honour.

The other thing that shortens a conversation

// crates/emma/src/agent.rs
/// Drop the conversation without ending the session.
///
/// A `cleared` record goes in the log, and `session::Fold` honours it — the
/// bytes stay in the file for a human to read and the fold skips them.
/// Without that arm `--resume` would fold the whole file and un-clear the
/// session, which would make this command a lie.
///
/// `turn_seq` is deliberately **kept**: turn ids have to stay unique inside
/// one session file, and the file is not cleared.
pub fn clear(&mut self) -> Cleared {
    let cleared = Cleared {
        goals: self.chapters.iter().filter(|c| !c.summarised).count(),
        messages: self.chapters.iter().map(|c| c.messages.len()).sum(),
    };
    self.chapters.clear();
    self.last_ending = None;
    self.last_input = None;
    // A resume that has not been spent yet is still a conversation waiting
    // to be injected into the next goal's query. Leaving it would mean
    // `/clear` on a `--resume`d session cleared everything except the thing
    // the user was most obviously trying to get rid of.
    self.resumed = None;
    self.s.log.append(
        "cleared",
        json!({ "goals": cleared.goals, "messages": cleared.messages }),
    );
    cleared
}

/clear is not compaction and shares none of its code. It drops everything, writes its counts into the record, and clears last_input so the next goal's compaction check has no stale measurement to compare against. A summarised chapter is not counted as a goal in the receipt, which keeps the number honest about what the user is losing.

The receipt in session_command.rs then says what survived: the session's tool and host grants, the transcript path, the model and the session id. Grants are consent about the process rather than about the conversation, and clearing them would make nothing safer, since the human is still at the keyboard and would be asked the same questions again. What silence would cost is the ability to notice, so the receipt names them.

The estimator, and where its error lands

// crates/emma/src/agent.rs
/// Roughly how many tokens a message list is worth.
///
/// `chars / 4`, the same conservative ratio `emma-llm`'s packer uses to decide
/// whether a prefix is worth a cache breakpoint, and documented there as
/// under-counting what the provider bills. It is used here for two things that
/// tolerate it — deciding *how much* to drop once a measured number has already
/// said dropping is necessary, and standing in for that measurement on the one
/// call of a process that has none. It is never what fires a budget.
fn estimate(messages: &[Message]) -> i64 {
    let chars: usize = messages.iter().map(|m| m.content.wire_len()).sum();
    (chars / 4) as i64
}

wire_len is the rendered JSON length, quotes and escapes included, because the provider tokenises those too. The under-count has a direction, and it lands differently on each consumer.

consumeran under-count meanswhich is
the compaction trigger at goal open the cap looks further away than it is, so compaction fires later, or not at all, on the first call tolerable: the next call reports a measured number and the check runs again before the request goes out
how many chapters to take every chapter looks smaller, so slightly more may be taken than strictly needed tolerable: the error is toward compacting more, not less
the cache-breakpoint gate in emma-llm a prefix that really does clear the model's floor is judged not to, and the marker is withheld a bill: the forgone 0.9× read discount on that span, with no symptom anywhere except the invoice
crates/emma/src/agent.rs — estimate; crates/llm/src/anthropic.rs — CHARS_PER_TOKEN, clears_minimum

The third row is where the margin widened. The gate used to be one constant, 512, which was right for claude-opus-5. The floor is per-model and not monotonic with release date, and the table now runs from 512 to 4,096: claude-haiku-4-5 and claude-opus-4-6 cache nothing under 4,096 tokens, and a model the table has never heard of is assumed to be at 4,096 too. At a 512 floor the gap between an under-counting estimate and the truth costs a marker on a prefix of a couple of kilobytes. At 4,096 it is a prefix of roughly sixteen kilobytes going unmarked, and one /model or one Haiku-typed delegation is enough to reach that floor. unverified: the direction of the error is stated in both source files and matches English-plus-JSON tokenising at closer to 3.5 characters per token, but nobody in this tree has measured Emma's own wire bytes against a token count. Settle it by sending a request of known rendered length with caching off and comparing wire_len / 4 against the input_tokens the API reports, or by pushing the same bytes through the token-counting endpoint.

What the estimate does not touch

The token budget. --max-tokens is enforced on cost_tokens, computed from the provider's own usage numbers with the cache multipliers applied, and no estimate is involved. It is tested after each call rather than before, so the call that crosses it is paid for in full: a 500,000 budget stopped a real run at 579,565. certified, and greppable. That figure is the largest goal_finished.tokens in ~/.emma/sessions/, and it is in sess-1786385316950-34808.jsonl, which is also the largest file in the directory at 272,923 bytes.
