What a write would change

The terminal Surface Frame Layout Colour Themes Vocabulary Transcript Markdown Diffs Status Sidebar Dock User tools Pages Copying out

A Write prompt that said write src/auth.rs — 4,102 bytes, 118 lines withheld what would actually change. An Edit prompt did better and still made the reader do the diffing, twenty - lines above twenty + lines of which three differed. This file is the missing half, and it is arranged around one rule: a diff is never fabricated.

Every case where a diff cannot be produced without fabricating one

The type says so before the code does. Change has three variants, and the two that are not a patch exist so a prompt can say either: “there is no diff here that would not fabricate one” and “there is no change here”.

CaseAnswer
Either side contains a NUL byteUndiffable, naming which side
The file is not UTF-8, larger than MAX_READ, a directory, or unreadableUndiffable, naming why
Either side has more lines than MAX_LINESUndiffable, with both counts
The changed region exceeds MAX_CELLSPatch { coarse: true }, labelled in the summary
The two sides are the same bytesIdentical, said out loud
They differ only in line endingsA patch with no hunks and a note saying so

The last row is the subtle one. compute returns early when the two texts are equal, so reaching the end with no hunks and no notes means the sides differ and nothing found a line or an ending to point at:

Two sides, and where each comes from

Write carries the whole new text and the old text is on disk, so its diff is the file against the proposal and its line numbers are real. Edit carries old_string and new_string, which are the two sides, so the diff is a function of the arguments alone and cannot disagree with what the tool will do. What it loses is position, so Patch::anchored is false and no @@ header is printed. A @@ -1 there would be an invented fact. tested: an_unanchored_diff_prints_no_line_numbers_it_does_not_have asserts the absence and that a whole-file diff does carry them, which makes it a distinction rather than a missing feature.

Neither is the diff of what happened. Both are computed before the write, from a proposal. A tool that then fails, or is refused, changed nothing, and the transcript says so on its own line.

Only NotFound is a new file

/// The file as it stands, for `Write` to be diffed against.
///
/// **Every failure is named rather than swallowed.** A file that cannot be read
/// must not fall through to "missing", because "missing" renders as a brand new
/// file made entirely of additions — which is precisely the mislabelled
/// destructive change this file exists to make impossible. Only `NotFound` is
/// `Missing`.
fn before(path: &str) -> Before {
    …
    let meta = match std::fs::metadata(&full) {
        Ok(m) => m,
        Err(e) if e.kind() == std::io::ErrorKind::NotFound => return Before::Missing,
        Err(e) => return Before::Unreadable(format!("{path} could not be read: {e}")),
    };

Line endings, which on this machine are the whole hazard

Emma is developed on Windows against a CRLF working tree. A diff comparing raw lines would report every line of every file as changed the first time anything normalised them, “which is worse than no diff: it buries the one real change in two thousand false ones.”

So split strips a trailing \r before lines are compared and records that it did, and a change in the endings becomes one sentence. The same goes for a missing final newline. tested: changing_only_the_line_endings_is_one_sentence_and_not_a_wall builds a two-thousand-line CRLF file against its LF twin, asserts both added and removed are zero, and asserts the whole rendered output is under five lines. a_real_change_inside_a_crlf_file_is_the_only_thing_reported holds the other end and also checks no stray carriage return reached the drawn rows.

A prefix trim and an LCS, bounded

similar is the obvious crate and was not taken. The requirement a general crate does not offer is that the diff be bounded: this runs on the interactive path for every Write a model makes, “so a two-hundred-megabyte file has to cost a sentence rather than a swap storm. Every limit in this file is that requirement showing through.”

crates/emma/src/term/diff.rs · the four limits

/// The most of a file that is read to diff against. Past this the prompt says
/// how big the file is instead, which is a fact, rather than a diff of the first
/// two megabytes, which would be a lie by omission.
pub const MAX_READ: u64 = 2 * 1024 * 1024;

/// The most lines either side may have before an exact diff is refused.
pub const MAX_LINES: usize = 50_000;

/// The most LCS cells to fill for the changed region, after the common prefix
/// and suffix are trimmed off. 250k is a 500×500 middle — an edit that rewrites
/// five hundred consecutive lines is a rewrite, and gets shown as one.
const MAX_CELLS: usize = 250_000;

/// Unchanged lines kept either side of a change, as `git diff` does.
const CONTEXT: usize = 3;
crates/emma/src/term/diff.rs — the Limits region

ops trims the common prefix and suffix, then either runs middle (the classic LCS table, backtracked into rows) or, past the cell bound, emits every removal followed by every addition and sets coarse. The table is u32 rather than usize, “a megabyte on a 32-bit count against two on a 64-bit one is worth having on a path a person is waiting on.” hunks groups changed rows with CONTEXT either side and merges runs that would share their context, tracking old and new line numbers as it walks.

The budget, and why a coarse patch splits it

BUDGET is 40 drawn body rows, the number the old approval::diff used, “so the cut this replaces is no larger than the one it inherits.” The summary and the notes sit outside it: a cut diff that no longer said -1,412 lines would withhold the fact the prompt exists to supply.

crates/emma/src/term/diff.rs · coarse_rows

/// A coarse patch, with the budget split between the two sides.
///
/// **Why this is not the ordinary head-of-the-diff cut.** A coarse patch is one
/// block of removals followed by one block of additions, so taking the first
/// forty rows takes forty removals and shows *no* additions at all — a
/// thousand-line rewrite drawn as a thousand-line deletion. That is `codex-rs`
/// #34515 with the signs the other way round, and it is worst in the case that
/// matters most: the reader is deciding whether to allow a destructive write.
/// So each side gets half the budget, whatever is left over goes to whichever
/// side can use it, and the closing row names how much of *each* went.
fn coarse_rows(patch: &Patch, budget: usize) -> Vec<Out> {
    …
    let half = budget / 2;
    // Each side asks for half; a side that wants less than half hands the rest
    // over rather than leaving the budget unspent.
    let take_del = dels
        .len()
        .min(half + half.saturating_sub(adds.len().min(half)));
    let take_add = adds.len().min(budget - take_del.min(budget));

The gutter, and the rule this file inverts

markdown.rs refuses to insert anything into text a reader copies. This file does the opposite: every row carries a +, - or two spaces. The distinction is stated rather than treated as an exception:

“A diff is not the file. It is a report about a change, in the format every reader already knows from git diff, and pasting it into a bug report is the use, pasting it into a compiler is not.”

crates/emma/src/term/diff.rs module doc, §"What is drawn, and what a reader copies"

crates/emma/src/term/diff.rs · text_of

/// The text of one row, gutter and all. **The single place the gutter is
/// written**, so the panel and the transcript cannot disagree about which side a
/// line is on — which is the `#34515` failure, a delete-only patch that read as
/// add-only, made structurally impossible rather than merely tested for.
fn text_of(out: &Out) -> String {
    match out {
        Out::Meta(t) => format!("  {t}"),
        Out::Hunk(t) => format!("  {t}"),
        Out::Cut(t) => format!("  … {t}"),
        Out::Add(t) => format!("  + {t}"),
        Out::Del(t) => format!("  - {t}"),
        Out::Context(t) => format!("    {t}"),
    }
}

The one line that is never cut

crates/emma/src/term/diff.rs · Patch::summary

    pub fn summary(&self) -> String {
        let plural = |n: usize| if n == 1 { "line" } else { "lines" };
        let mut out = match (self.added, self.removed) {
            (0, 0) => "no lines changed".to_string(),
            (a, 0) => format!("+{a} {}", plural(a)),
            (0, r) => format!("-{r} {}", plural(r)),
            (a, r) => format!("+{a} -{r} lines"),
        };
        if self.coarse {
            out.push_str(
                ", shown as one replacement — the changed region is too large to \
                 line up exactly",
            );
        }
        out
    }

Its doc names the incident it defends against: “the failure codex-rs shipped twice — an empty diff body, and a delete-only patch that read as add-only — where the magnitude of a destructive change went missing at exactly the prompt that existed to show it.” tested: a_huge_diff_is_cut_and_names_the_size_of_what_it_cut renders a two-hundred-row change inside a forty-row budget and asserts +100 -100 lines is still on screen, and deleting_most_of_a_file_reads_as_a_removal_and_not_as_an_addition asserts a 39-line deletion draws no + at all.

Which calls get a diff

changes_a_file(tool) is matches!(tool, "Write" | "Edit"), and it is consulted by two callers so that “the diff is drawn” and “the diff is not repeated” cannot come apart. Term::tool_started draws it; Term::prompt_header skips echoing the preview for the same set, because otherwise the same forty rows land on screen twice in a row, and “a reader scrolling back through two copies of a diff has to work out whether they are two changes.” tested from the other file: the_tools_whose_diff_is_drawn_are_exactly_the_ones_the_prompt_does_not_repeat is written as “these are the same set” rather than as two contains calls, “because the hazard is a writing tool added to one list and not the other.”

for_call returns None for anything else, and also for a Write or Edit missing its arguments, rather than diffing against the empty string. tested: a_tool_with_no_diff_to_show_gets_none_rather_than_an_invented_one.
