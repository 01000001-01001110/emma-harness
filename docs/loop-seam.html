The agent loop

Seams

The agent loop One turn Failure The memo Endings The kick Budgets Done Seams

Three things reach into the loop from outside it: a test replacing the network, a signal handler ending a call, and a user changing model mid-session. All three are handled by the same arrangement, which is that Setup holds interfaces rather than concrete types.

What a run is configured with

// crates/emma/src/agent.rs
pub struct Setup<'a> {
    /// The client for the model in force.
    ///
    /// **An `Arc` rather than a `&'a dyn Provider`, and the change was the one
    /// invasive part of `/model`.** A borrow ties the agent to a provider for
    /// its whole life, which is right up until the user is allowed to change
    /// model without leaving the session. Owning a counted handle keeps the
    /// field honest — the agent has exactly one provider at a time and swapping
    /// it is an explicit event, [`Agent::set_provider`] — where an interior
    /// `RefCell` would have made "which model is running" a question with no
    /// single answer.
    pub provider: Arc<dyn Provider>,
    pub harness: &'a Harness,
    /// The system prompt, before the standing contract is appended.
    ///
    /// Taken here rather than read from `harness.instructions` because a
    /// delegated run has the same harness — the same hooks, the same working
    /// directory, the same skills — and a *different* prompt: the body of its
    /// agent file. One field is the difference between that and a second
    /// `Harness`, which would mean two objects claiming to be this project's
    /// configuration.
    pub instructions: &'a str,
    pub tools: &'a Registry,
    pub approvals: &'a Approvals,
    pub log: &'a SessionLog,
    pub term: &'a Term,
    pub interrupt: Arc<Interrupt>,
    /// The token meter this run charges. See [`Spend`].
    pub spend: Arc<Spend>,
    /// How this run decides a goal is met. One implementation today; the loop
    /// knows only the trait, so swapping in a task-list or check-command
    /// authority is a different value here rather than an edit below.
    pub done: &'a dyn DoneCheck,
    pub cwd: PathBuf,
    pub session_id: String,

// … elided: `background`, the tool-api registry that holds work started by
// this session so it outlives the call that spawned it, with the eight-line
// argument for why it is defaulted rather than required.

    pub budgets: Budgets,
    pub caching: Caching,
    pub mode: Mode,
}

Fifteen fields, and two of them are the seam: provider is an Arc<dyn Provider> and done is a &dyn DoneCheck. term can be Term::silent(). So a test constructs the real Agent, the real Registry, the real Harness and the real approval gate, and swaps exactly one thing: the network.

pub struct Say {
    pub text: String,
    pub calls: Vec<(String, Value)>,
    pub tokens: i64,

Tests built on the fake prove the loop's decisions. They prove nothing about the wire.

Ctrl-C

// crates/emma/src/agent.rs
/// Ctrl-C, shared between the signal handler and everything that can be waiting.
///
/// A flag as well as a notification: the flag is what an iteration boundary
/// tests, and the notification is what cuts a model call that is thirty seconds
/// into a sixty-second answer. `notify_one` rather than `notify_waiters` so a
/// signal that arrives in the gap between two waits still lands — the permit is
/// held until somebody collects it.
#[derive(Default)]
pub struct Interrupt {
    flag: AtomicBool,
    notify: tokio::sync::Notify,
}

impl Interrupt {
    pub fn new() -> Arc<Self> {
        Arc::new(Self::default())
    }

    pub fn trip(&self) {
        self.flag.store(true, Ordering::SeqCst);
        self.notify.notify_one();
    }

    pub fn tripped(&self) -> bool {
        self.flag.load(Ordering::SeqCst)
    }

    /// Clear the flag so the next goal starts un-interrupted.
    ///
    /// **Without this the flag was one-way**, and three help strings were
    /// wrong: `cli.rs` and the session's own opening note both say Ctrl-C
    /// interrupts *a goal*, and it ended the whole session. Worse, a Ctrl-C
    /// pressed at an idle prompt did nothing visible and then made the *next*
    /// goal abort instantly, before any model call, with the session exiting
    /// after it — a keystroke doing its damage to work the user had not typed
    /// yet.
    ///
    /// Called at the top of an interactive turn rather than at the bottom of
    /// one, so a stray press between goals is discarded rather than banked. A
    /// press landing in the microsecond between this and the goal starting is
    /// lost, which is a far smaller wrong than the one it replaces.
    pub fn reset(&self) {
        self.flag.store(false, Ordering::SeqCst);
    }

    /// Clear the flag if this run gets more than one goal, and say whether it
    /// did.
    ///
    /// **The decision, not just the store.** `reset` is unconditional; the rule
    /// is that an *interactive* goal starts un-interrupted and a `-p` run does
    /// not, because `-p` has exactly one goal and a Ctrl-C pressed before it
    /// starts is a person cancelling the thing they just typed. Interactively
    /// the same press is a stray keystroke at an idle prompt, and banking it
    /// would abort the next goal before a single model call.
    ///
    /// That rule lived in `main.rs` as `if !opts.print`, which put a decision
    /// in the binary where no scripted `Provider` can reach it and left the
    /// `-p` half with no test at all -- the unit test below covered `reset`,
    /// which is the store rather than the choice. `CLAUDE.md` asks for
    /// decisions in the library for exactly this reason.
    ///
    /// Returning the answer rather than performing it silently is what makes
    /// both branches observable. See the lesson filed on `Term::clipboard`: a
    /// function that decides something and returns nothing has made the
    /// decision untestable.
    ///
    /// **What this still does not cover** is that `main` calls it. The goal
    /// loop is in `main.rs`, so deleting the call leaves the workspace green;
    /// that gap is `ARCH-003` and the fix is moving the loop, not another test
    /// here.
    pub fn starting_goal(&self, one_shot: bool) -> bool {
        if one_shot {
            return false;
        }
        self.reset();
        true
    }

    pub async fn wait(&self) {
        loop {
            if self.tripped() {
                return;
            }
            self.notify.notified().await;
        }
    }

    /// Wire the real signal. Not done in `new` so a test never installs a
    /// process-wide handler.
    pub fn install(self: &Arc<Self>) {
        let me = self.clone();
        tokio::spawn(async move {
            if tokio::signal::ctrl_c().await.is_ok() {
                me.trip();
            }
        });
    }
}

Two mechanisms because there are two kinds of waiting. tripped() is what the top of an iteration polls. wait() is what call_model's select! races against a streaming response, and it re-checks the flag on every wakeup rather than trusting the notification alone, so a signal that arrived before the wait started is not missed. notify_one holds the permit until somebody collects it, which is the same property from the other side.

crates/emma/src/agent.rs — Interrupt, Agent::call_model

install is separate from new so a test never installs a process-wide handler. It spawns a task that trips the flag once. The flag used to be one-way — an earlier version of this page said "a goal cannot be un-interrupted", and it was describing the code accurately — which meant Ctrl-C ended the session, against three help strings that promised it interrupts a goal. reset is the reversal, and starting_goal is the rule that uses it: an interactive goal starts un-interrupted, a -p run does not. A one-shot run has exactly one goal, so a press before it starts is the person cancelling what they just typed, and discarding it would run the thing they had just asked not to run. Interactively the same press is a stray keystroke at an idle prompt. A second Ctrl-C during a goal is the process's own handling, not this type. tested an_interrupt_can_be_cleared_so_the_next_goal_starts_clean covers the store; a_one_shot_run_keeps_an_interrupt_and_an_interactive_one_discards_it covers the choice. Three mutations of starting_goal each go red on a different assertion, which is what says the test tells the branches apart rather than failing for one reason three times.

That rule was if !opts.print in main.rs until 2026-08-23. It put a decision in the binary, where no scripted provider can reach it, and the -p half was asserted nowhere at all — the unit test named above covers reset, which is the store rather than the choice. Moving the rule next to the flag made both halves testable.

What it did not make testable is that main calls it. The interactive goal loop is still in main.rs, so deleting the call leaves the entire workspace green. unverified Nothing checks the wiring. What would settle it is extracting the goal loop into the library behind a seam a scripted provider can drive, rather than another test on Interrupt, which is the part that is already covered. It is filed as ARCH-003.

Changing model mid-session

// crates/emma/src/agent.rs
/// The provider in force, shared with everything that must not disagree about
/// which model this process is using.
///
/// **This exists because `/model` made "the model" a thing that changes.** The
/// `Agent` owns its provider outright and swaps it explicitly — see
/// [`Agent::set_provider`], and the argument on [`Setup::provider`] for why that
/// is not an interior-mutable cell. But `Delegate` resolves a subagent's client
/// when the delegation runs, long after it was constructed, and a subagent whose
/// file names no model is specified to use *the parent's*. Reading a clone
/// captured at boot would mean a subagent quietly running on the model the user
/// changed away from, with the parent's status row saying otherwise.
///
/// So there is exactly one cell, written in exactly one place — the `/model`
/// command, beside the `set_provider` call — and read by the one caller that
/// resolves late.
#[derive(Clone)]
pub struct Running(Arc<std::sync::Mutex<Arc<dyn Provider>>>);

Running::new, get and set are three lines each and all three use lock().unwrap_or_else(|e| e.into_inner()), so a poisoned mutex yields the value rather than panicking. A thread that panicked while holding this lock leaves a provider handle behind, and refusing to read it would turn one panic into a dead session.

crates/emma/src/agent.rs — Running 
// crates/emma/src/agent.rs
/// Swap the model for the rest of the session, and answer what was running.
///
/// **The conversation is untouched.** Every chapter, every tool result and
/// every summary stays exactly where it is and the whole list is re-sent to
/// the new model on the next goal — which is the behaviour a person asking
/// "is Sonnet enough for this?" wants, and the reason the one hazard below
/// exists.
pub fn set_provider(&mut self, provider: Arc<dyn Provider>) -> String {
    let was = self.s.provider.model_id().to_string();
    self.s.log.append(
        "model_changed",
        json!({ "from": was, "to": provider.model_id() }),
    );
    self.s.provider = provider;
    self.changed_from = Some(was.clone());
    was
}

changed_from is set here and is the only input to the recovery below. It is cleared by the first call that survives, so the recovery is armed for exactly one call after a change.

The loop's one retry

// crates/emma/src/agent.rs
/// The recovery for a model change that the provider would not accept.
///
/// **Whether one model's signed thinking blocks are accepted by another is
/// not established in this tree**, and it is the one thing that can turn
/// `/model` from "works" into a 400 on the very next call. So the failure is
/// handled rather than predicted: a `BadRequest` naming a signature or a
/// thinking block, on the first call after a change, compacts the whole
/// conversation to summaries — which are two plain `Message`s carrying no
/// provider state at all — and the caller retries once.
///
/// … elided: three further doc paragraphs, on which of the guards below are
/// load-bearing and which is a kept redundancy; the prose after this block
/// carries their argument.
fn recover_from_a_model_change(&mut self, e: &LlmError) -> bool {
    let Some(was) = self.changed_from.take() else {
        return false;
    };
    let LlmError::BadRequest { message } = e else {
        return false;
    };
    let lower = message.to_ascii_lowercase();
    if !lower.contains("signature") && !lower.contains("thinking") {
        // **The fragile edge, made loud rather than left silent.** This
        // recovery keys on the provider's prose because no structured code
        // distinguishes "your history carries blocks the new model will not
        // accept" from any other bad request. A wording change upstream
        // therefore disables the recovery without disabling anything that
        // reports it — and the symptom is a session that dies on the first
        // call after `/model` with a message nobody connects to the switch.
        //
        // Reaching here means the two facts that matter are both true: the
        // model changed this turn, and the provider refused the request.
        // That is worth a sentence even when the wording did not match,
        // because it is exactly the case where the recovery was supposed to
        // help.
        self.s.term.warn(&format!(
            "the provider refused the first request after the model changed from {was}, and                  the refusal does not read like the stale-signature case this run knows how to                  recover from: {message}. If this is that case in different words, `/compact`                  clears the blocks the old model bound."
        ));
        return false;
    }
    if !self
        .conversation()
        .iter()
        .any(|m| m.content.blocks().iter().any(ContentBlock::is_model_bound))
    {
        return false;
    }
    let size = self.estimated_context();
    let take = self.chapters.len();
    self.s.term.warn(&format!(
        "the provider rejected this conversation after the model changed from {was}: \
         {message}"
    ));
    match self.compact(take, size, "a model change invalidated signed content") {
        Compacted::Done { messages, .. } => {
            self.s.term.note(&format!(
                "summarised {messages} messages — a summary carries no signed thinking \
                 blocks — and retrying once. Their tool results are no longer in context."
            ));
            true
        }
        Compacted::Nothing(_) => false,
    }
}

Four guards. Only after a change, otherwise an ordinary malformed request costs somebody their tool traffic. Only on a message naming a signature or a thinking block. Both were confirmed by mutation, per the function's own doc: remove either and a test goes red. The third guard, the is_model_bound scan, is documented as redundant and kept: what bounds this to a single attempt is compact answering Compacted::Nothing once the conversation is already summaries, and a conversation with no model-bound block is one compaction has nothing left to take out of. Every mutation of that check is invisible for that reason. tested per the doc's own record of the mutations; not a mutation watched during this write-up, since this task did not change source.

The wording guard used to fail in silence — a bare return false; — and that was the fragile edge left unlit. The recovery keys on the provider's prose because no structured code distinguishes the stale-signature case from any other bad request, so a wording change upstream disables it without disabling anything that reports it, and the symptom is a session dying on the first call after /model with a message nobody connects to the switch. The branch now warns, naming the model change and pointing at /compact as the manual version of what the recovery would have done. tested an_ordinary_bad_request_is_still_reported_rather_than_compacted_away in tests/commands.rs asserts both that nothing is summarised and that the near-miss is said out loud. One honest wart: the warning string in the source is a single long literal with runs of spaces embedded where line continuations were meant to go, so what prints carries those gaps. The quote above reproduces it as it is.

What is not verified here

unverified Whether one model's signed thinking blocks are ever accepted by another. The function's own doc says this is not established in this tree, and nothing on this page settles it. The recovery exists because the answer is unknown rather than because the answer is known to be no. What would settle it: start a session on one model, produce a turn with thinking blocks, run /model, and read what the next call returns.

unverified That the two substring guards match what a real provider says. "signature" and "thinking" are matched case-insensitively against the BadRequest message. Whether a live rejection uses either word is a claim about the provider's error text, and the tests supply that text themselves through rejected(...). What would settle it: the experiment above, with the error message pasted here.
