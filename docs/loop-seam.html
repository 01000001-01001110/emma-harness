The agent loop

Seams

The agent loop One turn Failure The memo Endings The kick Budgets Done Seams

Three things reach into the loop from outside it: a test replacing the network, a signal handler ending a call, and a user changing model mid-session. All three are handled by the same arrangement, which is that Setup holds interfaces rather than concrete types.

What a run is configured with

// crates/emma/src/agent.rs
pub struct Setup<'a> {
    /// The client for the model in force.
    ///
    /// **An `Arc` rather than a `&'a dyn Provider`, and the change was the one
    /// invasive part of `/model`.** A borrow ties the agent to a provider for
    /// its whole life, which is right up until the user is allowed to change
    /// model without leaving the session. Owning a counted handle keeps the
    /// field honest — the agent has exactly one provider at a time and swapping
    /// it is an explicit event, [`Agent::set_provider`] — where an interior
    /// `RefCell` would have made "which model is running" a question with no
    /// single answer.
    pub provider: Arc<dyn Provider>,
    pub harness: &'a Harness,
    /// The system prompt, before the standing contract is appended.
    ///
    /// Taken here rather than read from `harness.instructions` because a
    /// delegated run has the same harness — the same hooks, the same working
    /// directory, the same skills — and a *different* prompt: the body of its
    /// agent file. One field is the difference between that and a second
    /// `Harness`, which would mean two objects claiming to be this project's
    /// configuration.
    pub instructions: &'a str,
    pub tools: &'a Registry,
    pub approvals: &'a Approvals,
    pub log: &'a SessionLog,
    pub term: &'a Term,
    pub interrupt: Arc<Interrupt>,
    /// The token meter this run charges. See [`Spend`].
    pub spend: Arc<Spend>,
    /// How this run decides a goal is met. One implementation today; the loop
    /// knows only the trait, so swapping in a task-list or check-command
    /// authority is a different value here rather than an edit below.
    pub done: &'a dyn DoneCheck,
    pub cwd: PathBuf,
    pub session_id: String,
    pub budgets: Budgets,
    pub caching: Caching,
    pub mode: Mode,
}

Fifteen fields, and two of them are the seam: provider is an Arc<dyn Provider> and done is a &dyn DoneCheck. term can be Term::silent(). So a test constructs the real Agent, the real Registry, the real Harness and the real approval gate, and swaps exactly one thing: the network.

The scripted provider

// crates/emma/tests/support/mod.rs
/// One scripted assistant turn.
pub struct Say {
    pub text: String,
    pub calls: Vec<(String, Value)>,
    pub tokens: i64,
    /// Answer this call with `LlmError::BadRequest` carrying this message,
    /// rather than with a turn.
    ///
    /// The provider rejecting a *request* — as opposed to failing to reach one
    /// — is a case the loop now has a recovery for: a model change can leave
    /// signed thinking blocks in the history that the new model will not take.
    /// A fake that could only succeed could not exercise it.
    pub fail: Option<String>,
}

pub struct Fake {
    script: Mutex<std::collections::VecDeque<Say>>,
    seen: Mutex<Vec<Request>>,
    /// What this client answers `model_id()` with. A session may now change
    /// model mid-conversation, and a test of that needs two clients that are
    /// distinguishable.
    id: String,
}

Four builders produce a Say: text, call, rejected, and the costing(n) modifier which is what the token-budget test uses to price a turn. The default cost is 10 tokens per turn, and a rejected turn costs 0.

seen is the half that matters. Recording every request makes the tests assertions about behaviour rather than about return values: a test can check what the model was told, which is where most of this file's guarantees live. The transcript contains "already_failed", the kick restated the goal, the model was told the denial cannot be approved away: none of those is observable from an Outcome.

Tests built on the fake prove the loop's decisions. They prove nothing about the wire.

Ctrl-C

// crates/emma/src/agent.rs
/// Ctrl-C, shared between the signal handler and everything that can be waiting.
///
/// A flag as well as a notification: the flag is what an iteration boundary
/// tests, and the notification is what cuts a model call that is thirty seconds
/// into a sixty-second answer. `notify_one` rather than `notify_waiters` so a
/// signal that arrives in the gap between two waits still lands — the permit is
/// held until somebody collects it.
pub struct Interrupt {
    flag: AtomicBool,
    notify: tokio::sync::Notify,
}

impl Interrupt {
    pub fn new() -> Arc<Self> { Arc::new(Self::default()) }

    pub fn trip(&self) {
        self.flag.store(true, Ordering::SeqCst);
        self.notify.notify_one();
    }

    pub fn tripped(&self) -> bool { self.flag.load(Ordering::SeqCst) }

    pub async fn wait(&self) {
        loop {
            if self.tripped() {
                return;
            }
            self.notify.notified().await;
        }
    }

    /// Wire the real signal. Not done in `new` so a test never installs a
    /// process-wide handler.
    pub fn install(self: &Arc<Self>) {
        let me = self.clone();
        tokio::spawn(async move {
            if tokio::signal::ctrl_c().await.is_ok() {
                me.trip();
            }
        });
    }
}

Two mechanisms because there are two kinds of waiting. tripped() is what the top of an iteration polls. wait() is what call_model's select! races against a streaming response, and it re-checks the flag on every wakeup rather than trusting the notification alone, so a signal that arrived before the wait started is not missed. notify_one holds the permit until somebody collects it, which is the same property from the other side.

crates/emma/src/agent.rs — Interrupt, Agent::call_model

install is separate from new so a test never installs a process-wide handler. It spawns a task that trips the flag once, and the flag is never reset, so a goal cannot be un-interrupted. A second Ctrl-C is what the process's own handling deals with, not this type.

Changing model mid-session

// crates/emma/src/agent.rs
/// The provider in force, shared with everything that must not disagree about
/// which model this process is using.
///
/// **This exists because `/model` made "the model" a thing that changes.** The
/// `Agent` owns its provider outright and swaps it explicitly — see
/// [`Agent::set_provider`], and the argument on [`Setup::provider`] for why that
/// is not an interior-mutable cell. But `Delegate` resolves a subagent's client
/// when the delegation runs, long after it was constructed, and a subagent whose
/// file names no model is specified to use *the parent's*. Reading a clone
/// captured at boot would mean a subagent quietly running on the model the user
/// changed away from, with the parent's status row saying otherwise.
///
/// So there is exactly one cell, written in exactly one place — the `/model`
/// command, beside the `set_provider` call — and read by the one caller that
/// resolves late.
pub struct Running(Arc<std::sync::Mutex<Arc<dyn Provider>>>);

Running::new, get and set are three lines each and all three use lock().unwrap_or_else(|e| e.into_inner()), so a poisoned mutex yields the value rather than panicking. A thread that panicked while holding this lock leaves a provider handle behind, and refusing to read it would turn one panic into a dead session.

crates/emma/src/agent.rs — Running 
// crates/emma/src/agent.rs
/// Swap the model for the rest of the session, and answer what was running.
///
/// **The conversation is untouched.** Every chapter, every tool result and
/// every summary stays exactly where it is and the whole list is re-sent to
/// the new model on the next goal — which is the behaviour a person asking
/// "is Sonnet enough for this?" wants, and the reason the one hazard below
/// exists.
pub fn set_provider(&mut self, provider: Arc<dyn Provider>) -> String {
    let was = self.s.provider.model_id().to_string();
    self.s.log.append(
        "model_changed",
        json!({ "from": was, "to": provider.model_id() }),
    );
    self.s.provider = provider;
    self.changed_from = Some(was.clone());
    was
}

changed_from is set here and is the only input to the recovery below. It is cleared by the first call that survives, so the recovery is armed for exactly one call after a change.

The loop's one retry

// crates/emma/src/agent.rs
/// **Whether one model's signed thinking blocks are accepted by another is
/// not established in this tree**, and it is the one thing that can turn
/// `/model` from "works" into a 400 on the very next call. So the failure is
/// handled rather than predicted: a `BadRequest` naming a signature or a
/// thinking block, on the first call after a change, compacts the whole
/// conversation to summaries — which are two plain `Message`s carrying no
/// provider state at all — and the caller retries once.
fn recover_from_a_model_change(&mut self, e: &LlmError) -> bool {
    let Some(was) = self.changed_from.take() else {
        return false;
    };
    let LlmError::BadRequest { message } = e else {
        return false;
    };
    let lower = message.to_ascii_lowercase();
    if !lower.contains("signature") && !lower.contains("thinking") {
        return false;
    }
    if !self
        .conversation()
        .iter()
        .any(|m| m.content.blocks().iter().any(ContentBlock::is_model_bound))
    {
        return false;
    }
    let size = self.estimated_context();
    let take = self.chapters.len();
    self.s.term.warn(&format!(
        "the provider rejected this conversation after the model changed from {was}: \
         {message}"
    ));
    match self.compact(take, size, "a model change invalidated signed content") {
        Compacted::Done { messages, .. } => {
            self.s.term.note(&format!(
                "summarised {messages} messages — a summary carries no signed thinking \
                 blocks — and retrying once. Their tool results are no longer in context."
            ));
            true
        }
        Compacted::Nothing(_) => false,
    }
}

Four guards, and the file says which are doing work. Only after a change, otherwise an ordinary malformed request costs somebody their tool traffic. Only on a message naming a signature or a thinking block. Both were confirmed by mutation, per the function's own doc: remove either and a test goes red. The third guard, the is_model_bound scan, is documented as redundant and kept: what actually bounds this to a single attempt is compact answering Compacted::Nothing once the conversation is already summaries, and a conversation with no model-bound block is one compaction has nothing left to take out of. Every mutation of that check is invisible for that reason. tested per the doc's own record of the mutations; not a mutation watched during this write-up, since this task did not change source.

What is not verified here

unverified Whether one model's signed thinking blocks are ever accepted by another. The function's own doc says this is not established in this tree, and nothing on this page settles it. The recovery exists because the answer is unknown rather than because the answer is known to be no. What would settle it: start a session on one model, produce a turn with thinking blocks, run /model, and read what the next call returns.

unverified That the two substring guards match what a real provider says. "signature" and "thinking" are matched case-insensitively against the BadRequest message. Whether a live rejection uses either word is a claim about the provider's error text, and the tests supply that text themselves through rejected(...). What would settle it: the experiment above, with the error message pasted here.
