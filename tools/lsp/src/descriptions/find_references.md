Find every use of a symbol, using the compiler's understanding of the code
rather than text matching.

This is what `Grep` cannot do. Grep finds a name; this finds _that symbol_ — it
knows the `Config` in one file is the same type as the `Config` in another, it
skips the one in a comment, and it skips an unrelated `Config` in a different
module. Use it before changing a signature, deleting a function, or renaming
anything.

Say where the symbol is by naming the file, the 1-based line, and the symbol as
it is written on that line. `Grep` output gives you all three. Emma finds the
column itself; if the name appears more than once on the line it refuses and
asks for `occurrence` rather than guessing.

- Rust files only. For any other language this refuses rather than falling back
  to a text search — a reference list produced by grep is a different answer to
  a different question.
- Results are grouped by file, each with its line number and the source line.
  Capped at 100; the result says so when it cut.
- Uses in dependencies and the standard library are counted but not shown, since
  they are outside the working directory.
- **Read the first two lines of every result.** They name the server and, when
  it was still indexing, say so. An empty result from a server that was still
  indexing is not "there are no references" — it is "the question could not be
  answered yet". The result will tell you which of the two it is. When it says
  the index was incomplete, wait a few seconds and ask again.
- Code generated by `derive` and other macros is not indexed, so uses that exist
  only inside a macro expansion will be missed. If you are changing something a
  derive touches, check that by hand.

The first call in a session waits for the language server to start and index the
project, which can take tens of seconds on a large workspace. Calls after that
are fast.
